# 悟能未命中或无法满足时的 fallback 规则

> 用途：当前悟能索引未找到可确认接口，或命中的悟能接口无法满足字段、筛选、统计口径、返回结构、性能要求时使用。

## 进入 fallback 的前提

只有在以下条件满足时，才进入 fallback：

- 已检索 `domain_indexes/wuneng_api_index.md`；
- 当前索引未找到可确认接口，或接口无法满足当前需求；
- 需求本身没有阻塞性口径歧义；
- 静态模板状态已确认，或当前只是在询问数据源补充路径。

如果存在统计口径、状态口径或输出粒度阻塞歧义，先停在 Gate 0。

## 三种现场状态

fallback 分支互斥，不要让现场三种都填。

### 路径 A：现场已有接口

要求补充：

1. 接口名称；
2. 请求方式；
3. 接口地址；
4. 星桥接口路径地址；
5. 请求参数说明；
6. 完整请求示例；
7. 完整返回示例，最好包含 `{hasError,result,message,tag,totalCount}` 外层；
8. 字段含义说明；
9. 数据口径说明。

拿到样例后，继续生成字段映射和 `function filter(data)`。

### 路径 B：暂无接口，但有表 / SQL / 查询逻辑

要求补充生成当前 SQL 必需的信息，优先包括：

1. 主表；
2. 关联表；
3. 关键字段清单及含义；
4. 表关联关系；
5. 过滤条件；
6. 统计口径；
7. 时间字段；
8. 区域字段；
9. 分组维度；
10. 排序和 TopN 规则；
11. 期望返回格式。

普通 `count / sum / group by / join` 聚合查询默认按 MySQL 兼容 SQL 编写，不把“数据库/schema”作为默认必填项；只有现场明确不是 MySQL，或日期函数、分页、窗口函数、递归查询等语法必须依赖数据库方言时，才补问数据库类型或切换写法。

如果当前已经明确是按区域、组织、时间等维度汇总统计且不返回个人明细、组件模板状态、统计时间范围或去重口径中的任意一部分，就先一次性把这几个独立缺口都列出来，不要拆成多轮；只有剩下确实依赖前一轮答案才能确定的问题，才留到下一轮。

拿到表字段或 SQL 后，继续生成建议 SQL、推荐返回格式、字段映射和 `function filter(data)`。

### 路径 C：接口和表都不明确

要求先确认：

1. 数据来源归属；
2. 业务系统；
3. 数据负责人；
4. 统计口径；
5. 输出粒度；
6. 目标返回格式；
7. 是否需要星桥配置。

此时不要强行要求 `result` 样例，也不要编造 SQL 或接口。
