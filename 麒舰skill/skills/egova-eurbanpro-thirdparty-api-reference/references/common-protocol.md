# 通用协议与请求规范

## 适用信号
- 需要快速确认 HTTP、编码、请求频率、统一请求结构。
- 不确定某接口属于 GET 还是 POST，或公共 Header/body 有什么要求。

## 基线规则
- 接口交互统一采用 `UTF-8`。
- `Content-Type` 使用 `application/json`。
- 请求必须包含用户凭证，具体见 `auth-apis.md`。
- 请求方法按接口说明使用 `GET` 或 `POST`。

## 请求频率建议
- 新工单列表、通知类定时请求可以 5-10 分钟拉一次。
- 其他业务接口尽量避免系统高频定时调用，优先人工触发或明确业务动作触发。

## 运行环境要求
- 接口部署在政务外网，对外提供政务外网地址。
- 需要按源 IP 开通防火墙策略。
- 联调前应检查网络、安全、账号配置是否满足要求。

## 统一请求信封
大多数 action 接口采用统一 body 结构：
- `data`
- `senderCode`
- `action`
- `uid`

## 结论
如果一个请求连协议、编码、凭证、统一信封都不符合，就先修通用层，不要直接进入业务参数诊断。
