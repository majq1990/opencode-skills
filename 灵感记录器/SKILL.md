# 灵感捕手

---

## 钉钉服务依赖

| 服务 | dws 模块 | 用途 |
|------|----------|------|
| AI 听记 | `dws minutes` | 获取听记转写原文、基础信息 |
| AI 表格 | `dws aitable` | 沉淀灵感档案数据 |

---

## 触发方式

- **听记URL**：`分析这个听记里的灵感：https://shanji.dingtalk.com/app/transcribes/xxx`
- **关键词**：`灵感捕手`、`我的灵感`、`想法库`、`查看灵感`
- **周期推送**：每周五自动推送本周灵感汇总

---

## 工作流程（严格按顺序执行）

### Step 1: 确定目标听记

根据用户输入确定要分析的听记：

| 用户输入 | 处理方式 |
|---------|---------|
| 提供听记URL | 直接从URL路径提取 taskUuid（URL最后一段即为taskUuid，如 `https://shanji.dingtalk.com/app/transcribes/abc123` 中 `abc123` 即为taskUuid），**禁止通过接口或浏览器访问URL获取taskUuid** |
| 仅说"查看灵感" | 查询最近30天听记，批量分析灵感 |

```bash
# 查询最近听记列表
dws minutes list mine --max 30 --format json
```

### Step 2: 获取听记完整内容

确定 taskUuid 后，获取听记数据：

```bash
# 获取基础信息（标题、时间）
dws minutes get info --id <taskUuid> --format json

# 获取转写原文
dws minutes get transcription --id <taskUuid> --format json
```

### Step 3: 灵感识别

基于以下信号特征识别灵感片段：

#### 灵感时刻的信号特征

| 信号类型 | 具体表现 | 权重 |
|---------|---------|------|
| **语言信号** | "对了"、"我想到了"、"有个想法"、"突然想到"、"其实可以" | 40% |
| **情绪信号** | 语气兴奋、语速加快、音调上扬 | 30% |
| **内容信号** | 提出问题、提出假设、提出方案、否定现状 | 20% |
| **上下文信号** | 话题转换、沉默后开口、回应他人时突然转折 | 10% |

#### 灵感类型分类

| 类型 | 特征 | 示例 |
|-----|------|------|
| **问题型灵感** | 发现痛点、提出质疑 | "为什么用户总是卡在这一步？" |
| **方案型灵感** | 提出解决思路 | "其实可以加个引导动画" |
| **连接型灵感** | 跨领域联想 | "这个功能像游戏里的成就系统" |
| **愿景型灵感** | 描绘未来图景 | "如果A1能实时翻译就好了" |
| **否定型灵感** | 反向思考 | "我们一直做的这个功能可能没必要" |

#### 灵感成熟度

| 等级 | 特征 | 说明 |
|-----|------|------|
| **闪念** | 一闪而过，未展开 | 刚萌芽，需要记录 |
| **萌芽** | 有初步描述 | 开始成形，可以展开 |
| **雏形** | 有具体方案 | 比较完整，可以验证 |
| **成熟** | 有实施路径 | 可以进入执行阶段 |

### Step 4: 灵感关联

查询历史灵感档案，识别相似或相关灵感：

```bash
# 查询 AI 表格中的历史灵感
dws aitable record list --base-id <BASE_ID> --table-id <灵感档案表ID> --format json
```

### Step 5: 输出灵感卡片

按以下模板输出灵感卡片：

```markdown
## 💡 灵感捕获

**灵感内容**：其实可以加个引导动画，让用户知道下一步该做什么

**类型**：方案型 | **成熟度**：萌芽 | **信号强度**：78分

**上下文**：
> 用户反馈说总是在这一步卡住，不知道点哪里。
> **其实可以加个引导动画，让用户知道下一步该做什么**
> 就像抖音那个新手引导一样。

**来源**：产品周会 | 2026-03-20

**发现**：这个灵感你已经提了 2 次
第一次是在 2026-03-10，最近一次是 2026-03-20

**关联灵感**：
- 用户总是在这一步卡住（问题型）
- 新手引导可以降低学习成本（方案型）

---

🎯 **下一步建议**：
这个想法开始成形，可以尝试写个简单方案，找机会验证一下效果。
```

### Step 6: 自动沉淀数据（必须执行）

> ⚠️ **强制约束**：输出报告后，**必须立即执行本步骤**，将分析结果写入 AI 表格。
> 本步骤是工作流的必要组成部分，**禁止跳过**，无需等待用户确认。
> 如果写入失败，必须重试一次；仍然失败则告知用户失败原因。

```bash
# 自动写入AI表格
dws aitable record create --base-id <BASE_ID> --table-id <灵感档案表ID> \
  --records '[{"cells":{
    "灵感内容": "<内容>",
    "灵感类型": "<类型>",
    "来源听记": "<标题>",
    "产生时间": "<日期>",
    "上下文": "<前后文>",
    "信号强度": <分数>,
    "成熟度": "<等级>",
    "提及次数": <次数>,
    "首次提及": "<日期>",
    "最近提及": "<日期>",
    "关联灵感": "<ID列表>",
    "标签": "<标签>",
    "状态": "<状态>"
  }}]' --format json
```

写入后向用户确认：`✅ 分析数据已自动沉淀到 AI 表格`
