# 悟空组件数据对接最终输出模板

> 适用场景：需求已满足门禁要求，可以生成数据源推荐、字段映射和 `function filter(data)` 脚本。

---

## 【输出原则】

1. 默认只输出四段：
    - 结论
    - 映射
    - 过滤脚本
    - 需要核对的内容

2. 不输出需求摘要、PRD、计划、思考过程。

3. `data` 默认是接口外层响应的 `result` 本体。

4. 只有以下场景才处理完整响应包：
    - 用户明确说明传入完整响应包；
    - 分页组件需要 `totalCount`；
    - 需要判断 `hasError`；
    - 用户提供的静态数据格式就是完整响应包转换后的结构。

5. 命中悟能接口时，必须输出：
    - 接口名称；
    - 请求方式；
    - 接口地址；
    - 星桥接口路径地址；
    - 响应主路径；
    - 响应形态。

6. 如果索引或详细文档未提供具体请求参数，不得猜测参数字段名。

7. 非阻塞默认假设写在“默认假设”中，例如时间范围默认口径、默认行政层级、默认筛选范围、表 / SQL fallback 的普通聚合查询默认按 MySQL 兼容 SQL、`filter(data)` 入参为 `result` 本体。

8. “需要核对的内容”只写落地前需要现场核对的联调事项，例如星桥路径缺失、接口文档与索引冲突、现场返回样例需要核对；没有则写“无”。它不是继续向用户索要阻塞信息的入口，也不要求用户当前必须回复。

9. 如果星桥接口路径地址为空、缺失或待确认，输出：
    - `星桥接口路径地址：待确认`
    - 并在“需要核对的内容”中说明。

10. 如果缺失信息会影响接口入参、返回结构、SQL、映射或脚本正确性，必须回到 Gate 0，使用 `### 请补充` 让用户按编号补齐，并停止输出最终四段式；示例字段名只能用于说明替换位置，不能当作已确认字段写入最终 SQL。

11. 过滤脚本必须是 ES5 兼容写法：
    - 使用 `var`；
    - 使用传统 `function`；
    - 不使用箭头函数；
    - 不使用 `let` / `const`；
    - 不使用可选链。

12. 涉及个人健康信息、身份可识别信息、个人隐私或单个自然人查询风险时，只能输出按区域、组织、时间等维度汇总统计且不返回个人明细的方案；不要使用“脱敏”“匿名化”“匿名统计”等措辞。
