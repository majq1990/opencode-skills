# 公钥、token 与诊断模板

## 默认前置核查
- 若问题属于 404、认证、token、流程/采集、多媒体，则在字段级诊断前先补 2-3 条前置核查结论。
- 只有纯报文/字段问题，才可直接进入字段级诊断。

## 公钥与 token
### 获取公钥
- 路径：`/oauth/extras/openapi/pubkey`
- 用途：获取公钥，用于加密 `client_secret`

### 获取 token
- 路径：`/oauth/extras/openapi/client`
- 用途：使用加密后的凭证换取 token
- 入参重点：`client_id`、加密后的 `client_secret`、固定值 `client_credentials`、`uuid`

### 业务接口带 token 的方式
- Header：`X-EGOVA-Authorization: Bearer <token>`
- Query：`egova_openapi_token=<token>`

## 使用规则
- 只有用户提供接口名/地址和 JSON 时才进入这个模板。
- 若只有 `/openapi/v1/action` 但没有 `action`，先指出“缺少 action，无法准确判定接口”。
- 若现场报“无法流转/未找到处理人”，要把区划字段列为重点排查项。
- 命中 404、认证、流程/采集、多媒体类问题时，不能跳过“默认前置核查”。

## 文档冲突
- `4.12 工单办结`：参数表与样例中的 action 不一致
- `4.22 更新工单对接信息`：参数表与样例中的 action 不一致

结论：命中冲突接口时，不能直接判定“通过”，必须写明“需现场确认”。
