## 2. DDCAT SQL 模板

灵珑 SQL 模板语法要点：`${var}` 渲染值（字符串要加引号）；`#if (v != null && v != '') ... #end` 判空；`#tag where() ... #end` 自动生成 where 并吃掉第一个 and。**四个入参为空时对应条件必须不生效**——每个条件都包 `#if`。

### 2.1 SQL1：统计指标（checkCount / errorCount / errorRate）

一次扫描 + 条件聚合（不要写 3 个子查询各扫一遍表，评分点"避免重复全表扫描"）：

```sql
SELECT
  COUNT(1) AS checkCount,
  IFNULL(SUM(CASE WHEN rec_mark_error_flag = 1 THEN 1 ELSE 0 END), 0) AS errorCount,
  IFNULL(ROUND(
    SUM(CASE WHEN rec_mark_error_flag = 1 THEN 1 ELSE 0 END) * 100.0
      / NULLIF(COUNT(1), 0)
  , 2), 0) AS errorRate
FROM mis_error_rec
#tag where()
  #if (createTimeStart != null && createTimeStart != '')
    and create_time >= '${createTimeStart}'
  #end
  #if (createTimeEnd != null && createTimeEnd != '')
    and create_time <= '${createTimeEnd}'
  #end
  #if (unArchiveFlag != null && unArchiveFlag != '')
    and un_archive_flag = ${unArchiveFlag}
  #end
  #if (districtName != null && districtName != '')
    and district_name = '${districtName}'
  #end
#end
```

要点：`ROUND(...,2)` 保留 2 位小数（1 分项）；`NULLIF` 防除零、`IFNULL` 防空表返回 NULL；`unArchiveFlag` 是数值列不加引号。

### 2.2 SQL2：TOP5 差错大类（errorMainTypeName / typeCount）

`error_main_type_names` 可能逗号分隔多值（如"标图不准确,案卷判断错误"），必须先拆分再统计。做法：**内层先按条件把差错件过滤成小结果集（只扫一次表），再连数字表拆分**：

```sql
SELECT t.errorMainTypeName, COUNT(1) AS typeCount
FROM (
  SELECT TRIM(SUBSTRING_INDEX(SUBSTRING_INDEX(e.error_main_type_names, ',', n.n), ',', -1)) AS errorMainTypeName
  FROM (
    SELECT error_main_type_names
    FROM mis_error_rec
    WHERE rec_mark_error_flag = 1
      AND error_main_type_names IS NOT NULL
      AND error_main_type_names != ''
      #if (createTimeStart != null && createTimeStart != '')
        and create_time >= '${createTimeStart}'
      #end
      #if (createTimeEnd != null && createTimeEnd != '')
        and create_time <= '${createTimeEnd}'
      #end
      #if (unArchiveFlag != null && unArchiveFlag != '')
        and un_archive_flag = ${unArchiveFlag}
      #end
      #if (districtName != null && districtName != '')
        and district_name = '${districtName}'
      #end
  ) e
  JOIN (
    SELECT 1 AS n UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5
    UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9 UNION ALL SELECT 10
  ) n ON n.n <= 1 + LENGTH(e.error_main_type_names) - LENGTH(REPLACE(e.error_main_type_names, ',', ''))
) t
GROUP BY t.errorMainTypeName
ORDER BY typeCount DESC
LIMIT 5
```

要点：差错大类只统计差错件（`rec_mark_error_flag = 1` 为固定条件，放 WHERE 首位，四个动态条件跟在后面）；数字表按逗号数 join，一条含 2 个大类的记录各计 1 次；`ORDER BY typeCount DESC LIMIT 5` 满足"按数量倒序 TOP5"（1 分项）。若测试库确认该字段全是单值，可简化为 `SELECT error_main_type_names AS errorMainTypeName, COUNT(1) AS typeCount ... GROUP BY ... ORDER BY ... LIMIT 5`。

### 2.3 SQL3：案件列表明细（列表页 Hook 用，开分页）

```sql
SELECT
  task_num AS taskNum,
  error_main_type_names,
  create_time,
  district_name,
  suggest
FROM mis_error_rec
#tag where()
  #if (createTimeStart != null && createTimeStart != '')
    and create_time >= '${createTimeStart}'
  #end
  #if (createTimeEnd != null && createTimeEnd != '')
    and create_time <= '${createTimeEnd}'
  #end
  #if (unArchiveFlag != null && unArchiveFlag != '')
    and un_archive_flag = ${unArchiveFlag}
  #end
  #if (districtName != null && districtName != '')
    and district_name = '${districtName}'
  #end
  #if (recMarkErrorFlag != null && recMarkErrorFlag != '')
    and rec_mark_error_flag = ${recMarkErrorFlag}
  #end
#end
ORDER BY create_time DESC
```

注意：多了第 5 个入参 `recMarkErrorFlag`（点差错件数跳转时传 1）；展示字段 taskNum 对应 `task_num`（抽查任务编号），若阅卷环境指认 `rec_task_num`（案件任务号）就换成它；**除 taskNum 外的字段名与列表查询面板字段保持一致，不要乱起别名**，否则面板条件匹配不上。

### 2.4 区域下拉（tc_region，region_type=2）

```sql
SELECT region_name AS label, region_name AS value
FROM tc_region
WHERE region_type = 2
ORDER BY region_id
```

value 用 `region_name` 而不是 region_id——考题明确"区域表的 id 与差错件表的区域 id 并不对应，传参用 districtName"。

## 3. DDCAT 注册步骤（每个模型都走一遍）

1. 应用后台 → 数据模型（ddcat）管理 → 新建数据模型，选择应用数据源。
2. 粘贴 SQL 到 SQL 编辑区。
3. **入参配置**：逐个添加 `createTimeStart`、`createTimeEnd`（字符串）、`unArchiveFlag`（数值/字符串均可，见 8.3）、`districtName`（字符串），全部**非必填**；SQL3 额外加 `recMarkErrorFlag`。参数名必须与 SQL 里 `${}` 变量名完全一致（大小写敏感）。
4. **出参配置**：点"解析/执行"自动生成出参，核对字段名 = checkCount/errorCount/errorRate（SQL1）、errorMainTypeName/typeCount（SQL2）。
5. **分页**：SQL1/SQL2/区域下拉**不开分页**；SQL3 **开启分页**（与列表部件分页开关保持同步，全开或全关）。
6. **测试验证**（对应 2 分"注册及查询正常" + 2 分"空参数逻辑"）：
   - 全空参执行 → 返回全量统计；
   - 只传 districtName → 只区域过滤生效；
   - 传 unArchiveFlag=0 → 已办结件（0 是有效值，不能当空处理）；
   - 全参执行 → 结果与手工 SQL 核对。
7. 记录模型 ID：编辑模型时浏览器开发者工具看请求 `unity/data-model/{id}`，或从编辑页 URL 取，填入登记表。

## 4. 看板页面配置

### 4.1 组件清单

| 区域 | 组件 | 数据来源 | 关键配置 |
|---|---|---|---|
| 标题区 | 自定义容器 + 文本 | — | 容器设背景/高度，文本写"差错案件统计" |
| 筛选区 | 自定义时间选择 | — | 记下 id `{CMP_DATE}` |
| 筛选区 | 下拉单选（区域） | ddcat `{DDCAT_REGION_ID}` | fit 脚本 unshift「全部」(value="")，id `{CMP_DISTRICT}` |
| 筛选区 | 下拉单选（是否办结） | 静态选项 | 全部=""、未办结=1、已办结=0，id `{CMP_ARCHIVE}` |
| 指标区 | 看板指标展示 | JS 赋值（SQL1） | id `{CMP_METRIC}`，绑 onClick 跳转 |
| 图表区 | 横向柱状图 | JS 赋值（SQL2） | id `{CMP_BAR}` |

### 4.2 布局

页面拖入「容器」→ 内套「网格布局（简）」分 4 行：第 1 行标题容器；第 2 行筛选区（弹性横排：时间 + 区域 + 办结）；第 3 行指标区；第 4 行图表区。层级清楚即拿满"布局清晰 2 分"。

### 4.3 区域下拉数据源 fit 脚本（加"全部"选项）

```js
function fit(result) {
  let list = (result && result.length) ? result : [];
  // ddcat 返回的 result 已是数组且含 label/value
  list = list.map(g => ({ label: g.label, value: g.value }));
  list.unshift({ label: "全部", value: "" });
  return list;
}
```

## 5. 页面 JS 脚本完整模板

**位置**：看板页面 → 设置 → 生命周期 → 页面加载完成（didMount）绑定自定义动作。全局函数挂 window，满足"全局函数封装 2 分"。

```js
function main() {
    var self = this;

    // ===== 常量：所有资源 ID 只在此处声明 =====
    var DDCAT_ID = {
        STAT: "{DDCAT_STAT_ID}",   // SQL1 统计模型
        TOP5: "{DDCAT_TOP5_ID}"    // SQL2 TOP5 模型
    };
    var CMP_ID = {
        DATE: "{CMP_DATE}",         // 自定义时间选择
        DISTRICT: "{CMP_DISTRICT}", // 区域下拉单选
        ARCHIVE: "{CMP_ARCHIVE}",   // 是否办结下拉单选
        METRIC: "{CMP_METRIC}",     // 看板指标展示
        BAR: "{CMP_BAR}"            // 横向柱状图
    };
    window.CMP_ID = CMP_ID;

    // ===== 获取筛选参数（空值不放入，满足"筛选项为空时不传该参数"）=====
    function getFilterParams() {
        var params = {};
        var timeCmp = self.$$(CMP_ID.DATE);
        if (timeCmp && timeCmp.currentTime) {
            params.createTimeStart = timeCmp.currentTime.start.format("YYYY-MM-DD 00:00:00");
            params.createTimeEnd = timeCmp.currentTime.end.format("YYYY-MM-DD 23:59:59");
        }
        var districtCmp = self.$$(CMP_ID.DISTRICT);
        var districtName = districtCmp ? districtCmp.$$getValue() : "";
        if (districtName) params.districtName = districtName;
        var archiveCmp = self.$$(CMP_ID.ARCHIVE);
        var unArchiveFlag = archiveCmp ? archiveCmp.$$getValue() : "";
        // 注意 0 是有效值（已办结），不能用 if(unArchiveFlag) 判断
        if (unArchiveFlag !== "" && unArchiveFlag !== null && unArchiveFlag !== undefined) {
            params.unArchiveFlag = unArchiveFlag;
        }
        return params;
    }
    window.GET_FILTER_PARAMS = getFilterParams;

    // 对象 → DATA_SOURCE_EXECUTE 的 queryParams 数组格式
    function toQueryParams(obj) {
        return Object.keys(obj).map(function (k) {
            return { name: k, valueContent: obj[k] };
        });
    }

    // ===== Loading 开关 =====
    function setLoading(id, loading) {
        var cmp = self.$$(id);
        if (cmp && cmp.data.props.loadingConfig) {
            cmp.data.props.loadingConfig.loading = loading;
        }
    }

    // ===== 全局刷新（页面初始化 + 筛选变化统一走这里）=====
    window.refreshData = function () {
        var queryParams = toQueryParams(getFilterParams());
        setLoading(CMP_ID.METRIC, true);
        setLoading(CMP_ID.BAR, true);

        // --- 指标区：SQL1 ---
        api.DATA_SOURCE_EXECUTE(DDCAT_ID.STAT, "ddcat", queryParams, [], "").then(function (res) {
            // ddcat 类型 res.result 已是数组，不需要 JSON.parse
            var row = (res && !res.hasError && res.result && res.result.length) ? res.result[0] : {};
            var metricCmp = self.$$(CMP_ID.METRIC);
            if (metricCmp) {
                metricCmp.data.props.dataSource.options = [
                    { name: "checkCount", text: "抽查数",   value: String(row.checkCount || 0), unit: "件", checked: false },
                    { name: "errorCount", text: "差错件数", value: String(row.errorCount || 0), unit: "件", checked: false },
                    { name: "errorRate",  text: "差错率",   value: String(row.errorRate == null ? 0 : row.errorRate), unit: "%", checked: false }
                ];
            }
            setLoading(CMP_ID.METRIC, false);
        }).catch(function (err) {
            console.error("统计模型查询失败", err);
            setLoading(CMP_ID.METRIC, false);         // 失败也必须关 Loading
            self.$message.error("案件统计数据加载失败");
        });

        // --- 图表区：SQL2 ---
        api.DATA_SOURCE_EXECUTE(DDCAT_ID.TOP5, "ddcat", queryParams, [], "").then(function (res) {
            var list = (res && !res.hasError && res.result) ? res.result : [];
            var barData = list.map(function (item) {
                return {
                    name: item.errorMainTypeName,
                    text: item.errorMainTypeName,
                    value: item.typeCount || 0,
                    unit: "件",
                    checked: false
                };
            });
            var barCmp = self.$$(CMP_ID.BAR);
            if (barCmp) {
                // 占比基数取返回最大值（列表已倒序，取第一条），柱子按比例撑满
                var maxVal = barData.length ? barData[0].value : 0;
                self.$$m(CMP_ID.BAR).props.chartOption.baseDataValue = maxVal || 1;
                barCmp.data.props.dataSource.options = barData; // 空数组也赋值，数据为空不报错
            }
            setLoading(CMP_ID.BAR, false);
        }).catch(function (err) {
            console.error("TOP5 模型查询失败", err);
            setLoading(CMP_ID.BAR, false);
            self.$message.error("差错类型 TOP5 加载失败");
        });
    };

    // ===== 页面首次加载自动查询 =====
    window.refreshData();
}
```

**筛选变化事件绑定**：给「自定义时间选择」「区域下拉」「办结下拉」三个组件各绑 onChange 动作（自定义脚本），内容统一为：

```js
function main(params) {
    if (window.refreshData) {
        window.refreshData();
    }
}
```

> 保存脚本时若报错（window 上挂了自定义方法导致），把代码复制后在小窗重新粘贴、点一下空白处再确认，多试几次（平台已知问题）。

## 6. 指标点击跳转 + 列表页接参自动查询

### 6.1 看板侧：指标展示组件绑定 onClick

点击指标栏目时触发，e 为该栏目信息（含 name/text）：

```js
function main(e) {
    // 差错率不跳转（4 分项里的红线）
    if (!e || (e.text && e.text.indexOf("率") > -1)) return;

    var params = window.GET_FILTER_PARAMS ? window.GET_FILTER_PARAMS() : {};
    // 点差错件数：额外携带 recMarkErrorFlag=1；点抽查数：查全部，不带该参数
    if (e.name === "errorCount") {
        params.recMarkErrorFlag = 1;
    }
    this.$router.push({
        name: "page-preview",
        query: {
            title: "案件列表",
            pageId: "{LIST_PAGE_ID}",
            showHeader: this.$route.query.showHeader,
            isFromAction: 1,
            _t: new Date().getTime() + ""
        },
        params: params
    });
}
```

用 `$router.push` 跳转（不是 window.open），返回时看板页面栈还在，原筛选条件不丢失（交互要求第 11 条）。

### 6.2 列表页侧：Hook 接参 + 自动查询

列表部件基于 SQL3 的空视图/实体搭架子（查询面板拖入 create_time（介于）、district_name、un_archive_flag 等字段），表格列表 → 高级 → Hook 配置开启，脚本：

```js
function main(pageId, param) {
    var self = this;
    var DDCAT_LIST_ID = "{DDCAT_LIST_ID}"; // SQL3 列表明细模型

    // 1. 取看板跳转带来的路由参数；缓存到 window，翻页/刷新时复用
    var routeParams = {};
    if (self.$route && self.$route.params && self.$route.params.createTimeStart !== undefined) {
        routeParams = self.$route.params;
        window.REC_LIST_PARAMS = routeParams;
    } else if (self.$route && self.$route.params && Object.keys(self.$route.params).length) {
        routeParams = self.$route.params;
        window.REC_LIST_PARAMS = routeParams;
    } else {
        routeParams = window.REC_LIST_PARAMS || {};
    }

    // 2. 跳转参数合入模型入参（空值不塞，满足"空参数不生效"）
    param.condition.params = param.condition.params || {};
    ["createTimeStart", "createTimeEnd", "districtName", "unArchiveFlag", "recMarkErrorFlag"]
        .forEach(function (k) {
            var v = routeParams[k];
            if (v !== undefined && v !== null && v !== "") {
                param.condition.params[k] = v;
            }
        });

    // 3. 回填查询面板默认值，让用户看得到当前过滤条件（组件 id 换成实际值）
    try {
        var dateCmp = self.$$("query_field_wrapper_日期组件id");
        if (routeParams.createTimeStart && dateCmp) {
            dateCmp.queryField.props.startTime.defaultValue.value = routeParams.createTimeStart;
            dateCmp.queryField.props.endTime.defaultValue.value = routeParams.createTimeEnd;
        }
        var districtCmp = self.$$("query_field_wrapper_区域组件id");
        if (routeParams.districtName && districtCmp) {
            districtCmp.queryField.props.defaultValue.value = routeParams.districtName;
        }
    } catch (e) { console.warn("查询面板回填跳过", e); }

    // 4. 用 ddcat 数据模型代替默认查询（列表初始化即自动执行，无需再点查询）
    return new Promise(function (resolve, reject) {
        api.DATA_EXECUTOR().executeDataModelForList(DDCAT_LIST_ID, param)
            .then(function (res) { resolve(res); })
            .catch(function () { reject(); });
    });
}
```

配套配置：列表部件「分页」开启且每页条数与模型分页同步；查询面板字段标题批量改中文，但字段名保持与 SQL3 输出列一致；若用户手动改了面板条件，面板条件会进入 `param.condition` 由模型变量同名匹配生效。

> 备选纯配置方案（不写 Hook）：列表用普通数据视图，跳转改用「动作面板打开页面 + 页面列表渲染组件参数映射到查询条件组件标识」，列表初始化自动按默认值查询；此时把传值字段放查询面板第一位，否则传值不成功。考试推荐 Hook 方案，可控性强且与原题演示一致。

## 8. 常见坑（考场救命清单）

1. **`unArchiveFlag=0` 被当成空**：0 是"已办结"有效值，JS 判空必须用 `!== ""` 而不是 truthy；SQL `#if` 里 `!= ''` 对数字 0 不会误判，但 JS 层若把 0 丢了照样查全量。
2. **ddcat 与 api 返回结构不同**：`DATA_SOURCE_EXECUTE(..., "ddcat", ...)` 的 `res.result` 已是数组直接用；`"api"` 类型的 `res.result` 是 JSON 字符串要 `JSON.parse`。别抄混。
3. **Loading 忘关**：成功回调、catch 里都要 `setLoading(id, false)`，评分表单独 2 分；页面白屏大多是失败分支没关。
4. **指标/柱状图数据格式**：options 数组每项必须含 `name/text/value/unit/checked`，value 建议转字符串；格式不对组件直接空白。
5. **保存 window 挂载脚本报错**：平台已知问题，复制代码到小窗重新粘贴、点空白处再确认，多试几次。
6. **差错率除零/空表**：`NULLIF(COUNT(1),0)` + `IFNULL(...,0)`，空数据时指标显示 0 而不是报错（交互要求第 8 条）。
7. **error_main_type_names 多值**：不拆分会把"A,B"当成一个类型统计，TOP5 结果错；拆分后记得 TRIM 去空格。
8. **点击差错率也跳转**：onClick 第一行就 `if (e.text.indexOf("率") > -1) return;`，这是 4 分项的扣分红线。
9. **列表面板字段起别名**：ddcat 代理查询时，查询面板字段名要与模型 SQL 输出列名一致（时间介于条件按 `_start`/`_end` 前缀约定），别名会导致面板条件失效。
10. **分页不同步**：SQL3 模型"是否分页"与列表部件"分页"开关必须全开或全关，否则翻页错乱、导出数据不一致。
11. **Hook 里粗暴改 param**：只往 `param.condition.params` 合并键值，不要重建/删除 param 结构，否则影响导出与查询一致。
12. **时间格式越界**：开始时间补 `00:00:00`、结束时间补 `23:59:59`，结束用 `<=`；开始/结束都空时不传，SQL 不拼条件。
13. **区域传值用 region_id**：tc_region 的 id 与 mis_error_rec.district_id 不对应，下拉 value 必须用 region_name，传参名 districtName。
14. **返回看板筛选丢失**：跳转必须用 `this.$router.push`（保留页面栈）；列表页参数存 `window.REC_LIST_PARAMS`，翻页时兜底。
