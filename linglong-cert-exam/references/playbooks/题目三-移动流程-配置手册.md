## 1. 任务拆解（考试操作顺序）

| 步骤 | 内容 | 产出 | 预计耗时 |
|------|------|------|----------|

## 2. 表单设计步骤（3 分中的 1 分 + 支撑后续全部）

### 2.1 新建流程表单

1. 进入应用 → 页面管理 → 新建页面 → 选择**流程表单**类型（参考《移动流程表单搭建步骤》3.1 新建流程表单）。
2. 表单命名如「违建问题上报表单」。建流程表单会自动带 documentNo（文号）等流程关联字段——**若考试环境存在文号字段，设为自动生成并隐藏**，不作为人工编辑项（原题明确要求）。

### 2.2 字段配置（7 个）

在表单设计器中依次拖入控件：

| 字段名称 | 控件类型 | 必填 | 关键配置 |
|----------|----------|------|----------|
| 案件号 | **流水号** | 否 | 自动生成；格式按**年月日**；设为**只读** |
| 信息来源 | 文本输入 | ✅是 | 打开「必填」开关 |
| 产权单位 | 文本输入 | ✅是 | 打开「必填」开关 |
| 联系人 | 文本输入 | ✅是 | 打开「必填」开关 |
| 使用单位 | 文本输入 | ✅是 | 打开「必填」开关 |
| 违建位置 | 文本输入 | ✅是 | 打开「必填」开关 |
| 创建时间 | 日期时间 | ✅是 | 默认值设为「当前时间」，格式含日期+时间 |

### 2.3 流水号（案件号）配置要点

1. 控件用「流水号」（不要用文本输入手填）。
2. 在流水号控件属性里设置编号规则：**前缀/日期格式选 `yyyyMMdd`（年月日）+ 自增序号**，例如 `20260708-0001` 效果。灵珑流水号规则配置里选择日期变量为「年月日」，序号位数按默认即可。
3. 勾选**只读**（评分点原文：「案件号由系统自动生成且只读展示」）。不勾必填。
4. 保存表单后**先自测新增一条**，确认案件号自动生成且带当天日期。

### 2.4 创建时间配置要点

- 控件「日期时间」，必填打开；
- 属性里「默认值」选**当前时间**（提交时自动填充，减少考试演示时手动操作）；
- 若平台无默认当前时间选项，可用公式默认值 `NOW()`（公式默认值不可用时手动选也不扣分，字段本身必填即可）。

## 3. 流程模板配置（5 分）

参考《PC工作台、地图交互、移动端流程相关配置》3.2 配置流程 /《移动流程表单搭建步骤》3.2。

### 3.1 流程结构

进入流程表单的「配置流程 / 流程设计」，拖出如下节点与连线：

```
开始 ──► 处置 ──► 核查 ──► 核实 ──► 办结 ──► 结束
              ◄──退回──┘   ◄──退回──┘  ◄──退回──┘
（核查退回处置、核实退回核查、办结退回核实）
```

- 必须包含**开始节点 + 结束节点 + 4 个业务节点**（评分点 1：1 分）。
- 节点名称严格写：`处置`、`核查`、`核实`、`办结`（列表要展示「节点名称」，写错直接暴露）。
- 正向连线：处置→核查、核查→核实、核实→办结、办结→结束。
- 退回：优先用节点操作菜单里的**回退**动作实现（回退到上一节点），无需额外画反向线；若考试环境的流程设计器要求显式流向，才补画 核查→处置、核实→核查、办结→核实 的退回连线并命名「退回」。

### 3.2 每个节点必配 4 件事

对处置/核查/核实/办结每个节点，逐一配置（参考文档 3.2 清单）：

1. **节点关联的表单**：全部关联「违建问题上报表单」；
2. **节点可操作人员**（受理人）：
   | 节点 | 受理人账号 |
   |------|-----------|
   | 处置 | XXX处置员01 |
   | 核查 | XXX核查员01 |
   | 核实 | XXX核实员01 |
   | 办结 | XXX管理员01 |
   直接在节点参与者里**指定具体用户**即可（本题不需要动态参与者；动态参与者 DYNAMIC_PARTICIPANT 公式是另一类场景）。
3. **案件认领方式**：按默认/自动认领即可（只有单人受理，不需要抢单）；
4. **操作菜单**：移动端只支持这 5 种菜单——**办结、批转、退件、回退、认领**。逐节点配置：
   | 节点 | 操作菜单 |
   |------|----------|
   | 处置 | 批转（→核查） |
   | 核查 | 批转（→核实）、回退（→处置） |
   | 核实 | 批转（→办结）、回退（→核查） |
   | 办结 | 办结、回退（→核实） |

   ⚠️ 不要给任何节点配「退件」——退件相当于不处理直接进办结栏，会破坏流程闭环。

### 3.3 节点表单字段权限（每节点 1 分的踩分句）

每个节点的表单字段要求：**可见、可编辑，案件号除外**（案件号只读；文号字段隐藏）。

- 在节点表单配置里逐字段设置权限（可见/可编辑），或直接依赖表单设计里案件号控件的「只读」属性；
- 逐节点检查：处置、核查、核实 = 全字段可见可编辑 + 案件号只读；办结节点原题写「表单字段可见」——保持可见即可，可编辑不扣分，但**案件号仍必须只读**；
- 文号（documentNo）如暴露在表单上，设为隐藏。

### 3.4 模板保存后

模板配置后平台会**自动生成移动卡片列表**（《移动流程表单搭建步骤》3.2 原文），列表字段可拖拽调整显示——这是第 5 章 5 个 tab 列表的基础，先保存发布模板再去搭页面。

## 4. 启动流程公式（2 分，单点分值最高，务必做对）

要求：新增表单**提交成功后**自动创建流程实例并进入处置节点。

配置位置（参考《流程表单使用表单事件执行后公式》第 3 节）：

1. 打开新增表单 → 点表单「**高级**」→ 进入「**表单事件**」；
2. 增加**业务关联规则** → 选择「**执行后公式**」（即提交/保存成功后触发）；
3. 写启动流程公式。

### 4.1 公式写法

标准形式（《PC工作台…》3.3.1 原文）：

```
FLOW_START(流程表单id, 文号)
```

本题表单即流程表单本身，最简写法——`流程表单id` 填当前流程表单的页面 id（表单设计器 URL 或页面属性里可复制），文号参数传当前记录的 documentNo/主键：

```
FLOW_START('<流程表单页面id>', 文号)
```

若考试环境表单与业务实体分离、需要按业务主键反查（参考文档中的完整真实示例）：

```
FLOW_START('a77f469a-3151-47c9-bb50-2785c17b50e5',
  ENTITY_SELECT_ONE('t_4beacafcf80b4dee89519ea39f573b31','id',QUERY_EQ('identity_no',身份证号)))
```

- 第 1 参 = **流程表单的页面 id**；
- ENTITY_SELECT_ONE('实体表标识id','逻辑主键列', QUERY_EQ('查询列',表单字段)) = 取业务记录主键赋给 documentNo 完成关联。
- 本题照第一种简式写即可，替换成自己的页面 id。

### 4.2 自测

用处置员01在 PC 或移动端提交一条数据 → 流程监控/待办里应立刻出现一个实例，当前节点=处置，受理人=处置员01。**这条不通，后面 11 分的页面列表全是空的**，所以必须在搭页面前打通。

## 5. 移动端 5 tab 页面配置（11 分，大头）

### 5.1 建页面骨架（1 分）

1. 应用 → 页面管理 → 新建**移动端页面**（命名如「违建问题办理」）；
2. 拖入**标签页（tab）组件**，配置 5 个 tab，标题依次：`处置`、`核查`、`核实`、`办结`、`查阅`（顺序、名称照原题，别加多余 tab）；
3. 每个 tab 内放一个**移动卡片列表**——直接复用流程模板自动生成的移动卡片列表（3.4 节），或拖入卡片列表绑定对应流程数据。

### 5.2 各 tab 数据过滤

流程列表数据本质是「待办/已办/办结」视图（act_ru_task 关联 lcwf_process_record，见《流程表单使用表单事件执行后公式》视图示例），按**当前节点名称**过滤：

| tab | 数据范围 | 过滤条件 |
|-----|----------|----------|
| 处置 | 处置节点待办 | 节点名称(nodeName) = `处置` |
| 核查 | 核查节点待办 | nodeName = `核查` |
| 核实 | 核实节点待办 | nodeName = `核实` |
| 办结 | 办结节点待办 | nodeName = `办结` |
| 查阅 | **已办结**数据 | 流程状态 = 已办结/已结束（办结列表视图，不按节点过滤） |

- 若用平台自动生成的流程卡片列表，直接在列表查询条件里加「节点名称 等于 XXX」；
- 若自建视图，参照参考文档待办视图 SQL，`where nodeName='处置'`，查阅 tab 用办结视图（数据来源换成已办结实例）；
- 各 tab 数据随流转自动进出（数据在哪个节点，就出现在哪个 tab；批转后从原 tab 移出）——这由过滤条件天然保证，不需要额外配置。

### 5.3 列表字段（处置/核查/核实/办结 四个 tab 一致）

卡片上拖拽显示 4 个字段 + 1 个按钮：

| 显示项 | 绑定字段 |
|--------|----------|
| 案件号 | 案件号（流水号字段） |
| 节点名称 | nodeName（流程当前节点） |
| 处理人 | 当前节点处理人（userId/处理人名称字段） |
| 创建时间 | 数据创建时间 |
| 操作按钮 | 按钮文字改为「**办理**」 |

「办理」按钮动作：打开**移动办理页面**（第 6 章），传参 `recordId`（案件ID）+ `taskId`（任务ID）——即待办详情 boxType=1 所需参数。传参配置方式同《移动端列表点击打开详情》：卡片/按钮属性 → 点击动作 → 打开页面 → 配置传参。

### 5.4 查阅 tab（字段不同！）

| 显示项 | 绑定字段 |
|--------|----------|
| 案件号 | 案件号 |
| 创建人 | 数据创建人 |
| 创建时间 | 创建时间 |
| 结束时间 | 流程结束时间 |

- **不放任何办理按钮**（原题明确「查阅 tab 不应提供继续办理按钮」，放了倒扣印象分）；
- 卡片配置「卡片点击动作」→ 打开移动办理页面，传 `recordId` + `instanceId`（流程实例ID），对应**办结详情 boxType=4**——可看基本信息 + 办理经过。

### 5.5 悬浮新增按钮（仅处置 tab 显示）

1. 在**处置 tab 内部**（tab 面板容器里，不是页面全局层）拖入悬浮按钮组件（或列表上方自定义按钮），定位右下角；
2. 点击动作：打开新增表单页面（移动办理页面的新增模式，或直接打开违建问题上报表单的移动表单页）；
3. **关键**：按钮放在处置 tab 的容器内，切到其他 tab 自然不显示——这是「悬浮按钮仅在处置 tab 下展示」最稳妥做法。若组件只能挂页面全局，则需按当前 tab 索引写显隐脚本，尽量避免；
4. 新增提交后返回列表并刷新（照《移动端提交返回列表并页面刷新》）：
   - 表单提交按钮 js：`onSave()` 成功后 `this.$route.query.refresh = "1"; this.$router.back();`
   - 列表页面 js：`didMount` 里监听 `afterEach`，`from.query.refresh === "1"` 时取卡片容器（`<卡片容器唯一标识>_csshandler_generate`，F12 查）调 `onRefresh()`；
   - 时间紧可跳过自动刷新，手动下拉刷新列表也能演示，不占评分点。

## 6. 移动办理页面（1 分）

参考《移动流程表单搭建步骤》3.3 / 《PC工作台…》3.4-3.5。

### 6.1 创建

1. 移动应用下 → 新建「**移动办理页面**」（平台专用页面类型）；
2. 在该页面下创建「**移动栏目箱子**」，按需勾选要添加的箱子（表单区/办理经过等）。

### 6.2 箱子按钮参数（boxType 对照表，背下来）

| 场景 | boxType | 必传参数 |
|------|---------|----------|
| 认领 | 0 | recordId（案件ID）+ taskId（任务ID） |
| **待办详情（各节点办理）** | **1** | recordId + taskId |
| 已办详情 | 2 | recordId + taskId |
| 经办详情 | 3 | recordId + instanceId（流程实例ID） |
| **办结详情（查阅）** | **4** | recordId + instanceId |
| 查询详情 | 5 | recordId |

本题核心用两个：**办理入口 boxType=1**（4 个待办 tab 的「办理」按钮跳转），**查阅入口 boxType=4**（查阅 tab 卡片点击跳转）。

### 6.3 入口关联清单

| 入口 | 来源 | 目标 | 传参 |
|------|------|------|------|
| 新增 | 处置 tab 悬浮按钮 | 新增表单（移动办理页面承载） | 无/新增模式 |
| 办理 | 处置/核查/核实/办结 tab「办理」按钮 | 移动办理页面 boxType=1 | recordId + taskId |
| 查阅 | 查阅 tab 卡片点击 | 移动办理页面 boxType=4 | recordId + instanceId |

办理页面打开后：显示节点办理表单（字段可编辑，案件号只读）+ 底部按钮随当前节点自动显示批转/回退/办结（来自 3.2 步配置的节点操作菜单）+ 可查看**办理经过**（先保存再批转时可见流转记录，见《移动流程表单搭建步骤》效果节）。

移动端最终检查：布局正常、字段清晰、按钮可点击（原题验收句，用手机预览或移动模拟模式过一遍）。

## 7. 12 步验证路径（照做打勾）

办理时的标准动作序列：**填写/修改表单 → 先保存 → 再点批转/回退/办结 → 选流向**（《移动流程表单搭建步骤》：先保存，再批转）。

- [ ] 1. **处置员01** 登录移动端；
- [ ] 2. 进入处置 tab，点右下角**悬浮新增按钮**；
- [ ] 3. 填写信息来源、产权单位、联系人、使用单位、违建位置（创建时间自动/选择）→ 提交；
- [ ] 4. 数据自动启动流程，出现在**处置 tab**，案件号已按年月日自动生成；
- [ ] 5. 处置员01 点「办理」→ 保存 → **批转至核查**；数据从处置 tab 消失；
- [ ] 6. **核查员01** 登录，数据出现在**核查 tab**；
- [ ] 7. 核查员01 办理：先演示**退回处置**（数据回到处置 tab，处置员01 可再次编辑并批转回来——这是页面列表 2 分里的踩分句），再**批转至核实**；
- [ ] 8. **核实员01** 登录，数据出现在**核实 tab**；
- [ ] 9. 核实员01 办理：可验证**退回核查**，然后**批转至办结**；
- [ ] 10. **管理员01** 登录，数据出现在**办结 tab**；
- [ ] 11. 管理员01 办理：可验证**退回核实**，然后点**办结**；
- [ ] 12. **巡查员01** 登录，办结数据出现在**查阅 tab**，点开可看**基本信息 + 办理经过**，且无办理按钮。

建议每步截图留证；验证中途退回后记得再批转回来，保证最后能走到办结。

## 8. 评分点对照 checklist（总 20 分）

### 流程模板配置（5 分）
- [ ] 1分：开始 + 结束 + 处置/核查/核实/办结四业务节点齐全；
- [ ] 1分：处置节点——处置员01 新增+受理+批转；表单字段可见可编辑，案件号除外；
- [ ] 1分：核查节点——核查员01 受理；可退回处置或批转核实；字段可见可编辑，案件号除外；
- [ ] 1分：核实节点——核实员01 受理；可退回核查或批转办结；字段可见可编辑，案件号除外；
- [ ] 1分：办结节点——管理员01 受理；可退回核实或办结；字段可见，案件号除外。

### 表单设计（3 分）

## 9. 常见坑

1. **公式没配 = 直接丢 2 分且全流程瘫痪**：FLOW_START 必须配在「表单事件→业务关联规则→执行后公式」，且第 1 参是**流程表单页面 id**（不是应用 id、不是实体表 id）。搭页面前先自测提交能进处置节点。
2. **退回后再次批转**：核查退回处置后，处置员01 必须还能编辑并再次批转（评分点原文）。若退回后处置 tab 看不到数据，检查处置 tab 过滤条件是否只认「新增来源」——正确做法是按 `nodeName=处置` 过滤，与来源无关。
3. **案件号权限**：案件号是「只读展示」不是「隐藏」；文号（documentNo）才是隐藏。两者搞反扣分。案件号别勾必填（流水号提交时才生成，勾必填可能卡提交）。
4. **悬浮按钮位置**：必须放在处置 tab 容器内部；放页面全局层会 5 个 tab 都显示，直接违反「仅处置 tab 展示」评分句。
5. **tab 过滤条件写错**：节点名称过滤值必须与流程模板里节点名一字不差（`处置` ≠ `处置节点`）。查阅 tab 是按**办结状态**过滤，不是 `nodeName=查阅`（流程里没有查阅节点）。
6. **操作菜单选错**：移动端只支持 办结/批转/退件/回退/认领 五种；「退回上一节点」用**回退**，别用**退件**（退件=不处理直接进办结栏）。办结节点才配「办结」。
7. **先保存再批转**：办理时直接点批转可能丢表单修改，标准动作是先保存再批转（参考文档明确的操作顺序），演示时也照这个顺序。
8. **受理人绑错账号**：节点参与者要指定到具体用户（XXX带自己姓名的 01 账号），别选到部门/岗位下的其他人；每个节点配完顺手核对一遍。
9. **办理/查阅传参**：办理入口 boxType=1 传 recordId+taskId；查阅入口 boxType=4 传 recordId+**instanceId**。查阅传成 taskId 会打不开（办结后任务已不存在）。
10. **列表不刷新误判失败**：批转后列表没变先手动下拉刷新再判断，不要急着改配置；自动刷新脚本（refresh=1 + onRefresh）属加分体验，非评分点。
11. **建错表单类型**：必须是**流程表单**，普通表单无法配流程模板；发现建错尽早重建，字段配置照第 2 章十分钟能重敲。
12. **验证顺序**：退回演示完必须批转回来继续往下走，最终要有一条数据真正办结进查阅 tab，否则查阅 tab 的 2 分没有数据支撑。
