## 1. 任务拆解（考试建议操作顺序）

| 步骤 | 做什么 | 对应分值 |

| 2 | 建 **案由列表视图**（关联法规、翻译状态/类型、带 regId/issuerId 参数） | 列表 2 分 |
| 3 | 页面左右分栏：左树部件绑视图，on-click 联动右列表传参 | 树第 3 小点 1 分 |
| 4 | 新增案由表单：文号规则 + 各字段公式默认值 + 禁用；新增按钮前置校验 | 表单 4 分 |
| 5 | 提交后关闭表单 + 刷新列表 | 1 分 |

| 8 | 打印模板 + 打印 API + 顶部"预览"按钮（含未选中校验） | 打印 3 分 |

先跑通 1→3 的树列表联动主链路，再做表单，最后做审核和打印（打印依赖模板设计，耗时最长，留足 30 分钟）。

### 0. 前置准备
1. **数据管理 → 业务实体**：把业务库的 `law_reg_issuer` / `law_reg_regulation` / `law_reg_cause` / `law_reg_audit_log` 注册为实体，**抄下每张表的实体 id**（形如 `t_xxxx` 或 `ds_tbl_t_xxxx`，浏览器 URL 里能看到）。
2. **数据源**：sys_human / sys_unit / sys_region 走**用户中心数据源**，law 系列表走**业务库数据源**。⚠️ 两个数据源的表**不能在同一个视图里 JOIN**，跨库取登录人信息必须走公式/会话变量。
3. **自定义会话变量**（应用设计 → 基础配置 → 会话变量），后面表单和视图都要用：

| 变量 | 建法 | 表达式/数据模型 |
|---|---|---|
| `登录人区域编码` | 数据模型（用户中心数据源）+ DDCAT_CALL | 模型 SQL：`SELECT code FROM sys_region WHERE id = ${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("REGION_ID()")}`；会话变量公式：`DDCAT_CALL('<数据模型id>','','','result.code')` |
| `登录人uid` | 数据模型 + DDCAT_CALL | 模型 SQL：`SELECT uid FROM sys_human WHERE id = '${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("USER_ID()")}'`；公式：`DDCAT_CALL('<数据模型id>','','','result.uid')` |
| `登录人姓名` | 同上取 `name` 字段 | `DDCAT_CALL('<数据模型id>','','','result.name')` |
| `权限区域编码集` | 公式型 | `REGION_CHILD_LIST(REGION_ID(), null, true, 'code')`（登录人区域及全部下级的 code 列表） |

> 内置会话变量可直接用：`USER_ID()`（用户 id）、`USER_USERNAME()`/`USERNAME()`（账号）、`REGION_ID()`（区域 id）、`NOW()`（当前时间）、`DEPARTMENT_ID()`（部门）。
> ⚠️ 题目要求创建人标识存 **sys_human.uid（int）**，`USER_ID()` 返回的是 varchar 主键 id，两者不是一回事——所以上面要建 `登录人uid` 会话变量。

## 2. 联合树视图 SQL（机构 + 法规 UNION，区域权限过滤）

**数据管理 → 数据视图（SQL）**，数据源选**业务库**，命名如 `v_issuer_reg_tree`：

```sql
SELECT node_id AS id, senior_id, node_name AS name, node_type, real_id, regulation_code
FROM (
    /* 节点类型1：颁发机构（自关联树） */
    SELECT
        CONCAT('ORG_', i.id)                        AS node_id,
        CASE WHEN i.senior_id = '0' OR i.senior_id IS NULL
             THEN '0' ELSE CONCAT('ORG_', i.senior_id) END AS senior_id,
        i.name                                      AS node_name,
        1                                           AS node_type,
        CONCAT('', i.id)                            AS real_id,
        ''                                          AS regulation_code
    FROM law_reg_issuer i
    WHERE i.delete_flag = 0
      AND ( i.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
            OR i.region_code = '<中央区域code>' )
    UNION ALL
    /* 节点类型2：法规，挂在其颁发机构节点下 */
    SELECT
        CONCAT('REG_', r.id)                        AS node_id,
        CONCAT('ORG_', r.reg_issuer_id)             AS senior_id,
        r.name                                      AS node_name,
        2                                           AS node_type,
        CONCAT('', r.id)                            AS real_id,
        r.code                                      AS regulation_code
    FROM law_reg_regulation r
    WHERE r.delete_flag = 0
      AND ( r.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
            OR r.region_code = '<中央区域code>' )
) t
ORDER BY node_type, id
```

要点：
- **两类节点用前缀区分**（`ORG_` / `REG_`）避免 id 撞车，`node_type` 字段供 JS 判断节点类型，`real_id` 存真实主键，`regulation_code` 供表单带入法规编码。
- **区域权限**：`权限区域编码集` 会话变量 = `REGION_CHILD_LIST(REGION_ID(), null, true, 'code')`，即"登录人区域及所有下级区域"的 code 列表，IN 匹配 law 表冗余的 `region_code`；**中央全员可见**用 `OR region_code = '<中央区域code>'` 兜底。先去用户中心 sys_region 里查 `name='中央'`（或顶级节点）的实际 code 填进去（拿不准就配成静态变量再引用）。
- 不想走会话变量，也可在视图里直接内联公式（文档验证过的写法）：
  ```sql
  AND i.region_code IN ('${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("IF_FORMULA(ISEMPTY(REGION_ID()),\"\",\"REGION_CHILD_LIST(REGION_ID(),null,true,code)\")")}')
  ```
- **备选思路（senior_code 前缀匹配）**：sys_region.senior_code 存上级编码路径。若环境里 REGION_CHILD_LIST 不可用，可先用会话变量取 `登录人区域编码`，再 `AND (region_code = '${登录人code}' OR region_code IN (SELECT code FROM <同库冗余的区域表> WHERE senior_code LIKE CONCAT('%','${登录人code}','%')))`——但 sys_region 在用户中心库，业务库视图 JOIN 不到，**优先用 REGION_CHILD_LIST 方案**。

## 3. 树部件配置 + 点选联动右侧列表

1. 页面用**网格/flex 左右分栏**：左列放**树部件**，右列放**列表部件**。
2. 树部件数据面板绑 `v_issuer_reg_tree`：节点标识=id，上级标识=senior_id，节点名称=name（顶级 senior_id='0'）。
3. 树属性面板 → 组件动作 **on-click** 绑定 JS（核心：法规节点传 regId，机构节点传 issuerId，并把当前节点存到页面级变量供"新增/预览"按钮校验）：

```javascript
function main(params) {
    const self = this;
    // 把选中节点存到页面根，供新增/预览按钮前置校验用
    const root = self.$$roots()[0];
    root.currentTreeNode = params;   // 含 node_type / real_id / regulation_code / name

    const pageTableList = root.$$element("page_widget_list_<右侧列表标识>");
    if (!pageTableList || !pageTableList.dataEngine) return;
    const tableComp = pageTableList.dataEngine.state.getElement("table_<表格组件标识>");
    if (!tableComp) return;

    if (params.node_type == 2) {          // 法规节点 → 该法规下案由
        tableComp.params.regId = params.real_id;
        tableComp.params.issuerId = null;
    } else {                              // 机构节点 → 该机构下所有法规的案由
        tableComp.params.regId = null;
        tableComp.params.issuerId = params.real_id;
    }
    tableComp.$$refreshData();
}
```

> 部件标识在设计器里选中部件后右侧属性面板可见；`params` 里字段名与视图列名一致。若 `params.node_type` 取出来是对象，用 `params.node_type.value`（先 console.log(params) 确认结构）。

## 4. 案由列表视图 SQL + 列表配置

视图 `v_cause_list`（业务库），**带 regId / issuerId 可选参数**（SQL 模板 #if 语法），未传参时默认全量：

```sql
SELECT
    c.id, c.uid, c.code, c.name AS cause_name,
    r.name AS regulation_name,
    c.cause_type,
    CASE c.cause_type WHEN 1 THEN '罚则' WHEN 2 THEN '违则' END AS cause_type_name,
    c.status,
    CASE c.status WHEN 0 THEN '待审核' WHEN 1 THEN '已生效' WHEN 2 THEN '已驳回' END AS status_name,
    @DATE_FORMAT(c.create_time,'%Y-%m-%d %H:%i') AS create_time_fmt,
    c.create_human_name,
    c.regulation_id, c.regulation_code, c.region_id, c.region_code, c.description
FROM law_reg_cause c
LEFT JOIN law_reg_regulation r ON c.regulation_id = r.id AND r.delete_flag = 0
WHERE c.delete_flag = 0
  AND ( c.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
        OR c.region_code = '<中央区域code>' )
#if(regId != null && regId != '')
  AND c.regulation_id = '${regId}'
#end
#if(issuerId != null && issuerId != '')
  AND r.reg_issuer_id = ${issuerId}
#end
ORDER BY c.create_time DESC
```

要点：
- **翻译显示**在视图里用 CASE 做（cause_type_name / status_name），列表直接展示文本列，同时保留原始 status 数字列（隐藏）供按钮显隐判断。
- 时间格式化用国产化自定义函数 `@DATE_FORMAT(...,'%Y-%m-%d %H:%i')`（注意 **%i 是分钟**，不是 %m）；不确定环境就在列表列上配"日期格式 yyyy-MM-dd HH:mm"也行。
- **约束1（列表也要权限隔离）**：WHERE 里同样加了 region_code 权限过滤。

列表部件配置：
- 数据面板绑 `v_cause_list`；展示列：案由编码/案由名称/法规名称/案由类型(cause_type_name)/案由状态(status_name)/创建时间/创建人名称。
- **状态筛选**：查询区加一个下拉查询字段绑 `status`，选项 0-待审核 / 1-已生效 / 2-已驳回。
- **顶部操作**：新增案由、预览（自定义脚本按钮，见 §5、§9）。
- **操作列**：编辑 | 审核 | 审核记录。**审核按钮配显隐条件**：条件绑 `status 等于 0`（或显隐表达式脚本 `return params.status.value === 0;`）——仅待审核显示。

## 5. 新增案由表单（4分）

新建**表单页面**绑实体 `law_reg_cause`，以弹窗方式打开。

### 5.1 前置校验（新增按钮，1分）

列表顶部"新增案由"按钮 → 绑定动作 → 自定义脚本：

```javascript
function main() {
    const self = this;
    const root = self.$$roots()[0];
    const node = root.currentTreeNode;   // 树 on-click 里存的
    if (!node || node.node_type != 2) {
        self.$message.warning("仅法规可新增案由！");
        return;                          // 不打开表单
    }
    // 打开新增表单弹窗，带入法规信息（页面参数）
    api.OPEN_DIALOG(self, {
        pageId: "<新增案由表单页面id>",
        title: "新增案由",
        params: {
            regulationId: node.real_id,
            regulationCode: node.regulation_code
        },
        onClose: function () {           // 弹窗关闭后刷新列表（双保险）
            const list = root.$$element("page_widget_list_<右侧列表标识>");
            const table = list.dataEngine.state.getElement("table_<表格组件标识>");
            table.$$refreshData();
        }
    });
}
```

> 若环境无 `api.OPEN_DIALOG`，用动作编排"打开弹窗页面"动作 + 参数映射（regulationId/regulationCode），前面加"执行脚本"节点做校验（脚本 return false 中断动作链）。弹窗打开方式以你平台版本可用的为准，**校验提示文案必须一字不差：`仅法规可新增案由！`**

### 5.2 表单字段与公式（2+1分）

| 字段 | 组件 | 配置 |
|---|---|---|
| 案由编码 code | 文号/编码组件 | **文号规则配置**：新增规则 = 日期段 `yyyyMMdd` + 4位流水号（按日重置，不足左补0），示例 202606060001。组件绑该规则，**禁用**。若组件不支持，默认值公式：`GENERATE_SEQUENCE('<文号规则Id>','law_reg_cause',0,null,'<applicationId>')` |
| 案由名称 name | 单行文本 | **必填**，用户录入 |
| 案由类型 cause_type | 下拉单选 | **必填**，选项：1-罚则 / 2-违则（存值 1/2） |
| 案由描述 description | 多行文本 | 选填 |
| 所属法规编码 regulation_code | 单行文本 | 默认值=页面参数 `regulationCode`（表单参数绑定/URL传值），**禁用** |
| 所属法规id regulation_id | 单行文本 | 默认值=页面参数 `regulationId`，**禁用** |
| 所属区域标识 region_id | 数字 | 默认值公式：`REGION_ID()`，**禁用** |
| 所属区域编码 region_code | 单行文本 | 默认值=会话变量 `登录人区域编码`（公式 `DDCAT_CALL('<模型id>','','','result.code')`），**禁用** |
| 创建人标识 create_human_id | 数字 | 默认值=会话变量 `登录人uid`（⚠️ 不是 USER_ID()），**禁用** |
| 创建人姓名 create_human_name | 单行文本 | 默认值公式：`USERNAME()`（题目写 user_name；若判卷要求真实姓名用会话变量 `登录人姓名`），**禁用** |
| 法规状态 status | 数字/下拉 | 默认值 `0`（待审核），**禁用** |
| 删除标识 delete_flag | 数字 | 默认值 `0`，**禁用**（可隐藏） |
| 唯一标识 uid | 单行文本 | 默认值公式：`UUID()`，**禁用** |
| 创建时间 create_time | 日期时间 | 默认值公式：`NOW()`，**隐藏** |

配置路径：组件属性 → 默认值 → **公式编辑**；"禁用"在组件属性勾选；"隐藏"在组件显隐里设。**评分点原文点名 UUID()、当前时间公式、默认0、区域/创建人取自登录人——公式名要用对**。

## 6. 案由审核（3分）

### 6.1 审核入口

```javascript
            const list = root.$$element("page_widget_list_<右侧列表标识>");
            list.dataEngine.state.getElement("table_<表格组件标识>").$$refreshData();
        }

```

### 6.2 审核弹窗页面
简单页面：单选组件 `radio_result`（通过=1 / 驳回=2，必填）+ 多行文本 `textarea_opinion`（审核意见）+「确认」按钮。确认按钮脚本 = **UPDATE 案由状态 + INSERT 审核日志**（EXEC_FORMULA 两连，公式字段可用列名）：

```javascript
function main() {
    const self = this;
    const causeId = self.$route.query.causeId || self.params.causeId;      // 弹窗参数
    const beforeStatus = Number(self.params.beforeStatus || 0);
    const result = self.$$("radio_result").$$getValue();                    // 1通过 / 2驳回
    const opinion = self.$$("textarea_opinion").$$getValue() || '';
    if (!result) { self.$message.warning("请选择审核结果"); return; }
    const afterStatus = (result == 1) ? 1 : 2;   // 通过→1已生效；驳回→2已驳回

    const CAUSE_TBL = "<law_reg_cause实体id>";      // 如 t_xxxx
    const LOG_TBL   = "<law_reg_audit_log实体id>";

    // ① 更新案由状态
    const updateSql = "UPDATE('" + CAUSE_TBL + "',"
        + "['status'," + afterStatus + ",'update_time',NOW()],"
        + "QUERY_EQ('id','" + causeId + "'))";
    // ② 写审核日志（审核人/时间/意见/前后状态；只增不删）
    const insertSql = "INSERT('" + LOG_TBL + "',["
        + "'cause_id','" + causeId + "',"
        + "'audit_human_id'," + "DDCAT_CALL('<登录人uid数据模型id>','','','result.uid')" + ","
        + "'audit_human_name',DDCAT_CALL('<登录人姓名数据模型id>','','','result.name'),"
        + "'audit_username',USERNAME(),"
        + "'audit_result'," + result + ","
        + "'audit_opinion','" + opinion.replace(/'/g, "\\'") + "',"
        + "'audit_time',NOW(),"
        + "'before_status'," + beforeStatus + ","
        + "'after_status'," + afterStatus + "])";

    api.EXEC_FORMULA(updateSql).then(res1 => {
        if (res1.hasError) { self.$message.error("状态更新失败"); return; }
        return api.EXEC_FORMULA(insertSql).then(res2 => {
            if (res2.hasError) { self.$message.error("审核日志写入失败"); return; }
            self.$message.success(result == 1 ? "审核通过" : "已驳回");
            self.$$closeDialog && self.$$closeDialog();
        });
    }).catch(err => self.$message.error(err.message));
}
```

要点/备选：
- `INSERT(表id,[列1,值1,列2,值2...])` 是文档标准公式；字段既可用列名也可用字段 id。**before_status/after_status/审核人/时间/意见是评分点第3小点，一项都不能少**。
- 若环境不支持 `UPDATE(...)` 公式，备选：审核弹窗直接做成 **law_reg_cause 编辑表单**（只放审核结果/意见两个可见组件，status 用业务规则联动：`IF(EQ(审核结果,1),1,2)`），表单保存即更新状态；写日志放到表单"提交后执行公式/后置动作"里跑上面的 insertSql。
- 若 DDCAT_CALL 嵌在 INSERT 里不解析，就在脚本外层先 `api.EXEC_FORMULA("DDCAT_CALL(...)")` 取出 uid/姓名再拼字符串。

## 7. 审核记录弹窗（2分）

1. 视图 `v_audit_log`（业务库，带 causeId 参数）：

```sql
SELECT
    l.id,
    CASE l.audit_result WHEN 1 THEN '通过' WHEN 2 THEN '驳回' END AS audit_result_name,
    l.audit_opinion,
    l.audit_human_name,
    @DATE_FORMAT(l.audit_time,'%Y-%m-%d %H:%i') AS audit_time_fmt,
    l.audit_time, l.cause_id
FROM law_reg_audit_log l
WHERE 1=1
#if(causeId != null && causeId != '')
  AND l.cause_id = '${causeId}'
#end
ORDER BY l.audit_time DESC
```

## 8. 打印预览（3分）

### 8.1 准备打印数据视图
打印模板的数据来源**必须是视图**（主表+一对多子表）。建 `v_print_regulation`（业务库，主表=法规）：

```sql
SELECT r.id, r.code AS regulation_code, r.name AS regulation_name,
       i.name AS issuer_name, r.region_code, r.description,
       @DATE_FORMAT(r.create_time,'%Y-%m-%d %H:%i') AS create_time_fmt,
       r.create_human_name
FROM law_reg_regulation r
LEFT JOIN law_reg_issuer i ON r.reg_issuer_id = i.id
WHERE r.delete_flag = 0
```

给该视图加**导航属性/关联视图**「案由明细」：关联 `v_cause_list`（或案由子视图），关系 `本表.id = 子表.regulation_id`，**关联类型必须选"一对多"**（否则打印只出第一条案由）。子视图里已把类型/状态翻译成文本，打印直接用文本列。

### 8.2 设计打印模板
应用设置 → 打印设计 → 新增模板：数据集选 `v_print_regulation`，**模板类型选 word 或 excel**（office 预览只支持这两种）。版式：上方放法规信息字段占位符（法规编码/名称/颁发机构/创建人/时间），下方插入**表格区**，行内放子表「案由明细」的字段（案由编码/名称/类型/状态/创建人/时间）——子表字段从右侧子表字段列表里点选。**子表表格放模板最后一行**（下方再有合并单元格会导致无法按数量扩行）。保存后**从浏览器 URL 抄下模板 id**。

### 8.3 定义打印 API
数据管理 → API 管理 → 新建（POST）：
- 地址：`/unity/establish/printing_template/binding-data/document-url?printingTemplateId=<模板id>`（有的版本是 `/linglong-api/unity/printingTemplate/binding-data/document-url`，以环境为准；Query 还可带 `fileName`）
- **Headers 加一条：`use-web-Authorization: true`**（透传 token，漏了必 401）
- Body：json 格式，传 SQL 过滤条件，如 `{"id":"1828675689310978048"}`（过滤主视图的法规 id）
- 返回值即渲染后文件的下载地址：单条 → `.../unity/establish/file/{文件id}/download?...`；多条 → `.../file/download-zip?id=...`

### 8.4 顶部"预览"按钮脚本（含未选中校验，1分）

```javascript
function main() {
    const self = this;
    const root = self.$$roots()[0];
    const node = root.currentTreeNode;
    if (!node || node.node_type != 2) {                    // 未选中法规节点
        self.$message.warning("请选择要打印的法规数据！");   // 文案一字不差
        return;
    }
    const hideMessage = self.$message.loading('打印预览中...', 0);
    const jsonParams = JSON.stringify({ id: node.real_id });   // 过滤打印视图：该法规

    api.DATA_SOURCE_EXECUTE("<打印API的ds_api_id>", 'api', [], [], jsonParams, new FormData()).then(res => {
        if (!res.hasError && res.result) {
            const result = JSON.parse(res.result);
            if (!result.hasError) {
                const fileurl = result.result;
                const startIndex = fileurl.lastIndexOf('/file/') + 6;
                const endIndex = fileurl.indexOf('/download');
                const fileId = fileurl.substring(startIndex, endIndex);
                // office 预览页（word/excel 模板）；旧版路径 /linglong/static/vue2/pc/third.html#/template/preview/{fileId}
                const base = window.location.href.substring(0, window.location.href.indexOf('/linglong'));
                const previewUrl = base + "/linglong/design.html#/template/preview/" + fileId;
                window.open(previewUrl, '_blank');
                self.$message.success('打印预览成功！');
            } else { self.$message.error('打印预览失败！'); }
        } else { self.$message.error('打印预览失败！'); }
    }).catch(err => { console.error(err); self.$message.error('打印预览失败！'); })
      .finally(() => hideMessage());
```

## 10. 常见坑

1. **跨数据源 JOIN**：sys_* 在用户中心库，law_* 在业务库，视图里 JOIN 不到——登录人区域/uid/姓名一律走公式或"数据模型+DDCAT_CALL"会话变量。
2. **USER_ID() ≠ sys_human.uid**：create_human_id / audit_human_id 要的是 int 型 uid，直接填 USER_ID()（varchar 主键）会存错甚至类型报错，必须走 `登录人uid` 会话变量。
3. **视图里调公式的转义**：`'${com.egova...runInSQL("公式")}'` 外层单引号+`${}`，公式内部双引号要 `\"` 转义；从网页复制公式先过一遍纯文本编辑器，别把 HTML 格式带进公式框。
4. **修改会话变量后**，引用它的列表过滤条件/视图要**重新选择/保存**一次才生效；不生效就删掉过滤条件重配。
5. **UNION 树 id 冲突**：机构 id 和法规 id 都是 bigint 会撞车，必须 CONCAT 前缀；UNION 各分支**列数、列序、类型必须一致**（数字列统一 CONCAT 成字符或都保持数字）。
6. **@DATE_FORMAT 的分钟是 `%i`** 不是 `%m`（%m 是月份）；国产库环境优先用 `@` 前缀自定义函数（@NOW()/@DATE_FORMAT/@CONCAT），且自定义函数名必须大写。
7. **文号规则**：规则要配"按日重置+4位补零"，否则跨天序号不归零、格式对不上 202606060001；用 GENERATE_SEQUENCE 时第5参是 applicationId，别漏。
8. **打印 API 忘加 Header `use-web-Authorization: true`** → 渲染接口 401/无权限；内外网环境还要在 API 后置脚本里 replaceAll 内网地址。
9. **打印子表只出一条** → 视图关联关系没选"一对多"；**导出报错扩不了行** → 子表表格没放模板最后一行（合并单元格挡住扩行）。
10. **预览路径版本差异**：`/linglong/design.html#/template/preview/{fileId}`（新）vs `/linglong/static/vue2/pc/third.html#/template/preview/{fileId}`（旧），word/excel 模板才能 office 预览；富文本模板只能走 pdfjs 预览。先手动验证再写进脚本。
11. **提示文案是采分点**："仅法规可新增案由！"、"请选择要打印的法规数据！"——标点（感叹号）都要一致。
12. **树 on-click 的 params 结构**先 console.log 确认（有的版本是 `params.node_type`，有的是 `params.node_type.value`），别盲写。
13. 新增案由后如果树上带计数，记得**同时刷新树面板**（`pageTreeEle.$$getRenderElement().$$refreshData()`）。
