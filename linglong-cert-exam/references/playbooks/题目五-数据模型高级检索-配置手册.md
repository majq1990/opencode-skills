# 题目五（抽考）：数据模型、高级检索 — 考试配置手册（20分）

> 场景：设备巡检标签列表。主表 `iot_inspection_task`，子表 `iot_inspection_task_tag`（`task_id` 关联）。
> 核心考点：主列表 SQL **禁止大表联查**，用 API 后置脚本按 `task_id` 批量查子表拼接标签；高级检索用 **exists 子查询**，不允许连表。
> 原题存档：`../exam/题目五-数据模型高级检索-原题.md`

## 1. 任务拆解（考试操作顺序）

| 步骤 | 操作 | 对应分值 |
|------|------|---------|
| ① | 数据模型：新建数据视图/数据模型，写主表 SQL + #if #else 条件 + exists 子查询，勾选**是否分页**，运行生成参数并设置必填 | 3分 |
| ② | API 管理：注册 API → 配置授权 → 配置地址（环境变量+相对路径）→ Query 参数 → 发送验证 | 3分（部分） |

## 2. 数据模型 SQL 完整模板（3分）

新建**数据视图（数据模型）**，选择业务库数据源，粘贴以下 SQL。
写完点【运行】，右侧自动生成参数列表 → 把 `plan_start_time_start`、`plan_start_time_end` 勾为**必填**，其余全部非必填 → 打开**是否分页**开关 → 保存。

```sql
SELECT
    t.task_id,
    t.task_code,
    t.device_code,
    t.device_name,
    t.device_type_name,
    t.site_name,
    t.area_name,
    t.inspect_org_name,
    t.inspector_name,
    t.task_status_name,
    t.risk_level_name,
    t.plan_start_time,
    t.plan_end_time,
    t.finish_time,
    t.task_desc,
    t.inspect_result,
    '' AS tag_names,
    '' AS tag_type_names,
    '' AS tag_group_names,
    '' AS tag_descs
FROM iot_inspection_task t
WHERE 1 = 1

/*计划开始时间：必填介于。#if #else 判空——不选时间不出数据*/
#if(plan_start_time_start != null && plan_start_time_start != '' && plan_start_time_end != null && plan_start_time_end != '')
    AND t.plan_start_time BETWEEN '${plan_start_time_start}' AND '${plan_start_time_end}'
#else
    AND 1 = 2
#end

/*巡检任务编号：包含（非必填）*/
#if(task_code != null && task_code != '')
    AND t.task_code LIKE '%${task_code}%'
#end

/*巡检任务状态：等于（非必填）*/
#if(task_status_name != null && task_status_name != '')
    AND t.task_status_name = '${task_status_name}'
#end

/*====== 高级检索 4 参数：exists 子查询，禁止连表，都过滤 delete_flag = 0 ======*/

/*标签名称：模糊*/
#if(tag_name != null && tag_name != '')
    AND EXISTS (SELECT 1 FROM iot_inspection_task_tag tt
        WHERE tt.task_id = t.task_id AND tt.delete_flag = 0
        AND tt.tag_name LIKE '%${tag_name}%')
#end

/*标签类型：模糊*/
#if(tag_type_name != null && tag_type_name != '')
    AND EXISTS (SELECT 1 FROM iot_inspection_task_tag tt
        WHERE tt.task_id = t.task_id AND tt.delete_flag = 0
        AND tt.tag_type_name LIKE '%${tag_type_name}%')
#end

/*标签说明：模糊*/
#if(tag_desc != null && tag_desc != '')
    AND EXISTS (SELECT 1 FROM iot_inspection_task_tag tt
        WHERE tt.task_id = t.task_id AND tt.delete_flag = 0
        AND tt.tag_desc LIKE '%${tag_desc}%')
#end

/*标签分组：精准匹配（等于）*/
#if(tag_group_name != null && tag_group_name != '')
    AND EXISTS (SELECT 1 FROM iot_inspection_task_tag tt
        WHERE tt.task_id = t.task_id AND tt.delete_flag = 0
        AND tt.tag_group_name = '${tag_group_name}')
#end

ORDER BY t.plan_start_time DESC
```

要点说明：
- **`'' AS tag_names` 等 4 个占位列必须写**：主 SQL 不联查子表，但响应结构里要有这 4 个扩展字段，后置脚本才有字段可回填、API 后置转换才能解析出这些输出字段（参考《数据模型、高级检索》中 `'' as lable_topic` 的做法）。
- 时间介于参数**必须命名** `plan_start_time_start` / `plan_start_time_end`（字段名 + `_start`/`_end` 后缀），这是灵珑自动接收介于条件的命名规范，写错查询面板传不进来。
- `#else AND 1 = 2` 就是"不选时间列表数据为空"的实现，这是 1 分的评分点，不能省。
- 灵珑 SQL 模板语法：字符串变量在 SQL 中要加引号 `'${xxx}'`；数值不加。判空固定写法 `#if(x != null && x != '') ... #end`。

## 3. API 配置步骤（3分）

进入应用【API管理】：

1. **新增接口**：API 列表新增分组（如"设备巡检"）→ 新增接口"设备巡检标签列表查询"，类型 **GET**。
2. **地址**：先在【环境变量】里新增本环境服务地址（ip:端口），接口地址选择该环境变量 + 数据模型的查询相对路径（数据模型保存后复制其接口地址/接口ID 拼相对路径；照当场提供的地址格式填）。**不要把 ip 写死在地址栏**，用环境变量。
3. **授权管理**：点【授权认证】按当场环境要求配置一条授权（脚本/Api Key/Base Auth/OAuth2 四选一，通常选脚本或复用平台已有授权）→ 回到接口的【授权管理】标签选中该授权。没配授权接口 401，此项 1 分。
4. **Query 参数**（【参数】标签页新增，全部勾选生效）：

| 参数名 | 说明 | 必填 |
|--------|------|------|
| plan_start_time_start | 计划开始时间开始值 | 必填 |
| plan_start_time_end | 计划开始时间结束值 | 必填 |
| task_code | 巡检任务编号，包含查询 | 非必填 |
| task_status_name | 巡检任务状态，精准匹配 | 非必填 |
| tag_name | 高级检索-标签名称，模糊 | 非必填 |
| tag_type_name | 高级检索-标签类型，模糊 | 非必填 |
| tag_desc | 高级检索-标签说明，模糊 | 非必填 |
| tag_group_name | 高级检索-标签分组，精准 | 非必填 |

   分页参数 pageIndex/pageSize：GET 请求由平台自动附带，**不需要手工处理**（题目原文明确）。
5. **响应字段（含扩展字段声明）**：给两个必填时间参数填上测试值 → 点【发送】→ 响应正常后进【后置转换】→ 点【解析】自动把转换前 JSON 解析为输出字段（含 tag/message/hasError/result/totalCount）。因为主 SQL 已用 `'' AS tag_names` 占位，`tag_names / tag_type_names / tag_group_names / tag_descs` 会一并出现在输出字段里；如果没占位就得在这里手动【新增】4 行扩展字段。也可直接配置 result→data 全字段转换。
6. 每一步改完**实时点【保存】**，再点【发送】验证。记下 **API 接口 ID**（列表 hook 要用）。

## 4. 全局变量配置（1分）

后置脚本里的数据库（数据源）名称**不允许写死**，必须走全局变量：

1. 进入应用【系统变量/变量管理】→ **静态变量** → 新增：
   - 名称：`数据源名称`（≤30字符）
   - 常量值：当场业务库的库名，例如 `iot_business`（≤100字符）
2. 保存后在变量列表**复制其 ID**，形如 `bd_var:4ea81933-13ff-4d82-af96-b110b4a2f82c`（V1.6.0.8+ 自带 `bd_var:` 前缀；旧版本 ID 无前缀，引用时写 `bd_var@{变量id}`）。
3. 后置脚本中获取方法（三选一，推荐第一种）：

```groovy
// 方法一（通用）：AppConstUtils 直接取静态变量值
var dbName = com.egova.lowcode.data.util.AppConstUtils.getValue("bd_var:你的变量ID");

// 方法二（1.5.3.88 / 1.6.0.26 及以上）：
var dbName = variables['STATIC_ENV']['数据源名称'];

// 方法三（1.5.3.88 / 1.6.0.26 及以上，静态变量优先于环境变量）：
var dbName = apiEnvUtil.getApiEnvInfo('数据源名称');
```

> 160 以上版本官方建议用全局变量替代老写法 `variables['env'].dealDbName`。

## 5. API 后置脚本完整模板（2分）

粘贴到接口【后置脚本】（groovy 语法），只需替换第 10 行的变量 ID：

```groovy
import java.util.stream.Collectors;

// 1. 反序列化数据模型返回结果
var dataMap = com.egova.json.utils.JsonUtils.deserialize(data, Map.class);

// 2. 收集本页主表返回的 task_id 集合
var taskIds = null;
if (dataMap && dataMap.result && dataMap.result.size() > 0) {
    taskIds = dataMap.result.collect { it.task_id };
}
if (!taskIds) {
    return
}

// 3. 数据源名称：必须通过全局变量获取，禁止写死库名（1分评分点）
var dbName = com.egova.lowcode.data.util.AppConstUtils.getValue("bd_var:你的变量ID");
var queryTemplate = sql.ofNamed(dbName);

// 4. 按 task_id 批量 in 查询子表，过滤 delete_flag = 0（评分点）
var tagList = queryTemplate.forList(
    'select task_id as taskId, tag_name as tagName, tag_type_name as tagTypeName, ' +
    'tag_group_name as tagGroupName, tag_desc as tagDesc ' +
    'from iot_inspection_task_tag ' +
    'where delete_flag = 0 and task_id in (:taskIds)',
    5000, ['taskIds': taskIds]);

// 5. 按 task_id 分组，逗号拼接四类标签信息
var nameMap  = new HashMap();
var typeMap  = new HashMap();
var groupMap = new HashMap();
var descMap  = new HashMap();
def appendVal = { map, key, val ->
    if (val == null || val == '') { return }
    var old = map.get(key);
    map.put(key, old == null ? val : old + '，' + val);
}
for (tag in tagList) {
    appendVal(nameMap,  tag.taskId, tag.tagName);
    appendVal(typeMap,  tag.taskId, tag.tagTypeName);
    appendVal(groupMap, tag.taskId, tag.tagGroupName);
    appendVal(descMap,  tag.taskId, tag.tagDesc);
}

// 6. 回填每行扩展字段（字段名与主 SQL 占位列一致）
for (var i = 0; i < dataMap.result.size(); i++) {
    var row = dataMap.result[i];
    row.tag_names       = nameMap.get(row.task_id);
    row.tag_type_names  = typeMap.get(row.task_id);
    row.tag_group_names = groupMap.get(row.task_id);
    row.tag_descs       = descMap.get(row.task_id);
}

// 7. 序列化返回
return com.egova.json.utils.JsonUtils.serialize(dataMap);
```

保存后再点【发送】：转换前结果里每行的 `tag_names` 等字段应从空字符串变成"标签A，标签B"形式的拼接值。有问题用 `out.println(...)` 打日志到响应【输出】里排查。

## 6. 列表 Hook 配置（1分 + 展示 2分）

### 6.1 骨架视图（列表部件的数据集）

hook 列表需要一个字段结构一致的视图做骨架。新建数据视图，按 API 响应字段写 mock SQL（**字段不能起别名、名称必须与响应字段一致**；datetime 字段用 `NOW()`）：

```sql
SELECT
    0 AS task_id,
    '' AS task_code,
    '' AS device_code,
    '' AS device_name,
    '' AS device_type_name,
    '' AS site_name,
    '' AS area_name,
    '' AS inspect_org_name,
    '' AS inspector_name,
    '' AS task_status_name,
    '' AS risk_level_name,
    NOW() AS plan_start_time,
    NOW() AS plan_end_time,
    NOW() AS finish_time,
    '' AS task_desc,
    '' AS inspect_result,
    '' AS tag_names,
    '' AS tag_type_names,
    '' AS tag_group_names,
    '' AS tag_descs,
    '' AS tag_name,
    '' AS tag_type_name,
    '' AS tag_group_name,
    '' AS tag_desc
```

> 最后 4 个单数占位列（tag_name 等）仅用于**高级检索组件绑定字段**，不加进列表展示列。

### 6.2 Hook 脚本

基于骨架视图创建表格列表部件 → 属性【Hook配置】开关置**开** → 点【设置方法】粘贴（**只改 apiId 一处**，换成第 3 步记下的 API 接口 ID——这是 1 分评分点）：

```js
function main(pageId, param) {
    return new Promise((resolve, reject) => {
        console.log(pageId, param);
        // ↓↓ 改成你自己的 API 接口 ID ↓↓
        const apiId = "27b84536-aea0-48df-b9ee-90ff69613c26";
        api.DATA_EXECUTOR().executeApiModelForList(apiId, "BUNCHES", param, { lostAbility: "01" })
            .then(res => {
                resolve(res);
            }).catch(() => {
                reject();
            })
    })
}
```

- `"BUNCHES"` = 灵珑 API（WIDZOM 是智云，别选错）。
- `lostAbility: "01"`：第一位 0 = 有分页能力（数据模型已开分页），第二位 1 = 缺失排序能力（这种模型代理列表不支持点表头排序）。
- 旧版本平台用 `api.API_DATA_EXECUTE(apiId, "BUNCHES", param, { lostAbility: "01" })`，1.4.4+ 两者兼容。
- hook 脚本里**不要修改 param**，否则导出数据与查询不一致。

### 6.3 分页与展示字段

- 列表部件属性开启**分页**，设置每页条数——必须与数据模型"是否分页"**同开**。
- 展示字段（评分点，至少含）：task_code、device_name、device_type_name、site_name、area_name、inspect_org_name、inspector_name、task_status_name、risk_level_name、plan_start_time、finish_time、tag_names（巡检标签）、tag_type_names（标签类型）、tag_group_names（标签分组）。用【批量修改】把标题改成中文。

### 6.4 查询面板（3 个固定过滤条件，3分）

查询面板只配这 3 个，**别多配**（配设备名称/设备类型/区域/风险等级会丢分）：

| 控件 | 绑定字段 | 匹配符 | 必填 |
|------|---------|--------|------|
| 日期范围/时间选择 | plan_start_time | 介于 | **必填** |
| 单行文本 | task_code | 包含 | 否 |
| 单行文本（或下拉单选） | task_status_name | 等于 | 否 |

- 绑定字段选骨架视图里的**原字段名**（未起别名），时间字段介于查询会自动按 `plan_start_time_start` / `plan_start_time_end` 传参——正好命中数据模型参数名。
- hook 列表的查询面板匹配符实际**不生效**，真正过滤逻辑在数据模型 SQL 里；但匹配符仍要配成与 SQL 一致（时间=介于、编号=包含、状态=等于），避免歧义，这也是"查询控件配置正确"的采分细节。
- 时间控件校验设为必填，可给默认值（如最近一个月）方便演示。

## 7. 高级检索配置（4分）

前提：灵珑版本 > 1.5.3.40。

1. **入口**：列表（或页面）配置 → 新增**顶部操作** → 选"高级搜索"按钮。
2. 点按钮的【设计组件】，打开高级搜索配置页（复用表单配置页），拖拽组件并绑定字段：

| 组件 | 绑定字段（=参数名） | 匹配符 | 说明 |
|------|--------------------|--------|------|
| 单行文本 | tag_name | 包含/模糊 | 标签名称 |
| 单行文本 | tag_type_name | 包含/模糊 | 标签类型 |
| 单行文本/多行输入 | tag_desc | 包含/模糊 | 标签说明 |
| 单行文本（或下拉单选） | tag_group_name | 等于 | 标签分组，精准匹配 |
| 日期范围选择 | plan_start_time | 介于（固定） | **必填 + 隐藏/不展示**，见下 |

3. **时间字段必填隐藏的处理**：数据模型的 `plan_start_time_start/end` 是必填参数，高级检索触发查询时也必须带上时间，否则命中 `#else AND 1=2` 全空。题目要求"时间字段必填不展示即可"——在高级搜索表单里放日期范围选择组件绑定 plan_start_time，设为必填并给默认值（如覆盖考试数据的大范围），再把组件设置为隐藏（显隐属性关闭/hidden）。这样用户只看到 4 个标签字段，但查询参数完整。若当场版本隐藏后不传值，则退而求其次：不放进高级搜索，靠普通查询面板的必填时间与高级检索条件**合并生效**（hook 的 param.condition 同时携带两者），实测哪种能带上时间就用哪种。
4. 匹配符说明：日期范围选择只支持"介于"；hook 列表下匹配符不生效，真实逻辑是 SQL 里的 `LIKE '%…%'`（3 个模糊）和 `=`（分组精准）+ exists + delete_flag=0，所以 4 分的实质在**第 2 节的 SQL** 里，这里只要参数名绑对、能把值传到 API。
5. 组件可设默认值但不会自动查询，需手动点【查询】。配置完成点【保存并退出】→ 回到设计器点【保存】→ 预览验证。
6. 注意：官方文档提示查询面板与高级搜索同时使用可能有问题（建议搜索框+高级搜索搭配）；本题两者都要，预览时重点回归"普通过滤仍生效 + 高级检索也生效"，若冲突优先保证参数都进了 hook 的 param（F12 看 console.log 打印的 param）。

## 8. 验证清单（逐项过一遍再交卷）

固定过滤 3 项：
- [ ] 不选计划开始时间（清空后查询）→ 列表**无数据**（#else 1=2 生效）
- [ ] 选一段计划开始时间 → 只出该范围内数据；改小范围数据变少
- [ ] task_code 输入某编号的中间片段 → 包含匹配命中
- [ ] task_status_name 输入/选择完整状态值 → 精准命中；输入半截状态 → 查不到（证明是等于不是包含）

高级检索 4 项（每项 1 分，都在选好必填时间的前提下验证）：
- [ ] tag_name 输入标签名关键字 → 只返回含该标签的任务；对一个 delete_flag=1 的标签名检索 → 不出数据
- [ ] tag_type_name 输入类型关键字 → 模糊命中
- [ ] tag_desc 输入说明关键字 → 模糊命中
- [ ] tag_group_name 输入完整分组名 → 精准命中；输入半截分组名 → 查不到

后置脚本：
- [ ] 列表"巡检标签/标签类型/标签分组"列出现"标签A，标签B"式拼接值；无标签的任务该列为空
- [ ] 在库里把某标签 delete_flag 置 1（或找现成数据）→ 拼接结果不含它

## 10. 常见坑

1. **介于参数命名不符**：写成 `startTime/endTime` 或 `plan_start_timeStart` 都收不到查询面板的介于值——必须是 `plan_start_time_start` / `plan_start_time_end`（字段名+后缀）。直接丢时间条件 1 分并连带"过滤生效"1 分。
2. **忘写 #else AND 1=2**：只判空不写 else，不选时间会查出全量数据，"不选时间列表数据为空"评分点丢 1 分。
3. **写死库名**：后置脚本里 `sql.ofNamed('iot_business')` 直接写库名 = 全局变量 1 分丢掉。必须先建静态变量再用 `AppConstUtils.getValue("bd_var:…")` 取。
4. **exists 忘过滤 delete_flag=0 / 后置脚本忘过滤**：两处都要有 `delete_flag = 0`，评卷会拿已删除标签数据测。
5. **图省事直接 JOIN 子表**：主 SQL `LEFT JOIN iot_inspection_task_tag` 是本题**红线**，约束里明确禁止大表联查，高级检索也只能 exists 不许连表。
6. **hook 里 apiId 没改**：粘了示例脚本忘换成自己的 API 接口 ID，列表空转，hook 1 分 + 展示 2 分连带丢。同时确认类型是 `"BUNCHES"` 不是 `"WIDZOM"`。
7. **主 SQL 没写 `'' AS tag_names` 占位列**：后置转换解析不出扩展字段、骨架视图/列表也没这列可绑，标签列展示不出来。占位列 + 后置脚本回填字段名 + 骨架视图列名，三处必须完全一致。
8. **骨架视图字段起了别名**：查询面板/高级检索绑定的字段名与参数名对不上，条件传不进 API。骨架视图一律用原字段名，datetime 用 `NOW()` 占位。
9. **模型分页与列表分页不同步**：数据模型"是否分页"和列表部件"分页"要全开（或全关），只开一边翻页错乱。
10. **多配了过滤条件**：查询面板加了设备名称/设备类型/区域/风险等级等字段——题目限制死只许 3 个固定条件，多配扣分。
11. **高级检索时间没带上**：高级检索查询若不携带必填时间参数，会命中 `1=2` 全空，看起来像"高级检索坏了"。按 §7.3 处理（隐藏必填时间组件给默认值，或与普通面板时间合并生效）。
12. **状态字段配成包含**：`task_status_name` 必须是等于（SQL 里 `=`），配成 LIKE 精准匹配评分点不过。
13. **API 改完没点保存就发送**：API 配置每步要实时【保存】，否则发送用的还是旧配置，排查半天白排。
14. **groovy 脚本引号**：`forList` 的 SQL 字符串里用单引号包裹，命名参数 `(:taskIds)` 用 map 传参，别手拼 in 字符串（有注入和格式风险）。
