# **一、试题背景**

现有法规管理系统，涉及颁发机构、法规、案由及审核等业务数据，相关数据分布在用户中心的人员表（sys\_human）、部门表（sys\_unit）、区域表（sys\_region）以及业务库的颁发机构表（law\_reg\_issuer）、法规表（law\_reg\_regulation）、案由表（law\_reg\_cause）、案由审核记录表（law\_reg\_audit\_log）中。

请基于上述数据表，在灵珑平台中完成法规管理模块的页面配置，实现：
1. 以左右分栏布局展示颁发机构与法规的联合树，以及右侧案由列表，支持按区域权限隔离数据；
2. 在法规节点下新增案由，案由编码由系统按文号规则自动生成，相关字段自动带入当前登录人信息；
3. 支持对待审核状态的案由执行审核通过或驳回操作，并自动生成审核记录；
4. 支持查看某条案由的历史审核记录列表；
5. 支持对当前选中法规节点下的所有案由数据进行打印预览，以表格形式展示法规信息与案由详情，用户可在预览后决定是否下载。

# **三、关联关系**

**人员与部门**
- `sys_human.unit_id` → `sys_unit.id`：人员属于某个部门，通过部门标识关联。
- `sys_human.region_id` → `sys_region.id`：人员属于某个区域，通过区域标识关联。

**人员与法规**
- `sys_human.uid` ← `law_reg_regulation.create_human_id`：法规记录了创建人，关联到人员表的 `uid` 字段（而非 `id`）。

**人员与案由**
- `sys_human.uid` ← `law_reg_cause.create_human_id`：案由记录了创建人，关联到人员表的 `uid` 字段（而非 `id`）。

**颁发机构（自关联）**
- `law_reg_issuer.senior_id` → `law_reg_issuer.id`：机构表自关联，构成树形层级结构（如：公安部 → 国务院 → 中央）。
- `law_reg_issuer.region_id` → `sys_region.id`：人员属于某个区域，通过区域标识关联。
- `law_reg_issuer.region_code` → `sys_region.code`：人员属于某个区域编码，通过区域编码标识关联。

**颁发机构与法规**
- `law_reg_regulation.reg_issuer_id`→ `law_reg_issuer.id`：法规选择颁发机构，关联到颁发机构表的id。

**法规与案由**
- `law_reg_cause.regulation_id` → `law_reg_regulation.id`：案由表关联所属的法规列表。

**法规与区划**
- `law_reg_regulation.region_id` → `sys_region.id`：法规属于某个区域，通过区域标识关联。
- `law_reg_regulation.region_code` → `sys_region.code`：法规属于某个区域编码，通过区域编码标识关联。

**案由与审核记录**
- `law_reg_audit_log.cause_id` → `law_reg_cause.id`：每条审核记录归属于某条法规。
- `law_reg_audit_log.audit_human_id` → `sys_human.uid`：记录了执行审核操作的人员。

**案由与区划**
- `law_reg_cause.region_id` → `sys_region.id`：案由属于某个区域，通过区域标识关联。
- `law_reg_cause.region_code` → `sys_region.code`：案由属于某个区域编码，通过区域编码标识关联。

> 注意：左侧树仅展示当前登录人有权限区域内的法规节点，跨区域法规不在树中显示。   

### **4.2 左侧联合树（5 分）**

#### **4.2.1 树节点层级**

树节点分两类，层级结构示意如下：
```
中央
├── 全国人民代表大会（颁发机构节点）
│   ├── 中华人民共和国道路交通安全法（法规节点）
│   └── ……
└── 国务院
    └── 公安部（颁发机构节点）
        └── 道路交通安全违法行为处理程序规定（法规节点）
地方
└── 湖北省
    └── 湖北省住建厅（颁发机构节点）
        └── ……

```

说明：只能看到当前登录人所属区域或所属下级区域的颁发机构和法律法规，注意如果是中央颁发的法律法规则全部可见

### **4.3 右侧案由列表（2 分）**

默认进入页面时（未点选任何法规节点），右侧展示案由列表的所有数据。

**展示字段：**

| **字段** | **来源** | **备注** |
|---------|---------|---------|
| 案由编码 | `law_reg_cause.code` | 文号格式，唯一 |
| 案由名称 | `law_reg_cause.name` | — |
| 法规名称 | `law_reg_cause.name` | 关联 `reg_issuer_id` 查询 |
| 案由类型 | `law_reg_cause.cause_type` | 需要显示对应文本而非数字 |
| 案由状态 | `law_reg_cause.status` | 0-待审核 / 1-已生效 / 2-已驳回 |
| 创建时间 | `law_reg_regulation.create_time` | 格式：yyyy-MM-dd HH:mm |
| 创建人名称 | `law_reg_regulation.create_human_name` | — |
| 顶部操作 | - | 新增案由 \| 预览 |
| 操作 | - | 编辑 \| 审核 \| 审核记录 |

列表支持按案由状态筛选（待审核 / 已生效 / 已驳回）。
> 说明：仅待审核状态的法规可执行审核操作；已生效或已驳回的法规不展示审核操作按钮。   

### **4.4 新增案由（4分）**

#### **4.4.1 入口**
1. 在左侧树中点选一个**法规节点**，右侧切换为该法规的案由列表
2. 右侧列表顶部提供"新增案由"按钮
3. 仅当所选为法规时，点击按钮可打开新增表单；否则前置校验提示"仅法规可新增案由！"
> 说明：法规数据已提前维护。

# 五、约束说明
1. 所有法规和案由数据的查询与操作基于当前登录人的区域权限进行隔离，无权限区域的数据不可见也不可操作；
2. 案由仅能在法规下新增；
3. 新增案由时，所属法规由左侧点选自动带入，用户不可在表单中手动修改
4. 审核记录日志只增不删，不支持修改
5. 法规数据已在后台提前维护，**前端不提供新增法规入口**
6. 批量打印时未勾选任何法规，系统提示"请选择要打印的法规数据！"
