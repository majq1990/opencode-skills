流程表单使用API进行收件
1 使用场景
在实际的应用中，业务表中不存在documentNo字段，但是流程表单是需要通过documentNo这个字段与业务表进行关联，默认收件方式无法和流程表单关联。于是使用API进行收件时将业务表中的唯一id（主键）作为关联条件，则在收件时需要将业务表中的id值赋值给流程表单的documentNo用来对两个表的关联。
示例：业务表（law_card_info）
流程表单的配置可参考：《PC应用搭建步骤（含流程）》
2 效果
在使用按钮点击后用脚本执行api收件操作，触发后会有当前业务表的信息与当前触发的流程相关的信息进行绑定，以便于可以查看当前业务数据的所在流程。

注意：
pageId：为流程表单的id
documentNo：为业务部需要与流程表单关联的字段值，在本示例中是使用law_card_info中的id
submitProcess(self, defaultParams, documentNo)为API收件的方法，在需要发起收件时调用，调用后会调用api进行收件
/**
 * 
 * @param {*} self 为当前页面的对象，用于报错消息弹窗提醒
 * @param {*} defaultParams 当前对象的默认参数
 * @param {*} documentNo 为业务表（law_card_info）中的逻辑主键，即id字段的值
 * @returns 
 */
function submitProcess(self, defaultParams, documentNo) {
    return new Promise((resolve, reject) => {

        var queryParams = [{
            "name": "pageId",
            "valueContent": "a77f469a-3151-47c9-bb50-2785c17b50e5"
        }];

        var jsonParams = {
            "documentNo": documentNo
        };

        /**
         * 330e5dec-f6a2-4cce-9e6b-5a354620c840 : api对应的id可以通过ctrl + shift + C 进行选中
         * queryParams ： 发起流程所需的参数
         * JSON.stringify(jsonParams) ： 将业务表（law_card_info）中的逻辑主键，即id字段的值转为json格式传递给api，对流程表单进行赋值
         */
        api.DATA_SOURCE_EXECUTE("330e5dec-f6a2-4cce-9e6b-5a354620c840", "api", queryParams, [], JSON.stringify(jsonParams)).then((res) => {
            console.log("响应", res);
            if (!res.hasError) {
                resolve(res);
            } else {
                self.$message.error(res.message);
            }
        }).catch(err => {
            self.$message.error(err.message);
            reject(err)
        });

    });
}
