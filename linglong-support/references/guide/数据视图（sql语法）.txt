数据视图（sql语法）
一、视图简介
视图是一种虚拟表，它基于一个或多个表的查询结果而创建。视图并不实际存储数据，而是在每次查询时动态生成结果。
二、使用视图
1、多表联合
（1）INNER JOIN（内连接）
只会返回两个表中匹配的行。
SELECT * 
FROM table1 
INNER JOIN table2 ON table1.column = table2.column;
例如，假设有 students 表（student_id，student_name）和 scores 表（student_id，score），要获取学生的姓名及其对应的分数，可以这样写：
SELECT s.student_name, sc.score 
FROM students s 
INNER JOIN scores sc ON s.student_id = sc.student_id;

（2）LEFT JOIN（左连接）
返回左表中的所有行，以及右表中与左表匹配的行。如果右表中没有匹配的行，则相应的列值为 NULL 。
SELECT * 
FROM table1 
LEFT JOIN table2 ON table1.column = table2.column;
例如，有 departments 表（department_id，department_name）和 employees 表（employee_id，employee_name，department_id），要获取所有部门及其所属员工的信息：
SELECT d.department_name, e.employee_name 
FROM departments d 
LEFT JOIN employees e ON d.department_id = e.department_id;

（3） RIGHT JOIN（右连接）
与左连接相反，返回右表中的所有行，以及左表中与右表匹配的行。如果左表中没有匹配的行，则相应的列值为 NULL 。
SELECT * 
FROM table1 
RIGHT JOIN table2 ON table1.column = table2.column;
假设还是上述的 departments 表和 employees 表，要获取所有员工及其所属部门的信息（包括没有部门的员工）：

FROM departments d 
RIGHT JOIN employees e ON d.department_id = e.department_id;

（4）其他函数
字符串函数
CONCAT(str1, str2, ...): 连接一个或多个字符串。
LENGTH(str): 返回字符串的长度。
UPPER(str): 将字符串转换为大写。
LOWER(str): 将字符串转换为小写。
REPLACE(str, find_string, replace_with): 替换字符串中的子串。
SUBSTRING(str, start, length): 返回字符串的一部分。
LOCATE(substring, string[, position]): 查找子串的位置。
INSTR(str, substring): 查找子串的位置，同LOCATE。
REVERSE(str): 反转字符串。
数学函数
ABS(X): 返回X的绝对值。
CEIL(X): 返回小于等于X的最小整数。
FLOOR(X): 返回大于等于X的最大整数。
ROUND(X[, D]): 四舍五入X到D位小数。
RAND(): 返回0到1之间的随机数。
MOD(N, M): 返回N除以M的余数。
PI(): 返回π的值。
POW(X, Y): 返回X的Y次方。
SQRT(X): 返回X的平方根。
日期和时间函数
CURDATE(): 返回当前日期。
CURTIME(): 返回当前时间。
NOW(): 返回当前的日期和时间。
DATE_ADD(date, INTERVAL expr unit): 添加时间间隔。
DATE_SUB(date, INTERVAL expr unit): 减去时间间隔。
DATE_FORMAT(date, format): 格式化日期和时间。
TIMESTAMPDIFF(unit, date1, date2): 计算两个日期之间的差值。
STR_TO_DATE(str, format): 将字符串转换为日期。
流程控制函数
IF(condition, true_expr, false_expr): 如果条件为真则返回true_expr，否则返回false_expr。
CASE ... WHEN ... THEN ... ELSE ... END: 多分支条件表达式。
IFNULL(expr1, expr2): 如果expr1为NULL则返回expr2，否则返回expr1。
其他常用函数
COUNT(expr): 计算非NULL值的数量。
SUM(expr): 计算所有值的总和。
AVG(expr): 计算所有值的平均值。
MAX(expr): 返回最大值。
MIN(expr): 返回最小值。

三、SQL注意细节
1、避免使用 % 前缀模糊查询
例如：like '%name'或者like '%name%'，这种查询会导致索引失效而进行全表扫描。但是可以使用like 'name%'，这种会使用到索引。
2、避免在 where 子句中对字段进行表达式操作
这种不会使用到索引：
select user_id,user_project from user_base where age*2=36;
可以改为：
select user_id,user_project from user_base where age=36/2;
任何对列的操作都将导致表扫描，它包括数据库函数、计算表达式等等，查询时要尽可能将操作移至等号右边。
3、避免隐式类型转换
where 子句中出现的 column 字段要和数据库中的字段类型对应
SELECT * from tc_video_group where group_id = 2773
SELECT * from tc_video_group where group_id = '2773'
4、提高group by语句的效率
1、反例
先分组，再过滤
select job, avg（salary） from employee
group by job
having job ='develop' or job = 'test';
2、正例
先过滤，后分组
select job，avg（salary） from employee
where job ='develop' or job = 'test'
group by job;

四、视图性能问题
灵珑平台有性能检测，但是只能作为参考，因为数据量一般都不大测不出性能问题
使用explain分析SQL执行计划
（1）type
system：表仅有一行，基本用不到；
const：表最多一行数据配合，主键查询时触发较多；
eq_ref：对于每个来自于前面的表的行组合，从该表中读取一行。这可能是最好的联接类型，除了const类型；
ref：对于每个来自于前面的表的行组合，所有有匹配索引值的行将从这张表中读取；
range：只检索给定范围的行，使用一个索引来选择行。当使用=、<>、>、>=、<、<=、IS NULL、<=>、BETWEEN或者IN操作符，用常量比较关键字列时，可以使用range；
index：该联接类型与ALL相同，除了只有索引树被扫描。这通常比ALL快，因为索引文件通常比数据文件小；
all：全表扫描；
性能排名：system > const > eq_ref > ref > range > index > all。
实际sql优化中，最后达到ref或range级别。
（2）Extra常用关键字
Using index：只从索引树中获取信息，而不需要回表查询；
Using where：WHERE子句用于限制哪一个行匹配下一个表或发送到客户。除非你专门从表中索取或检查所有行，如果Extra值不为Using where并且表连接类型为ALL或index，查询可能会有一些错误。需要回表查询。
Using temporary：mysql常建一个临时表来容纳结果，典型情况如查询包含可以按不同情况列出列的GROUP BY和ORDER BY子句时；

2、视图中调用公式
在某些场景中，视图中需要调公式来进行数据过滤，比如按当前登录者信息过滤数据，下面的示例给出了如何在视图中调用公式：
SELECT * from sys_region where name in ('${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("IF_FORMULA(ISEMPTY(REGION_ID()),\"\",\"REGION_CHILD_LIST(REGION_ID(),1,true,name)\")")}')
上面的sql实现了按当前登录者所属区域及子孙区域的区域名过滤出相关区划数据
可以看到使用了内置的公式执行方法:
com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("公式表达式")方法，括号中为公式表达式，里面可以根据场景替换成需要的公式（注意：示例中用了IF_FORMULA做了兼容处理，避免因为region_id取到的是空导致报错）
注意：
引用上述公式调用方法时需要用'${  }'括起来，里面的公式表达式需要用双引号引起来，如果公式表达式内部也有双引号，则需要用\"来替代避免被截断
执行的公式不支持使用sql中的其他字段作为公式的入参，只支持固定值或者内置的会话变量公式

4、交流一下 使用过程中的视图
WITH RECURSIVE sys_region_hierarchy AS (
  SELECT id, type, senior_id, name
  FROM sys_region
  WHERE senior_id = -1

  UNION ALL

  SELECT sr.id, sr.type, sr.senior_id, sr.name
  FROM sys_region sr
  JOIN sys_region_hierarchy srh ON sr.senior_id = srh.id
),
patrol_with_hierarchy AS (
  SELECT
    p.id,
    p.name,
    p.card_no,
    p.region_id,
    p.delete_flag,
    p.gender_id,
    p.unit_id,
    p.description,
    p.mobile_verify_media_id,
    p.valid_flag,
    p.phone AS 联系电话,
    CASE
      WHEN p.valid_flag = 1 THEN '在线'
      ELSE '离线'
    END AS status,
    su.name AS 所属部门,
    sh.id AS current_region_id,
    sh.type AS current_hierarchy_type,
    sh.senior_id
  FROM
    patrol p
  JOIN
    sys_unit su ON p.unit_id = su.id
  LEFT JOIN
    sys_region_hierarchy sh ON p.region_id = sh.id
)
SELECT
  pw.id,
  pw.name,
  pw.card_no,
  pw.region_id,
  pw.delete_flag,
  pw.gender_id,
  pw.unit_id,
  pw.description,
  pw.mobile_verify_media_id,
  pw.valid_flag,
  pw.联系电话,
  pw.status,
  pw.所属部门,
  CASE
    WHEN pw.current_hierarchy_type = 2 THEN pw.current_region_id
    WHEN pw.current_hierarchy_type = 3 THEN (SELECT sh.id FROM sys_region_hierarchy sh WHERE sh.id = pw.senior_id AND sh.type = 2)
    ELSE NULL
  END AS 区域,
  CASE
    WHEN pw.current_hierarchy_type = 3 THEN pw.current_region_id
    WHEN pw.current_hierarchy_type = 4 THEN (SELECT sh.id FROM sys_region_hierarchy sh WHERE sh.id = pw.senior_id AND sh.type = 3)
    ELSE NULL
  END AS 街道,
  CASE
    WHEN pw.current_hierarchy_type = 4 THEN pw.current_region_id
    ELSE NULL
  END AS 社区
FROM
  patrol_with_hierarchy pw
ORDER BY
  pw.id
