灵珑页面交互传参
灵珑平台可以通过组件、部件、页面及导航菜单等要素，构建高度灵活的页面组织与交互体系。本文将系统介绍各要素接收参数的底层逻辑，以帮助使用者可以在多样化场景下，建立完整的参数传递链路。
1 开始之前
在深入灵珑交互体系之前，需要了解一些有关传参的基本认识
在部件场景中，documentNo 是一个特殊参数，常用于数据查询
在页面场景中，可以通过部件渲染组件渲染部件
若无特殊说明，移动端和 PC 端传参方式一致，且传参效果也一致
灵珑交互传参过程包含以下步骤，本文也将从以下步骤进行介绍：
传参起始位置：这是参数提供的入口，可以是动作配置，也可以是一段 js 脚本，也包括 url 参数
传参中间链路：从参数起始位置到解析位置，中间经历的转发层，一般是需要向页面内的部件传参时，页面并不接收参数，只对参数进行转发
参数解析位置：这是参数最终使用的位置，参数将在这一层生效
2 传参起始位置
在灵珑内，可以通过多种方式，向组件、部件、页面内传参，常见的传参起始说明如下。
2.1 动作面板参数配置
通过动作面板配置动作，向部件/页面传参，打开一个页面或部件时，可以配置参数。其支持两种参数设置：标准和自定义。
标准模式：可以传递常量，也可以从当前动作执行上下文获取数据字段
自定义模式：完全使用 js 脚本提供参数
对于标准模式和自定义模式，灵珑内部提供的参数完全一致，但自定义模式会更加灵活，可以完全自定义参数
3.1 参数名称填什么
当配置一个参数名称时，参数名称填什么取决于【参数解析位置】接收的参数名称。所以在配置动作时，就需要判断当前参数最终的【参数解析位置】
通过动作弹窗配置的动作，如果打开的是部件，则最终作用的解析位置是【部件】；如果打开的是页面，则最终作用的解析位置是【页面】
页面本身并不具备参数使用能力，页面一般作为【传参中间链路】而存在，传递到页面的参数会在页面内解析以后，再通过部件渲染组件传递给【部件】
示例
地址：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995808753510813696
配置按钮【打开表单页面】，传入参数 formId，该参数会在页面内被接收解析
在页面中，为表单部件渲染组件配置参数，接收参数 formId，并映射为新的 documentNo 参数，实际最终表单部件获取的参数名为 documentNo
请注意理解参数从 formId 转变为 documentNo 的变化过程，一般而言，从始至终使用同一个参数名称是推荐做法
部件内如何使用参数？
对不同的部件，其内部有不同的使用逻辑，这一部分的内容会在本文参数解析与使用部分详细介绍
3.2 执行上下文提供哪些数据字段
当使用动作弹窗配置参数时，可以按照以下步骤判断当前执行上下文提供了哪些参数：
3.2.1 判断动作使用场景
当实际配置动作时，需要判断该动作触发时的上下文环境，上下文环境不一致，可以获取到的参数也不同
一般而言，在部件设计器内可以进行设计（配置）的组件，属于对应的部件场景；在页面设计器内可以进行设计（配置）的组件，属于对应的页面场景
3.2.2 各场景参数说明
以下是各个设计器场景下，可以获取到的参数说明
表单部件场景
如果该动作在表单部件场景内，当前动作上下文没有数据字段提供
列表部件场景
如果该动作在列表部件场景内，且该动作符合以下情况，则该动作可以使用当前环境已经绑定的数据字段（包括使用中的字段和隐藏字段），在实际执行时，会自动获取当前表格行、当前卡片的数据进行传参
表格列表单元格动作
表格列表操作列按钮
表格列表行点击、行双击动作
卡片列表操作列按钮
卡片列表字段链接动作
卡片列表点击卡片动作
⚠️ 注意：只有卡片列表内置【操作栏按钮组件】能获取上下文数据字段，在卡片布局内拖入的普通按钮组件无法获取上下文数据字段
示例：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995744773698260992
详情部件场景
如果该动作在详情部件场景内，在任意位置，该动作都可以使用当前环境已经绑定的数据字段
树部件场景
如果该动作在树部件场景内，且该动作为树节点操作栏按钮，则该动作可以使用当前环境已经绑定的数据字段
页面场景
如果该动作在页面场景内，当前动作上下文没有数据字段提供
3.3 自定义参数函数提供的参数
当使用自定义参数时，函数提供一个默认参数，包含当前执行上下文提供的数据字段
示例：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995744773698260992
在示例列表部件的操作列中，配置一个按钮【自定义函数获取参数】，其最终获取到的数据格式为：
params[fieldName].valuefieldName 是字段名称
params[fieldId]fieldId 是字段标识
可以通过以上方式获取对应的数据字段值
function main(params) {
    console.log("自定义传参提供的当前执行上下文环境参数：", params);
    return {
        documentNo: params.documentNo.value
    };
}
3 参数解析与使用
当配置好参数传递入口以后，经过中间链路转发，参数到达目标位置，被目标位置接收并解析，其遵循固定的解析与使用规则，接下来按照目标位置的场景。
3.1 表单部件
表单部件的核心渲染组件为 FormRenderView，通过动作配置的表单部件弹窗、页面内的表单部件渲染组件、展示的表单都是基于 FormRenderView 来渲染。
FormRenderView 上提供了表单 render API，这一部分可以在 《灵珑前端 JS-API》中查看，其中的 $$getExtraParams方法，该方法会返回当前表单部件接收到的外部参数，可以用于检查传参是否正确
表单部件中解析的参数，主要有以下用途：
获取 documentNo，进行数据查询与表单数据回显
获取组件 id，进行单个组件默认值填充
按照传参用途分别进行说明：
3.1.1 传递 documentNo 进行数据查询与表单数据回显
示例地址：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995774525809135616
在列表部件场景的操作列中，配置一个按钮【打开表单部件】，配置其动作为打开表单部件。参数设置部分，在列表部件场景中，表格列表操作列按钮可以获取到当前环境使用到的数据字段，所以配置参数传递文号，这样就可以打开表单部件并能回显对应文号的数据
显示效果：数据被回填到表单，可以进行编辑与保存
3.1.2 获取组件 id，进行单个组件默认值填充
示例地址：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995774525809135616
如果获取到的参数名称是表单内某个组件的组件标识，则该参数值会以默认值的形式，在一打开表单时就填充到对应组件
示例中，为组件【性别】（single_select_d1scpr）设置一个默认值，我们希望一打开表单就显示默认性别
显示效果：新增打开的表单，会自动填入默认值
3.2 列表部件
列表部件的核心渲染组件为 ListRenderView，通过动作配置的列表部件弹窗、页面内的列表部件渲染组件，展示的列表都是基于 ListRenderView 来渲染。
ListRenderView 上提供了列表 render API，这一部分可以在 《灵珑前端 JS-API》 中查看，其中的 $$getExtraParams方法，该方法会返回当前列表部件接收到的外部参数，可以用于检查传参是否正确
列表部件中解析的参数，主要有以下用途：
获取查询组件 id，用于设置查询条件默认值
3.2.1 获取查询组件 id，用于设置查询条件默认值
示例地址：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995814384745615360
上文表单部件中，打开的是部件弹窗。本列表部件中，打开的是页面，页面中传参多了一道映射，这部分在本文【参数名称填什么】有详细说明
在示例场景中，配置操作列按钮【打开列表页面】，配置打开一个页面，向页面传递参数 username
在页面中，配置列表部件渲染组件接收参数 username，并映射到列表部件的查询条件上，列表部件通过查询条件组件标识接收
显示效果：点击不同行的按钮，对应行的【员工姓名】字段被传递到查询条件中，进行初始化查询
3.3 详情部件
详情部件的核心渲染组件为 DetailRenderView，通过动作配置的详情部件弹窗、页面内的详情部件渲染组件，展示的详情都是基于 DetailRenderView 来渲染。
DetailRenderView 上提供了详情 render API，这一部分可以在 《灵珑前端 JS-API》 中查看，其中的 $$getExtraParams方法，该方法会返回当前详情部件接收到的外部参数，可以用于检查传参是否正确
详情部件中解析的参数，主要有以下用途：
获取详情字段名，用于进行详情数据查询
3.3.1 获取详情字段名，用于详情数据查询
示例地址：http://10.250.1.39:30095/magic/linglong/design.html#/list-design/wp_widget_1995818580135940096
在示例场景中，配置操作列按钮【打开详情部件】，配置打开一个详情部件，传递参数 name
显示效果：点击不同行的按钮，对应行的【员工姓名】字段被传递到详情中，进行初始化查询
备注：传递到详情部件的参数，会在接口请求时被一并带入，以实现过滤效果
