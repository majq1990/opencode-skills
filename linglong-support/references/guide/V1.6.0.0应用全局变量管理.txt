V1.6.0.0应用全局变量管理
文档变更记录
灵珑在搭建应用时会涉及到一些全局变量，包括在数据视图、JS脚本、公式、列表部件过滤条件、表单组件属性和api前后置脚本等位置，当应用或页面导出再导入时这些资源还需要手动调整配置适配新环境。那么，为了配置入口统一，也为了减少手动调整配置，在原来会话变量的基础上增加了静态变量，统称为系统变量。
1 变量管理
变量管理分为会话变量管理和静态变量管理，以ID作为唯一条件，本应用内不允许重名，跨应用允许重名。
2 会话变量（原有功能）
会话变量主要是配置表达式，分为内置会话变量和自定义会话变量。内置会话变量不允许编辑和删除。功能和原来一样。《会话变量配置》
内置会话变量：us-开头的，目前有7个内置。导出应用时不会导出内置会话变量。
全局会话变量：怎么来的？可能是手动写数据库表生成的。导出应用时不会导出全局会话变量。
私有会话变量：升级V1.6.0之后（有此新功能后），在灵珑应用里增加的会话变量都是私有变量。导出应用时可以导出私有会话变量。导入规则见本文“5 被引用变量的导入导出”。
3 静态变量（新增）
静态变量主要用来管理常量，包括在APP_CONST()公式、数据视图，JS脚本、列表部件过滤条件，表单组件配置项属性，api前后置脚本引用的常量内容。
同一个应用里会话变量和静态变量互相不允许重名，不同应用里允许重名；
名称：最多允许输入30个字符；
常量值：最多允许输入100个字符。
4 引用变量
在数据视图、JS脚本、公式、列表部件过滤条件、表单组件属性和api前后置脚本等位置会引用变量，引用时直接填写变量id，在变量管理列表中可以找到并复制使用（V1.6.0.8版本增加了“bd_var:”前缀）。
ID以“bd_var:”开头，便于在部件、页面、应用在复制、导出和导入时同步将关联的变量导出，保证完整性（V1.6.0.8版本支持）。
兼容旧版本的ID，引用变量时可以写“bd_var@{变量id}”（也就是变量id本身没有bd_var:前缀，在引用变量的JS脚本里写上“bd_var@{变量id}”，导出时可以把变量一起导出）。
4.1 公式APP_CONST()
系统提供了一个新公式来获取指定变量的值：公式APP_CONST() 用于获取用户会话变量的计算结果或静态变量的值。
key：静态变量或会话变量的id；
返回：静态变量的值，会话变量的计算结果。
例如：在表里给增加两个单行文本，配置默认值，使用APP_CONST()公式提取会话变量或静态变量的值。
4.2 数据视图引用静态变量
数据视图引用静态变量有两种方式。
第一种：红字是静态变量的ID
'${com.egova.lowcode.data.util.AppConstUtils::getValue("bd_var:4ea81933-13ff-4d82-af96-b110b4a2f82c-70bb-4d7d")}'
select * from dev_table1_edit
  where wenben2 like '%${com.egova.lowcode.data.util.AppConstUtils::getValue("bd_var:24bda5c2-f79d-4bc0-9c89-ed91f4763067")}%'
第二种：视图中调用APP_CONST公式，红字是静态变量的ID
'${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("APP_CONST(\"bd_var:4ea81933-13ff-4d82-af96-b110b4a2f82c-70bb-4d7d\")")}'
select * from dev_table1_edit
  where riqishijian2 
    between '${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("APP_CONST(\"bd_var:975c85b3-d9ff-43a7-83da-af17b9de9b16\")")}'
    and '${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("APP_CONST(\"bd_var:977022f0-97c6-4f12-8123-737660e2a852\")")}'
4.3 JS脚本中引用静态变量
在部件和页面JS里引用静态变量主要是使用：
方法一：this.$$getConstValue("bd_var:静态变量的id");
function main() {
    const a = this.$$getConst("bd_var:086c04a1-bd3b-4fb2-a5c2-503ebde192e6");
    console.log("常量值：this.$$getConst", a);
}
方法二：api.CONST["静态变量的id"]
function main() {
    console.log(api.CONST["bd_var:24bda5c2-f79d-4bc0-9c89-ed91f4763067"]);
}

4.4 列表条件过滤引用变量
列表条件过滤把原来的“登录者信息变量”改为“会话变量”，同时增加了“静态变量”，根据需要选择。过滤条件绑定后保存的是系统变量的id。这样在修改系统变量的名称后不需要更新列表的过滤条件。
静态变量：列表过滤条件选择静态变量实现过滤。
列表的表格字段【设置】的“条件样式”里设置静态变量。
4.5 组件引用静态变量
组件的属性里需要定义服务地址一类的场景，例如：地图、地图位置等组件，如果服务地址有变化，每次迁移环境后需要手动找到部件或页面修改地址。使用静态变量就解决了这个麻烦，可以引用静态变量，到系统变量里统一修改。

5 被引用变量的导入导出
当部件、页面、应用被复制或导出导入时，也会同时导出被引用的变量，部分引用可以导出，部分不能导出。
可以导出：数据视图、部件和页面JS、列表部件过滤条件和表单里的组件引用的变量可以导出和导出，如果会话变量里包含API，也会导出该API；
不能导出：API前置和后置脚本引用的变量不能导出
导出和导入时，会话变量的处理比较特殊，因为涉及到不能随意修改目标端变量配置的内容。
覆盖导入：ID不变，变量名称覆盖，表达式不变；
重新生成：ID增加后缀，变量名称增加后缀，表达式直接导入，里面引用API的ID变更为本次导入后API的ID；
5.1 部件JS引用的变量导出导入
如果部件js脚本里引用了会话变量或静态变量，同时该部件也可能被页面引用，此时导出部件、导出页面和导出应用都会导出部件js脚本引用的变量（统称变量）。再导入时也同步导入。包含会话变量引用的API。
部件发布后才能导出和导入，设计中的暂时不支持。
部件引用的变量修改过名称或值，再发布部件，再导出时可以导出修改后的变量内容。
开发侧注意：部件通过JS引用变量时不向lcbase_reference表里写记录，通过程序解析导出。
5.2 页面JS引用的变量导出导入
同部件js引用的导出和导入，也是发布后才能导出和导入。
5.3 数据视图引用的变量导出导入
如果数据视图引用了会话变量或静态变量，同时使用视图创建了部件（列表部件、详情部件），部件再被页面引用，此时导出部件、导出页面和导出应用都会导出视图里引用的变量（统称变量）。再导入时也同步导入。包含会话变量引用的API。
5.4 组件引用的变量导出导入
组件属性（如：地图组件、地图位置组件、地图绘制及其他业务组件）只能引用静态变量，被表单部件或页面引用时，此时导出部件、导出页面和导出应用都会导出视图里引用的变量（统称变量）。再导入时也同步导入。包含会话变量引用的API。
5.5 已有应用变量的导出导入
在V1.6.0.8版本之前的应用中创建的会话变量没有前缀，导出应用再导入（重新生成和覆盖导入）后会增加前缀，并在被引用的地方替换ID。仅自定义变量导入的时候加前缀，全局变量的ID不变。
旧应用引用变量的位置包括：列表部件过滤条件引用会话变量，API前后置脚本引用变量，数据视图引用变量，JS脚本引用变量。
