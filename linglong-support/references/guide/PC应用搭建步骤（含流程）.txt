应用系统的表单部件、列表部件和系统用到的部分页面涉及到的物理表在“业务实体”里新建或者导入。
导入的表需要在当前应用绑定的数据源里已经存在。
关于id和documentNo的说明（区分大小写）：
关于id字段
“业务实体”里的表均需要有id字段。
如果导入的表已经有id字段并且是主键则直接使用；
如果导入的表没有id字段，可以将主键字段的“别名”填写为id。
关于documentNo字段
如果“业务实体”里的表将做为表单部件里的子表（即明细组件）则需要有documentNo字段，用于与主表关联。
如果导入的外部表作为子表且没有documentNo字段，需要选择一个字段将“别名”填写为documentNo，要求是非空字段。
注意：别名为documentNo的字段数据是根据灵珑的规则生成和存储。
documentNo的数据类型说明
如果主表有documentNo，则必须是字符串且长度大于等于50，否则无法保存
如果主表没有documentNo，子表有documentNo，类型与主表的id字段的数据类型保持一致。可以是整型或字符型
如果主表有documentNo，子表也有documentNo，则均必须是字符串且长度大于等于50

function jumpToPage(self, result, defaultParams) {
    var element = self;
    var rootPageElement = null;
    result = JSON.parse(result);

    while (element) {
        if (element.getPageInfo && element.goHistory) {
            rootPageElement = element;
            break;
        } else {
            element = element.$parent;
        }
    }
    if (rootPageElement) {
        var data = result.result;

3 FAQ
3.1 如何确定案卷所属的流程版本？
问：流程发布了很多版本，在不同的版本分别有若干案卷，如何知道当前案卷属于哪个流程版本？
图 流程发布过的版本很多
图 不知道案卷属于哪个版本
方法一：看F12返回
在案卷列表里点【办理】或【详情】，看task?taskId=的请求返回值，里面包含defineId，中间两个冒号之间的数字就是所属的版本；
方法二：在业务库查表
根据案卷的documentNo在表lcwf_process_record里查processDefineId的值，中间两个冒号之间的数字就是所属的版本；
