## §1 DDCAT 数据模型（4 个模型逐个建）

### 1.1 新建模型的通用操作（每个模型都走这一遍）

1. 应用后台 → 左侧菜单找到**数据模型（ddcat）管理**（以现场界面为准，通常在应用管理/数据侧栏），点击**新建数据模型**。
2. 弹出新建界面后：
   - **模型名称**：填有辨识度的中文名（如"差错统计-SQL1"），方便回头找；
   - **数据源**：下拉选择**应用绑定的业务数据源**（即能查到 `mis_error_rec` 的那个库；考场一般只有一个可选项）。
3. 在 **SQL 编辑区**整段粘贴对应 SQL（§1.3~§1.6 各自给出）。
4. **入参配置**：在"入参/参数"区域逐个点"添加参数"，每个参数按下面三列填：

   | 填写项 | 怎么填 |
   |---|---|
   | 参数名称 | 必须与 SQL 里 `${}` / `#if` 中的变量名**逐字符一致（大小写敏感）** |
   | 参数类型 | 时间与区域填字符串；`unArchiveFlag` / `recMarkErrorFlag` 数值或字符串均可（见 §7 坑 1） |
   | 是否必填 | **全部选"否"（非必填）**——空参查全量是 2 分项 |

5. **出参配置**：点击"解析 / 执行"按钮（不同版本叫"解析 SQL"或"执行"，以现场为准），平台自动从 SELECT 列生成出参；逐个核对出参字段名与题目要求完全一致。
6. **分页开关**：SQL1 / SQL2 / 区域下拉**不开分页**；SQL3 **开启分页**（官方文档明确：列表的分页条件会带入 ddcat，**必须在数据模型中开启分页**）。
7. **测试执行**：在测试区给参数赋值后执行，按各模型小节给的三组用例跑。
8. 点**保存**。
9. **记录模型 ID**（两种方法，推荐方法一）：
   - 方法一：保存后重新点开"编辑"该模型，F12 Network 里找请求 `unity/data-model/{id}`，最后一段 UUID 即模型 ID（官方文档示例：`unity/data-model/18f28cef-1752-40eb-a189-b21ec98fc4d8` 中的 `18f28cef-...` 即模型 ID）；
   - 方法二：部分版本编辑页 URL 最后一段就是模型 ID，直接从地址栏取。
   - 抄入 §0.2 登记表。

### 1.2 灵珑 SQL 模板语法速记

- `${var}`：渲染参数值，**字符串参数要自己加引号** `'${var}'`，数值参数不加；
- `#if (v != null && v != '') ... #end`：判空包裹，参数为空时整段条件不拼入 SQL；
- `#tag where() ... #end`：自动生成 WHERE 并吃掉第一个 `and`；
- **四个入参为空时对应条件必须不生效**——所以每个动态条件都要包 `#if`（空参数逻辑 2 分）。

### 1.3 模型一：SQL1 统计指标（checkCount / errorCount / errorRate）

一次扫描 + 条件聚合（不要写 3 个子查询各扫一遍表，评分点"避免重复全表扫描"）：

```sql
SELECT
  COUNT(1) AS checkCount,
  IFNULL(SUM(CASE WHEN rec_mark_error_flag = 1 THEN 1 ELSE 0 END), 0) AS errorCount,
  IFNULL(ROUND(
    SUM(CASE WHEN rec_mark_error_flag = 1 THEN 1 ELSE 0 END) * 100.0
      / NULLIF(COUNT(1), 0)
  , 2), 0) AS errorRate
FROM mis_error_rec
#tag where()
  #if (createTimeStart != null && createTimeStart != '')
    and create_time >= '${createTimeStart}'
  #end
  #if (createTimeEnd != null && createTimeEnd != '')
    and create_time <= '${createTimeEnd}'
  #end
  #if (unArchiveFlag != null && unArchiveFlag != '')
    and un_archive_flag = ${unArchiveFlag}
  #end
  #if (districtName != null && districtName != '')
    and district_name = '${districtName}'
  #end
#end
```

SQL 要点：`ROUND(...,2)` 保留 2 位小数（1 分项）；`NULLIF` 防除零、`IFNULL` 防空表返回 NULL；`unArchiveFlag` 是数值列不加引号。

**逐步操作**：

1. 按 §1.1 新建模型，命名"差错统计-SQL1"，选数据源，粘贴上面 SQL。
2. 逐个添加 4 个入参（一个个点"添加"，填完一个再填下一个）：

   | 参数名称（逐字符照抄） | 类型 | 必填 |
   |---|---|---|
   | `createTimeStart` | 字符串 | 否 |
   | `createTimeEnd` | 字符串 | 否 |
   | `unArchiveFlag` | 数值或字符串 | 否 |
   | `districtName` | 字符串 | 否 |

3. 点"解析/执行"，确认出参恰好 3 个：`checkCount`、`errorCount`、`errorRate`（大小写一致）。
4. 分页开关保持**关闭**。
5. 测试执行三组用例（对应 2 分"注册及查询正常" + 2 分"空参数逻辑"）：
   - **用例 A（全空参）**：4 个参数都留空 → 应返回全表统计，errorRate 是 2 位小数；
   - **用例 B（单参）**：只填 `districtName`（从库里随便挑一个真实区域名）→ 数字应小于等于用例 A；再单测 `unArchiveFlag=0`（已办结，0 是有效值，不能被当空处理）；
   - **用例 C（全参）**：4 个都填 → 与手工 SQL 结果核对（可在测试区把条件写死跑一次对数）。
6. 保存 → 按 §1.1 步骤 9 记录 `{DDCAT_STAT_ID}`。

### 1.4 模型二：SQL2 TOP5 差错大类（errorMainTypeName / typeCount）

`error_main_type_names` 可能逗号分隔多值（如"标图不准确,案卷判断错误"），必须先拆分再统计。做法：**内层先按条件把差错件过滤成小结果集（只扫一次表），再连数字表拆分**：

```sql
SELECT t.errorMainTypeName, COUNT(1) AS typeCount
FROM (
  SELECT TRIM(SUBSTRING_INDEX(SUBSTRING_INDEX(e.error_main_type_names, ',', n.n), ',', -1)) AS errorMainTypeName
  FROM (
    SELECT error_main_type_names
    FROM mis_error_rec
    WHERE rec_mark_error_flag = 1
      AND error_main_type_names IS NOT NULL
      AND error_main_type_names != ''
      #if (createTimeStart != null && createTimeStart != '')
        and create_time >= '${createTimeStart}'
      #end
      #if (createTimeEnd != null && createTimeEnd != '')
        and create_time <= '${createTimeEnd}'
      #end
      #if (unArchiveFlag != null && unArchiveFlag != '')
        and un_archive_flag = ${unArchiveFlag}
      #end
      #if (districtName != null && districtName != '')
        and district_name = '${districtName}'
      #end
  ) e
  JOIN (
    SELECT 1 AS n UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4 UNION ALL SELECT 5
    UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8 UNION ALL SELECT 9 UNION ALL SELECT 10
  ) n ON n.n <= 1 + LENGTH(e.error_main_type_names) - LENGTH(REPLACE(e.error_main_type_names, ',', ''))
) t
GROUP BY t.errorMainTypeName
ORDER BY typeCount DESC
LIMIT 5
```

SQL 要点：差错大类只统计差错件（`rec_mark_error_flag = 1` 为固定条件，放 WHERE 首位，四个动态条件跟在后面）；数字表按逗号数 join，一条含 2 个大类的记录各计 1 次；`ORDER BY typeCount DESC LIMIT 5` 满足"按数量倒序 TOP5"（1 分项）。若测试库确认该字段全是单值，可简化为 `SELECT error_main_type_names AS errorMainTypeName, COUNT(1) AS typeCount ... GROUP BY ... ORDER BY ... LIMIT 5`。

**逐步操作**：

1. 新建模型"差错TOP5-SQL2"，选同一数据源，粘贴 SQL。
2. 添加与 §1.3 完全相同的 4 个入参（名称/类型/非必填一模一样）。
3. 点"解析/执行"，确认出参 2 个：`errorMainTypeName`、`typeCount`。
4. 分页**关闭**。
5. 测试三组用例：
   - 全空参 → 最多 5 行，`typeCount` 从大到小排列；
   - 先用全空参结果里手动数一下含逗号的多值记录是否被各计 1 次（在测试库跑 `SELECT error_main_type_names FROM mis_error_rec WHERE error_main_type_names LIKE '%,%' LIMIT 5` 抽查）；
   - 全参 → 行数只减不增，顺序仍降序。
6. 保存 → 记录 `{DDCAT_TOP5_ID}`。

### 1.5 模型三：SQL3 案件列表明细（列表页 Hook 用，开分页）

```sql
SELECT
  task_num AS taskNum,
  error_main_type_names,
  create_time,
  district_name,
  suggest
FROM mis_error_rec
#tag where()
  #if (createTimeStart != null && createTimeStart != '')
    and create_time >= '${createTimeStart}'
  #end
  #if (createTimeEnd != null && createTimeEnd != '')
    and create_time <= '${createTimeEnd}'
  #end
  #if (unArchiveFlag != null && unArchiveFlag != '')
    and un_archive_flag = ${unArchiveFlag}
  #end
  #if (districtName != null && districtName != '')
    and district_name = '${districtName}'
  #end
  #if (recMarkErrorFlag != null && recMarkErrorFlag != '')
    and rec_mark_error_flag = ${recMarkErrorFlag}
  #end
#end
ORDER BY create_time DESC
```

SQL 要点：比前两个多了第 5 个入参 `recMarkErrorFlag`（点差错件数跳转时传 1）；展示字段 taskNum 对应 `task_num`（抽查任务编号），若阅卷环境指认 `rec_task_num`（案件任务号）就换成它；**除 taskNum 外的字段名与列表查询面板字段保持一致，不要乱起别名**，否则面板条件匹配不上（§7 坑 9）。

**逐步操作**：

1. 新建模型"案件明细-SQL3"，选同一数据源，粘贴 SQL。
2. 添加 **5 个**入参：§1.3 的 4 个 + `recMarkErrorFlag`（数值或字符串，非必填）。
3. 点"解析/执行"，确认出参 5 个：`taskNum`、`error_main_type_names`、`create_time`、`district_name`、`suggest`。
4. **开启分页**（这是四个模型里唯一开分页的；⚠️ 后面 §2.6 列表部件的分页开关必须与它同步，全开或全关，否则翻页错乱）。
5. 测试三组用例：空参返回全量首页；`recMarkErrorFlag=1` 只剩差错件；全参组合正确、按 `create_time` 倒序。
6. 保存 → 记录 `{DDCAT_LIST_ID}`。

### 1.6 模型四：区域下拉（tc_region，region_type=2）

```sql
SELECT region_name AS label, region_name AS value
FROM tc_region
WHERE region_type = 2
ORDER BY region_id
```

SQL 要点：value 用 `region_name` 而不是 region_id——考题明确"区域表的 id 与差错件表的区域 id 并不对应，传参用 districtName"（§7 坑 13）。label/value 命名是给下拉组件直接吃的格式。

**逐步操作**：

1. 新建模型"区域下拉"，选同一数据源，粘贴 SQL。
2. **不加任何入参**（固定查 region_type=2）。
3. 点"解析/执行"，确认出参 `label`、`value` 两列且值相同（都是区域名）。
4. 分页**关闭**。
5. 测试执行 → 应返回全部二级区域，无重复。
6. 保存 → 记录 `{DDCAT_REGION_ID}`。

#### ✅ 本步验证
- 登记表前 4 行已填满 4 个模型 ID；
- 每个模型都通过了"空参 / 单参 / 全参"测试；`unArchiveFlag=0` 有过滤效果（不等于空）；
- SQL1 的 errorRate 是 2 位小数；SQL2 结果降序且 ≤5 行；SQL3 分页开启；区域模型输出 label/value。

#### ⚠️ 注意事项
- ⚠️ 参数名大小写敏感：`districtname` ≠ `districtName`，配错的表现是"传了参但过滤不生效"。
- ⚠️ `unArchiveFlag=0` 被当成空（§7 坑 1）：SQL `#if` 里 `!= ''` 对数字 0 不会误判，但测试时必须专门跑一次 `=0` 确认。
- ⚠️ 差错率除零/空表（§7 坑 6）：`NULLIF(COUNT(1),0)` + `IFNULL(...,0)` 保证空数据时返回 0 而不是 NULL/报错。
- ⚠️ `error_main_type_names` 多值不拆分（§7 坑 7）：会把 "A,B" 当一个类型统计，TOP5 全错；拆分后 TRIM 去空格。
- ⚠️ 性能分：SQL1 一次扫描聚合、SQL2 内层先过滤再拆分，都是"避免不必要的全表重复扫描"的得分写法，别改回多子查询。

## §2 案件列表页（先于看板建，产出 {LIST_PAGE_ID}）

### 2.1 准备列表架子（空视图/实体）

灵珑列表基于视图搭架子，而本题数据实际由 ddcat 供给，**视图只是壳，不需要真实数据**。官方文档做法：用

```sql
select '' as taskNum, '' as error_main_type_names, '' as create_time, '' as district_name, '' as suggest from dual
```

这类语句造一个空视图（字段名与 SQL3 输出列一一对应；`from dual` 写法按现场数据库方言调整，MySQL 可省略）。若考场环境已提供 `mis_error_rec` 实体/视图，直接基于它建列表也可以——**关键是列表列字段名要与 SQL3 输出列一致**。

操作：数据管理/视图管理里新建视图（以现场界面为准），保存备用。

### 2.2 新建表格列表部件

1. 左侧菜单 → **部件设计**（或"部件管理"，以现场为准）→ 新建 → 选择**列表部件**（表格列表类型）。
2. 命名"案件列表"。
3. **数据集绑定**：选择 §2.1 的空视图（或实体）。
4. 进入列表设计器（URL 形态类似 `design.html#/list-design/{widgetId}`）。

### 2.3 表格列字段配置

在列表设计器中把以下 5 个字段加入表格展示列（从左侧字段区拖入或勾选，以现场为准），逐列设置：

| 列字段名（与 SQL3 输出一致） | 列标题（显示名） |
|---|---|
| `taskNum` | 任务编号 |
| `error_main_type_names` | 差错大类 |
| `create_time` | 上报时间 |

| `suggest` | 建议 |

列标题批量改中文没问题，但**字段名本身不许再起别名**（§7 坑 9）。

### 2.4 查询面板配置

1. 在列表设计器的**查询面板**区域，把以下字段拖入查询条件（以现场界面为准，通常是把字段从字段列表拖到查询面板区）：
   - `create_time`：匹配符（操作符）设为**「介于」**——官方文档明确：date 字段默认设置为"介于"，**介于操作的参数按 `_start` / `_end` 后缀约定**传给模型；
   - `district_name`：匹配符"等于"（下拉或文本均可）；
   - `un_archive_flag`：匹配符"等于"。
2. 查询字段标题改成中文（上报时间/区域/是否办结）。
3. 记下时间、区域两个查询字段外壳组件的唯一标识（形如 `query_field_wrapper_xxxxxx`，在该查询字段的属性面板「唯一标识」处，以现场为准）——§2.5 脚本回填默认值要用。

### 2.5 Hook 开启与脚本粘贴

**入口（官方文档原话）**：表格列表 → **高级 → Hook 配置**，打开开关，进入脚本编辑框，整段粘贴：

```js
function main(pageId, param) {
    var self = this;
    var DDCAT_LIST_ID = "{DDCAT_LIST_ID}"; // SQL3 列表明细模型

    // 1. 取看板跳转带来的路由参数；缓存到 window，翻页/刷新时复用
    var routeParams = {};
    if (self.$route && self.$route.params && self.$route.params.createTimeStart !== undefined) {
        routeParams = self.$route.params;
        window.REC_LIST_PARAMS = routeParams;
    } else if (self.$route && self.$route.params && Object.keys(self.$route.params).length) {
        routeParams = self.$route.params;
        window.REC_LIST_PARAMS = routeParams;
    } else {
        routeParams = window.REC_LIST_PARAMS || {};
    }

    // 2. 跳转参数合入模型入参（空值不塞，满足"空参数不生效"）
    param.condition.params = param.condition.params || {};
    ["createTimeStart", "createTimeEnd", "districtName", "unArchiveFlag", "recMarkErrorFlag"]
        .forEach(function (k) {
            var v = routeParams[k];
            if (v !== undefined && v !== null && v !== "") {
                param.condition.params[k] = v;
            }
        });

    // 3. 回填查询面板默认值，让用户看得到当前过滤条件（组件 id 换成实际值）
    try {
        var dateCmp = self.$$("query_field_wrapper_日期组件id");
        if (routeParams.createTimeStart && dateCmp) {
            dateCmp.queryField.props.startTime.defaultValue.value = routeParams.createTimeStart;
            dateCmp.queryField.props.endTime.defaultValue.value = routeParams.createTimeEnd;
        }
        var districtCmp = self.$$("query_field_wrapper_区域组件id");
        if (routeParams.districtName && districtCmp) {
            districtCmp.queryField.props.defaultValue.value = routeParams.districtName;
        }
    } catch (e) { console.warn("查询面板回填跳过", e); }

    // 4. 用 ddcat 数据模型代替默认查询（列表初始化即自动执行，无需再点查询）
    return new Promise(function (resolve, reject) {
        api.DATA_EXECUTOR().executeDataModelForList(DDCAT_LIST_ID, param)
            .then(function (res) { resolve(res); })
            .catch(function () { reject(); });
    });
}
```

**粘贴后必须做的 3 处替换**：
1. `{DDCAT_LIST_ID}` → 登记表里 SQL3 的模型 ID；
2. `query_field_wrapper_日期组件id` → §2.4 记下的时间查询字段唯一标识；
3. `query_field_wrapper_区域组件id` → 区域查询字段唯一标识。

**脚本逐段说明**：
- 第 1 段：优先取 `$route.params`（看板 `$router.push` 带来的参数），并存进 `window.REC_LIST_PARAMS`；翻页时路由参数会丢，从 window 兜底（§7 坑 14）。
- 第 2 段：只把**非空**参数合入 `param.condition.params`——评分点"空参数不生效"（2 分）就在这三行 if；⚠️ 只做键值合并，**不要重建/删除 param 结构**（§7 坑 11），否则影响导出与查询一致性。
- 第 3 段：把参数回填到查询面板默认值，用户能看见当前过滤条件；包 try-catch 是为了组件 id 填错时不至于整个列表挂掉。
- 第 4 段：返回 Promise，用 ddcat 模型代替视图默认查询。官方文档另有等价写法 `api.MODEL_DATA_EXCUTE(模型id, param)`——若现场 `DATA_EXECUTOR().executeDataModelForList` 不存在（版本差异），换成 `api.MODEL_DATA_EXCUTE(DDCAT_LIST_ID, param)` 即可，param 默认不需要修改。

**用户手动改面板条件时的机制**（官方文档）：面板条件会进入 `param.condition`（tableConditionDescriptor.members），由模型变量同名匹配生效——所以 §2.4 才强调字段名不许起别名、时间用「介于」走 `_start/_end` 约定。

### 2.6 分页设置

列表设计器 → 表格列表属性（以现场为准，通常在表格属性/分页区）→ **开启分页**，每页条数与常规一致（如 10/20）。⚠️ 必须与 §1.5 模型的分页开关**同步开启**（§7 坑 10），列表的 pageIndex/pageSize 会自动带入 ddcat。

### 2.7 页面包装、记录 pageId

1. 左侧菜单 → **页面管理** → 新建页面，命名"案件列表"。
2. 页面画布中拖入**列表部件渲染组件**（或"部件渲染"组件，以现场为准），在其属性面板选择 §2.2 建好的"案件列表"部件。
3. 保存并发布页面。
4. **记录 pageId**：页面管理里该页面的 URL 最后一段（或页面属性里的页面标识，以现场为准），抄入登记表 `{LIST_PAGE_ID}`。
5. 点预览，确认列表能出全量数据（此时无路由参数，Hook 空参走全量）。

#### ✅ 本步验证
- 预览列表页：5 列都有数据、按上报时间倒序、分页翻页正常；
- 查询面板手动选时间/区域/办结 → 点查询 → 数据被正确过滤（F12 Network 看模型请求的 params）；
- `{LIST_PAGE_ID}` 已回填登记表。

#### ⚠️ 注意事项
- ⚠️ 排序（官方文档）：列表排序字段若与 ddcat SQL 里 `ORDER BY` 的字段相同，排序会失效；本题 SQL3 已写死 `create_time DESC`，列表列不要再对 create_time 配排序规则。
- ⚠️ 面板字段起别名（§7 坑 9）：查询面板字段名要与模型 SQL 输出列名一致（时间介于条件按 `_start`/`_end` 前缀约定），别名会导致面板条件失效。
- ⚠️ 备选纯配置方案（不写 Hook）：列表用普通数据视图，跳转改用「动作面板打开页面 + 页面列表渲染组件参数映射到查询条件组件标识」（参见官方《灵珑页面交互传参》3.2.1 节：页面把参数映射到列表部件的查询条件组件标识，列表初始化自动按默认值查询）；此时把传值字段放查询面板第一位，否则传值不成功。**考试推荐 Hook 方案**，可控性强且与原题演示一致。

## §3 看板页面（布局 + 组件逐个配置）

### 3.1 新建看板页面

1. 页面管理 → 新建页面，命名"领导看板"（或题目指定名）。
2. 进入页面设计器（URL 形态类似 `design.html#/design/{pageId}`）。

### 3.2 布局容器逐层搭建

按官方《基于页面的工作台配置》的标准做法：

1. 从组件区把**「容器」**组件拖入页面画布（顶层壳）。
2. 在容器内拖入**「网格布局（简）」**组件，把页面切成 **4 行**：
   - 第 1 行：标题区（矮行）；
   - 第 2 行：筛选区（矮行）；
   - 第 3 行：指标区；
   - 第 4 行：图表区。
   行高比例在网格布局属性面板调整（以现场界面为准，通常有行列数和比例设置）。
3. 第 2 行筛选区内再拖一个**容器**，在其属性面板**开启弹性模式 → 横向排列 → 主轴对称排布**（官方文档原话），让三个筛选组件横向排开。

层级清楚（标题/筛选/指标/图表四区肉眼可辨）即拿满"布局清晰 2 分"。

### 3.3 标题区

1. 第 1 行网格内拖入**容器**，属性面板设背景色/高度（以现场为准）。
2. 容器内拖入**文本**组件，双击或在属性面板改文字为"差错案件统计"，调字号加粗。

### 3.4 筛选区（3 个组件逐个配）

**组件 a：自定义时间选择**

1. 从组件区找到**「自定义时间选择」**组件（题目指定组件名），拖入筛选容器最左。
2. 属性面板按默认即可（如有"默认选中今天/本月"选项按题意，不确定就不设默认）。
3. 属性面板找到**「唯一标识」**，抄入登记表 `{CMP_DATE}`。

**组件 b：下拉单选（区域）**

1. 拖入**「下拉单选」**组件，放时间选择右侧。
2. **绑定数据源**：在组件属性面板的数据源/选项配置里，选择"数据源"方式，类型选 **ddcat**，选中 §1.6 的区域下拉模型（或填 `{DDCAT_REGION_ID}`，以现场界面为准——通常是在属性面板"数据源"区点添加/选择数据源）。
3. **fit 脚本入口**：数据源配置里有**「请求返回时的数据适配（fit）」**脚本框（官方文档中数据源配置固定包含 willFetch / fit / onError 三个函数入口），点开粘贴：

```js
function fit(result) {
  let list = (result && result.length) ? result : [];
  // ddcat 返回的 result 已是数组且含 label/value
  list = list.map(g => ({ label: g.label, value: g.value }));
  list.unshift({ label: "全部", value: "" });
  return list;
}
```

   脚本说明：ddcat 类型数据源返回的 result 已是数组（不像 api 类型要 `JSON.parse`，§7 坑 2）；`unshift` 在头部塞一个「全部」选项，value 为空串——选"全部"时 `getFilterParams` 不传 `districtName`，正好命中"空参查全量"。
4. 唯一标识抄入 `{CMP_DISTRICT}`。

**组件 c：下拉单选（是否办结）— 静态选项**

1. 再拖入一个**「下拉单选」**，放最右。
2. 这个不绑数据源，用**静态选项**：属性面板选项配置区逐条点"添加选项"（以现场界面为准）：

   | label（显示） | value（值） |
   |---|---|
   | 全部 | （空串） |
   | 未办结 | 1 |
   | 已办结 | 0 |

   （un_archive_flag 含义：1=未归档/未办结，0=已归档/已办结。）
3. 唯一标识抄入 `{CMP_ARCHIVE}`。

### 3.5 指标区：看板指标展示组件

1. 第 3 行网格内拖入**「看板指标展示」**组件（题目指定组件名）。
2. **不在属性面板绑数据源**——本题指标数据由 §4 页面 JS 里 `DATA_SOURCE_EXECUTE` 查回后直接赋值给 `dataSource.options`（官方领导看板文档同款做法），属性面板保持默认即可；如属性面板要求必须有初始 options，可先留 3 个占位项。
3. 唯一标识抄入 `{CMP_METRIC}`。
4. onClick 事件绑定放到 §4.4 做（先把布局搭完）。

### 3.6 图表区：横向柱状图组件

1. 第 4 行网格内拖入**「横向柱状图」**组件。
2. 同样不绑数据源，由 §4 JS 赋值。
3. 唯一标识抄入 `{CMP_BAR}`。
4. 占比基数说明（官方文档）：横向柱状图有"占比基数（baseDataValue）"概念——组件 value 达到基数才把柱子撑满；§4 脚本里用 `this.$$m('唯一标识').props.chartOption.baseDataValue = 最大值` 动态设置，无需在属性面板手填。

### 3.7 组件清单总核对

| 区域 | 组件 | 数据来源 | 关键配置 |
|---|---|---|---|
| 标题区 | 自定义容器 + 文本 | — | 容器设背景/高度，文本写"差错案件统计" |
| 筛选区 | 自定义时间选择 | — | 记下 id `{CMP_DATE}` |
| 筛选区 | 下拉单选（区域） | ddcat `{DDCAT_REGION_ID}` | fit 脚本 unshift「全部」(value="")，id `{CMP_DISTRICT}` |
| 筛选区 | 下拉单选（是否办结） | 静态选项 | 全部=""、未办结=1、已办结=0，id `{CMP_ARCHIVE}` |
| 指标区 | 看板指标展示 | JS 赋值（SQL1） | id `{CMP_METRIC}`，绑 onClick 跳转 |
| 图表区 | 横向柱状图 | JS 赋值（SQL2） | id `{CMP_BAR}` |

六类组件一个不缺 = "页面组件选择正确 2 分"。

#### ✅ 本步验证
- 页面预览：四个区域肉眼分明；区域下拉能拉出「全部 + 所有二级区域」；办结下拉三个选项；指标和柱状图此时还没数据（正常，§4 才赋值）。
- 登记表 5 个 `{CMP_*}` 全部填齐。

#### ⚠️ 注意事项
- ⚠️ 唯一标识一个都不能抄错：JS 里 `self.$$(id)` 找不到组件不报错只返回 undefined，表现为"页面没反应"，排查成本很高。抄的时候直接从属性面板复制粘贴。
- ⚠️ 区域下拉 value 必须是 region_name（§7 坑 13）——§1.6 的 SQL 已保证，这里别在 fit 里改成 id。
- ⚠️ 「全部」选项 value 必须是空串 `""` 而不是字符串 `"全部"`，否则会把"全部"当区域名传给 SQL 查出 0 条。

## §4 页面 JS（生命周期 + 事件绑定）

### 4.1 didMount 绑定入口

**入口**：看板页面设计器 → 页面设置/属性 → **生命周期** → **页面加载完成（didMount）** → 绑定动作 → 选择**「自定义动作」**（以现场界面为准；与官方领导看板文档"全局方法注册于表单部件 didMount 事件"同一机制——在页面或部件的动作面板/生命周期里绑 JS）。

自定义动作脚本编辑框可点**「全屏」**放大、点**「验证」**检查语法（官方《动作面板》文档功能）。整段粘贴：

### 4.2 页面全局脚本（粘贴后替换 7 个占位 ID）

全局函数挂 window，满足"全局函数封装 2 分"：

```js
function main() {
    var self = this;

    // ===== 常量：所有资源 ID 只在此处声明 =====
    var DDCAT_ID = {
        STAT: "{DDCAT_STAT_ID}",   // SQL1 统计模型
        TOP5: "{DDCAT_TOP5_ID}"    // SQL2 TOP5 模型
    };
    var CMP_ID = {
        DATE: "{CMP_DATE}",         // 自定义时间选择
        DISTRICT: "{CMP_DISTRICT}", // 区域下拉单选
        ARCHIVE: "{CMP_ARCHIVE}",   // 是否办结下拉单选
        METRIC: "{CMP_METRIC}",     // 看板指标展示
        BAR: "{CMP_BAR}"            // 横向柱状图
    };
    window.CMP_ID = CMP_ID;

    // ===== 获取筛选参数（空值不放入，满足"筛选项为空时不传该参数"）=====
    function getFilterParams() {
        var params = {};
        var timeCmp = self.$$(CMP_ID.DATE);
        if (timeCmp && timeCmp.currentTime) {
            params.createTimeStart = timeCmp.currentTime.start.format("YYYY-MM-DD 00:00:00");
            params.createTimeEnd = timeCmp.currentTime.end.format("YYYY-MM-DD 23:59:59");
        }
        var districtCmp = self.$$(CMP_ID.DISTRICT);
        var districtName = districtCmp ? districtCmp.$$getValue() : "";
        if (districtName) params.districtName = districtName;
        var archiveCmp = self.$$(CMP_ID.ARCHIVE);
        var unArchiveFlag = archiveCmp ? archiveCmp.$$getValue() : "";
        // 注意 0 是有效值（已办结），不能用 if(unArchiveFlag) 判断
        if (unArchiveFlag !== "" && unArchiveFlag !== null && unArchiveFlag !== undefined) {
            params.unArchiveFlag = unArchiveFlag;
        }
        return params;
    }
    window.GET_FILTER_PARAMS = getFilterParams;

    // 对象 → DATA_SOURCE_EXECUTE 的 queryParams 数组格式
    function toQueryParams(obj) {
        return Object.keys(obj).map(function (k) {
            return { name: k, valueContent: obj[k] };
        });
    }

    // ===== Loading 开关 =====
    function setLoading(id, loading) {
        var cmp = self.$$(id);
        if (cmp && cmp.data.props.loadingConfig) {
            cmp.data.props.loadingConfig.loading = loading;
        }
    }

    // ===== 全局刷新（页面初始化 + 筛选变化统一走这里）=====
    window.refreshData = function () {
        var queryParams = toQueryParams(getFilterParams());
        setLoading(CMP_ID.METRIC, true);
        setLoading(CMP_ID.BAR, true);

        // --- 指标区：SQL1 ---
        api.DATA_SOURCE_EXECUTE(DDCAT_ID.STAT, "ddcat", queryParams, [], "").then(function (res) {
            // ddcat 类型 res.result 已是数组，不需要 JSON.parse
            var row = (res && !res.hasError && res.result && res.result.length) ? res.result[0] : {};
            var metricCmp = self.$$(CMP_ID.METRIC);
            if (metricCmp) {
                metricCmp.data.props.dataSource.options = [
                    { name: "checkCount", text: "抽查数",   value: String(row.checkCount || 0), unit: "件", checked: false },
                    { name: "errorCount", text: "差错件数", value: String(row.errorCount || 0), unit: "件", checked: false },
                    { name: "errorRate",  text: "差错率",   value: String(row.errorRate == null ? 0 : row.errorRate), unit: "%", checked: false }
                ];
            }
            setLoading(CMP_ID.METRIC, false);
        }).catch(function (err) {
            console.error("统计模型查询失败", err);
            setLoading(CMP_ID.METRIC, false);         // 失败也必须关 Loading
            self.$message.error("案件统计数据加载失败");
        });

        // --- 图表区：SQL2 ---
        api.DATA_SOURCE_EXECUTE(DDCAT_ID.TOP5, "ddcat", queryParams, [], "").then(function (res) {
            var list = (res && !res.hasError && res.result) ? res.result : [];
            var barData = list.map(function (item) {
                return {
                    name: item.errorMainTypeName,
                    text: item.errorMainTypeName,
                    value: item.typeCount || 0,
                    unit: "件",
                    checked: false
                };
            });
            var barCmp = self.$$(CMP_ID.BAR);
            if (barCmp) {
                // 占比基数取返回最大值（列表已倒序，取第一条），柱子按比例撑满
                var maxVal = barData.length ? barData[0].value : 0;
                self.$$m(CMP_ID.BAR).props.chartOption.baseDataValue = maxVal || 1;
                barCmp.data.props.dataSource.options = barData; // 空数组也赋值，数据为空不报错
            }
            setLoading(CMP_ID.BAR, false);
        }).catch(function (err) {
            console.error("TOP5 模型查询失败", err);
            setLoading(CMP_ID.BAR, false);
            self.$message.error("差错类型 TOP5 加载失败");
        });
    };

    // ===== 页面首次加载自动查询 =====
    window.refreshData();
}
```

**脚本逐段说明（对照评分点）**：
- **常量区**：所有资源 ID 只在此处声明，其他地方通过 `window.CMP_ID.XXX` 引用——官方领导看板文档硬性规范："不允许在脚本的其他地方出现组件标识"。
- **getFilterParams**：从三个筛选组件取值，**空值不放入 params**（"筛选项为空时不传该参数"，交互要求第 5 条）；时间用组件的 `currentTime.start/end`（官方文档同款 API），补 `00:00:00` / `23:59:59` 防时间越界（§7 坑 12）；`unArchiveFlag` 用 `!== ""` 判断，0 不会被丢（§7 坑 1）。
- **toQueryParams**：把对象转成 `DATA_SOURCE_EXECUTE` 要求的 `[{name, valueContent}]` 数组格式（官方 SDK 方法签名：`DATA_SOURCE_EXECUTE(id, sourceType, queryParams, formParams, jsonParams)`）。
- **setLoading**：通过 `cmp.data.props.loadingConfig.loading` 开关组件加载态（官方 SET_CMP_LOADING 同款写法）。
- **refreshData**：全局刷新入口，页面初始化和筛选 onChange 都走它（"全局函数封装与事件绑定 2 分"）；两个模型请求各自 then/catch，**catch 里必关 Loading + $message.error 提示**（"Loading 与异常处理 2 分"）。
- **ddcat 返回结构**：`res.result` 已是数组直接用，不要 `JSON.parse`（§7 坑 2——"api" 类型才是 JSON 字符串）。
- **组件赋值格式**：options 每项必须含 `name/text/value/unit/checked`（§7 坑 4），value 转字符串。
- **占比基数**：`$$m(id).props.chartOption.baseDataValue = 最大值`，官方文档原话"也可通过接口返回数据的最大值设置占比基数"。

**保存动作**：粘贴替换完 ID → 点「验证」→ 点确定/保存。⚠️ 若保存报错（window 上挂自定义方法导致的平台已知问题，§7 坑 5）：把代码复制后在小窗重新粘贴、点一下空白处再确认，多试几次。

### 4.3 筛选组件绑定 onChange（3 个组件各做一遍）

**入口**：选中组件 → 属性面板 → **高级 → 添加绑定动作**（官方《动作面板》文档：组件绑定事件在"高级-绑定动作"里配置）→ 事件选 **onChange（值修改后）** → 动作类型选**「自定义动作」** → 粘贴：

```js
function main(params) {

}
```

对**自定义时间选择、区域下拉、办结下拉**三个组件各绑一次，脚本完全相同。这满足交互要求 2/3/4 条"修改 X 后统计数据实时刷新"。

### 4.4 指标组件绑定 onClick 跳转

**入口**：选中「看板指标展示」组件 → 高级 → 添加绑定动作 → 事件选 **onClick**（官方文档："该事件在点击看板指标展示组件的每个栏目时触发"，e 为该栏目信息，含 name/text）→ 自定义动作，粘贴：

```js
function main(e) {
    // 差错率不跳转（4 分项里的红线）
    if (!e || (e.text && e.text.indexOf("率") > -1)) return;

    var params = window.GET_FILTER_PARAMS ? window.GET_FILTER_PARAMS() : {};
    // 点差错件数：额外携带 recMarkErrorFlag=1；点抽查数：查全部，不带该参数
    if (e.name === "errorCount") {
        params.recMarkErrorFlag = 1;
    }
    this.$router.push({
        name: "page-preview",
        query: {
            title: "案件列表",
            pageId: "{LIST_PAGE_ID}",
            showHeader: this.$route.query.showHeader,
            isFromAction: 1,
            _t: new Date().getTime() + ""
        },
        params: params
    });
}
```

粘贴后把 `{LIST_PAGE_ID}` 换成登记表里的列表页 pageId。

**脚本说明**：
- 第一行红线：`e.text` 含"率"直接 return——"点击差错率不跳转"是 4 分项的扣分红线（§7 坑 8）；
- `e.name === "errorCount"` 时额外带 `recMarkErrorFlag=1`（只查差错件）；点抽查数不带该参数（查全部）；
- 跳转用 `this.$router.push`（官方领导看板文档同款：name 固定 `page-preview`，query 里带 title/pageId/showHeader/isFromAction/_t，筛选参数放 `params`）——**不是 window.open**：push 保留页面栈，列表页返回时看板还在、筛选条件不丢（交互要求第 11 条，§7 坑 14）。

#### ✅ 本步验证
- 预览看板：首次加载指标区出现 3 个数、柱状图出现 ≤5 根柱且降序（首次加载自动查询 = 交互要求第 1 条）；
- 改任一筛选项 → 两块数据实时刷新，刷新瞬间能看到 Loading；
- F12 Console 无红色报错；Network 里每次 onChange 恰好发出 2 个模型请求，且空筛选项没出现在请求参数里；
- 点"抽查数"→ 跳列表全量（带当前筛选）；点"差错件数"→ 列表只剩差错件；点"差错率"→ 不跳；
- 从列表页返回 → 看板筛选条件保持不丢。

#### ⚠️ 注意事项
- ⚠️ Loading 忘关（§7 坑 3）：成功回调、catch 里都要 `setLoading(id, false)`，评分表单独 2 分；页面一直转圈大多是失败分支没关。

- ⚠️ 数据格式（§7 坑 4）：options 每项必须含 `name/text/value/unit/checked`，格式不对组件直接空白不报错。
- ⚠️ 排查思路：组件不显示数据 → Console 里 `console.log` 看 res；点击没反应 → 在 onClick 里加 `debugger`，F12 下点击会断住（官方调试文档方法）。

## §7 常见坑总表（考场救命清单）

> 14 条已按操作步骤就近内嵌「⚠️」提示，此处汇总备查。

1. **`unArchiveFlag=0` 被当成空**：0 是"已办结"有效值，JS 判空必须用 `!== ""` 而不是 truthy；SQL `#if` 里 `!= ''` 对数字 0 不会误判，但 JS 层若把 0 丢了照样查全量。（内嵌于 §1 注意事项、§4.2 脚本注释、§5 步骤 4）
2. **ddcat 与 api 返回结构不同**：`DATA_SOURCE_EXECUTE(..., "ddcat", ...)` 的 `res.result` 已是数组直接用；`"api"` 类型的 `res.result` 是 JSON 字符串要 `JSON.parse`。别抄混。（内嵌于 §3.4 fit 说明、§4.2 脚本注释）
3. **Loading 忘关**：成功回调、catch 里都要 `setLoading(id, false)`，评分表单独 2 分；页面白屏/一直转圈大多是失败分支没关。（内嵌于 §4 注意事项）
4. **指标/柱状图数据格式**：options 数组每项必须含 `name/text/value/unit/checked`，value 建议转字符串；格式不对组件直接空白。（内嵌于 §4 注意事项）
5. **保存 window 挂载脚本报错**：平台已知问题，复制代码到小窗重新粘贴、点空白处再确认，多试几次。（内嵌于 §4.2 保存动作、§4.3）
6. **差错率除零/空表**：`NULLIF(COUNT(1),0)` + `IFNULL(...,0)`，空数据时指标显示 0 而不是报错（交互要求第 8 条）。（内嵌于 §1 注意事项、§5 步骤 11）
7. **error_main_type_names 多值**：不拆分会把"A,B"当成一个类型统计，TOP5 结果错；拆分后记得 TRIM 去空格。（内嵌于 §1.4、§1 注意事项）
8. **点击差错率也跳转**：onClick 第一行就 `if (e.text.indexOf("率") > -1) return;`，这是 4 分项的扣分红线。（内嵌于 §4.4）
9. **列表面板字段起别名**：ddcat 代理查询时，查询面板字段名要与模型 SQL 输出列名一致（时间介于条件按 `_start`/`_end` 前缀约定），别名会导致面板条件失效。（内嵌于 §2.3、§2.4、§2 注意事项）
10. **分页不同步**：SQL3 模型"是否分页"与列表部件"分页"开关必须全开或全关，否则翻页错乱、导出数据不一致。（内嵌于 §1.5、§2.6）
11. **Hook 里粗暴改 param**：只往 `param.condition.params` 合并键值，不要重建/删除 param 结构，否则影响导出与查询一致。（内嵌于 §2.5 脚本说明）
12. **时间格式越界**：开始时间补 `00:00:00`、结束时间补 `23:59:59`，结束用 `<=`；开始/结束都空时不传，SQL 不拼条件。（内嵌于 §4.2 脚本注释）
13. **区域传值用 region_id**：tc_region 的 id 与 mis_error_rec.district_id 不对应，下拉 value 必须用 region_name，传参名 districtName。（内嵌于 §1.6、§3 注意事项）
14. **返回看板筛选丢失**：跳转必须用 `this.$router.push`（保留页面栈）；列表页参数存 `window.REC_LIST_PARAMS`，翻页时兜底。（内嵌于 §2.5、§4.4、§5 步骤 9/10）

## 附录 C：ddcat 代理列表的排序/分页规则（《如何使用ddcat数据模型动态查询列表数据》）

- **排序**：列表排序字段不含计算字段时，列表排序条件会转成 ORDER BY 拼到 ddcat SQL 上，**ddcat 自带条件在前，列表条件在后**；若 ddcat 的 ORDER BY 与列表排序存在相同字段，排序失效。列表排序字段含计算字段时，仅列表排序生效。本题 SQL3 已写死 `create_time DESC`，列表侧不要再配 create_time 排序。
- **分页**：列表的分页条件自动带入 ddcat 执行，前提是**数据模型开启分页**；两侧开关必须同步（§7 坑 10）。
