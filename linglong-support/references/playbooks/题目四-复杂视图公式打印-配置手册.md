## §0 前置准备

### 0.1 注册业务实体（4 张 law 表）

**入口**：进入应用后，顶部/左侧切到 **工作台 → 数据管理 → 业务实体**。

逐张表操作（law_reg_issuer / law_reg_regulation / law_reg_cause / law_reg_audit_log 共 4 次）：

1. 在业务实体列表页点 **【导入】**（表已在业务库物理存在，走导入而不是新建；按钮名可能是"导入表/从数据源导入"，以现场界面为准）。

### 0.2 数据源确认

1. **业务库数据源**：law 系列 4 张表所在库。应用创建时绑定，工作台里建视图时数据源下拉能选到它。

### 0.3 自定义会话变量（3 个数据模型型 + 1 个公式型）

**为什么要建**：表单默认值要填"当前登录人"的区域编码、uid（int）、姓名；视图要按"登录人区域及下级"过滤。内置会话变量给不全这些值（尤其 uid），所以自建。

**内置会话变量对照**（可直接在公式里用，不用建）：

| 标识 | 变量名称 | 公共表达式 |
|---|---|---|
| us-1 | 所属单位 | `DEPARTMENT_ID()` |
| us-2 | 用户标识 | `USER_ID()` |
| us-3 | 用户账户 | `USER_USERNAME()` |
| us-4 | 当前时间 | `NOW()` |
| us-5 | 区域标识 | `REGION_ID()` |

> ⚠️ 题目要求创建人标识存 **sys_human.uid（int）**，而 `USER_ID()` 返回的是 varchar 主键 id，**两者不是一回事**——这就是要建 `登录人uid` 会话变量的原因。

#### 0.3.1 会话变量①：登录人区域编码

**第一步：建数据模型（用户中心数据源）**

1. **工作台 → 数据管理 → 数据模型**（若你的版本数据模型在别的分组下，以现场界面为准）→ 点 **【新增】**。
2. 名称填 `登录人区域编码模型`；**数据源选：用户中心**。
3. SQL 编辑框粘贴（注意 `${...runInSQL(...)}` 整段原样，双引号别丢）：

```sql
SELECT code
FROM sys_region
WHERE id = ${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("REGION_ID()")}
```

4. 点 **【执行】** 测试：应返回当前登录人区域的一行 code。
5. 点 **【保存】**。
6. **抄数据模型 id**：保存后看**浏览器地址栏最后的一串 id**，形如 `ds_mod_9bdc40be-4da5-437c-a2c6-c4a045f872d7`，抄下来记为 `<区域编码模型id>`。

**第二步：建会话变量**

1. **应用设计 → 基础配置 → 会话变量**（列表页展示所有会话变量；内置的全局会话变量不可编辑删除，自建的是私有会话变量）。
2. 点 **【新增会话】**，弹出新增窗口：
   - 会话命名：`登录人区域编码`（取有意义的名称）；
   - 公式/表达式框粘贴：

```
DDCAT_CALL('<区域编码模型id>','','','result.code')
```

   > DDCAT_CALL 四个参数：数据模型id / 入参名 / 入参值 / 取值路径。这里模型无入参，中间两个留空字符串；`result.code` 表示取返回结果第一行的 code 字段。
3. 点 **【保存】**；确认该变量为**启用**状态（会话变量在启用状态下才可使用）。
4. **抄会话变量 ID**：在会话变量列表/编辑页获取该变量的 ID（形如 `bd_var_xxxx`，编辑窗口或 URL 里可见，以现场界面为准），§1 视图 SQL 里 `getSessionVariable("...")` 要填它。

#### 0.3.2 会话变量②：登录人uid

同 0.3.1 流程，两处不同：

1. 数据模型名称 `登录人uid模型`，数据源仍选**用户中心**，SQL：

```sql
SELECT uid
FROM sys_human
WHERE id = '${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("USER_ID()")}'
```

   > ⚠️ sys_human.id 是 varchar，`${...}` 外面**要包单引号**；0.3.1 的 sys_region.id 是 int，不包引号。别抄混。
2. 【执行】→ 应返回当前登录人的一行 int 型 uid → 【保存】→ URL 抄 `<uid模型id>`。
3. 会话变量命名 `登录人uid`，公式：

```
DDCAT_CALL('<uid模型id>','','','result.uid')
```

#### 0.3.3 会话变量③：登录人姓名

可以复用 0.3.2 的思路单独建一个模型（也可以把 0.3.2 的模型 SQL 改成 `SELECT uid, name FROM sys_human WHERE ...` 一个模型两个变量共用）：

1. 数据模型 `登录人姓名模型`（用户中心数据源）：

```sql
SELECT name
FROM sys_human
WHERE id = '${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("USER_ID()")}'
```

2. 【执行】→【保存】→ 抄 `<姓名模型id>`。
3. 会话变量命名 `登录人姓名`，公式：

```
DDCAT_CALL('<姓名模型id>','','','result.name')
```

#### 0.3.4 会话变量④：权限区域编码集（公式型，不需要数据模型）

1. 应用设计 → 基础配置 → 会话变量 → 【新增会话】。
2. 会话命名 `权限区域编码集`，公式框直接填组合公式：

```
REGION_CHILD_LIST(REGION_ID(), null, true, 'code')
```

   > REGION_CHILD_LIST('regionId', level, includeSelf, 'field')：regionId 填 null/当前值时取登录人区划；level 填 null 表示取全部层级下级；includeSelf=true 表示含本节点；'code' 表示返回 code 字段列表。即"登录人区域及全部下级区域"的 code 列表。
3. 【保存】→ 确认启用 → **抄该会话变量 ID**，记为 `<权限区域编码集会话变量ID>`（§1/§3 视图 SQL 都要用）。

#### 0.3.5 会话变量生效验证（4 个都做）

- 快捷验证：随便找/建一个表单页面，放一个"单行文本"组件 → 组件属性 → 默认值 → **公式编辑** → 填 `DDCAT_CALL(...)` 或 `REGION_CHILD_LIST(...)` → 预览页面看组件是否带出期望值。
- 或页面脚本里跑：

```javascript
api.EXEC_FORMULA("REGION_CHILD_LIST(REGION_ID(), null, true, 'code')").then(res => {
  console.log("公式执行结果为：", res.result);
});
```

**✅ 本步验证**：4 个会话变量全部出现在会话变量列表且启用；公式验证能取到 区域code / int型uid / 姓名 / code列表 四个值；3 个数据模型 id + 4 个会话变量 ID 已抄录。

**⚠️ 注意事项**：
- **从网页/文档复制公式，先粘到纯文本编辑器（记事本）再复制进灵珑公式框**，防止带 HTML 格式导致公式不生效（官方文档明确提醒过）。
- **修改会话变量公式后，引用它的列表过滤条件/视图要重新选择、重新保存一次才生效**；仍不生效就删掉过滤条件重配。
- 会话变量也可用 `API_CALL('ds_api:xxx', '入参名', 入参值, 'result.xxx')` 调 API 接口取值，本题用 DDCAT_CALL（数据模型）即可。

## §1 联合树视图（机构 + 法规 UNION，区域权限过滤）

### 1.1 先查"中央"区域 code

区域权限要求"中央颁发的法规全员可见"，SQL 里要写死中央的 code：

1. 到 **统一用户中心 → 基础数据 → 行政区划**（或直接查库）找 `name='中央'`（通常是顶级节点）的记录，抄其 **code** 值，记为 `<中央区域code>`。
2. 查不到界面就在数据视图里临时执行 `SELECT id, code, name FROM sys_region WHERE senior_id IS NULL OR senior_id = -1 OR senior_id = 0`（用户中心数据源）看顶级节点。
3. 拿不准就把它配成**静态变量**（应用设计 → 基础配置 → 静态/全局变量，V1.6.0+ 支持），SQL 里用 `${com.egova.lowcode.data.util.AppConstUtils::getValue("bd_var:<静态变量id>")}` 引用——改起来不用动 SQL。

### 1.2 新建视图

1. **工作台 → 数据管理 → 数据视图** → 点 **【新增视图】**（SQL 语法类型）。
2. 名称填 `v_issuer_reg_tree`；**数据源选：业务库**（law 表所在库）。
3. SQL 编辑框粘贴（`<权限区域编码集会话变量ID>`、`<中央区域code>` 换真实值）：

```sql
SELECT node_id AS id, senior_id, node_name AS name, node_type, real_id, regulation_code
FROM (
    /* 节点类型1：颁发机构（自关联树） */
    SELECT
        CONCAT('ORG_', i.id)                        AS node_id,
        CASE WHEN i.senior_id = '0' OR i.senior_id IS NULL
             THEN '0' ELSE CONCAT('ORG_', i.senior_id) END AS senior_id,
        i.name                                      AS node_name,
        1                                           AS node_type,
        CONCAT('', i.id)                            AS real_id,
        ''                                          AS regulation_code
    FROM law_reg_issuer i
    WHERE i.delete_flag = 0
      AND ( i.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
            OR i.region_code = '<中央区域code>' )
    UNION ALL
    /* 节点类型2：法规，挂在其颁发机构节点下 */
    SELECT
        CONCAT('REG_', r.id)                        AS node_id,
        CONCAT('ORG_', r.reg_issuer_id)             AS senior_id,
        r.name                                      AS node_name,
        2                                           AS node_type,
        CONCAT('', r.id)                            AS real_id,
        r.code                                      AS regulation_code
    FROM law_reg_regulation r
    WHERE r.delete_flag = 0
      AND ( r.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
            OR r.region_code = '<中央区域code>' )
) t
ORDER BY node_type, id
```

4. 点 **【执行】**：下方应返回机构 + 法规两类行（node_type=1/2，node_id 带 ORG_/REG_ 前缀）。
5. 确认结果正确后点 **【保存】**（官方步骤明确是**先【执行】后【保存】**）。

### 1.3 SQL 要点（读懂再抄）

- **两类节点用前缀区分**（`ORG_` / `REG_`）避免 bigint id 撞车；`node_type` 供 JS 判断节点类型；`real_id` 存真实主键；`regulation_code` 供表单带入法规编码。
- **区域权限**：`权限区域编码集`（=登录人区域及所有下级的 code 列表）IN 匹配 law 表冗余的 `region_code`；**中央全员可见**用 `OR region_code = '<中央区域code>'` 兜底。
- 会话变量在视图里的标准引用格式（官方文档原文）：
  `${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("会话变量ID", true)}`
- 不想走会话变量，也可在视图里直接内联公式（文档验证过的写法，注意内部双引号 `\"` 转义）：

```sql
AND i.region_code IN ('${com.egova.lowcode.base.util.TemplateFormulaUtils::runInSQL("IF_FORMULA(ISEMPTY(REGION_ID()),\"\",\"REGION_CHILD_LIST(REGION_ID(),null,true,code)\")")}')
```

- **备选思路（senior_code 前缀匹配）**：sys_region.senior_code 存上级编码路径。若环境里 REGION_CHILD_LIST 不可用，可先用会话变量取 `登录人区域编码`，再 `AND (region_code = '${登录人code}' OR region_code IN (SELECT code FROM <同库冗余的区域表> WHERE senior_code LIKE CONCAT('%','${登录人code}','%')))`——但 sys_region 在用户中心库，业务库视图 JOIN 不到，**优先用 REGION_CHILD_LIST 方案**。

**✅ 本步验证**：视图【执行】能出数据；node_id 全部带前缀；换一个**非中央区域账号**登录预览，只能看到本区域+下级+中央的节点。

**⚠️ 注意事项**：
- UNION 各分支**列数、列序、类型必须一致**（数字列统一 CONCAT 成字符或都保持数字），否则执行报错或树渲染错乱。
- 视图里执行的公式**不支持用 SQL 其他字段作为公式入参**，只支持固定值或内置会话变量公式。
- `'${...}'` 外层单引号别丢；公式内部双引号必须 `\"` 转义，否则被截断。

### 2.3 树 on-click 联动脚本

1. 选中**树部件（树面板）** → 右侧属性面板 → **组件动作** → 找到 **on-click** → 点击进入动作/脚本编辑（官方文档路径：*点击树面板，在树的属性面板中配置组件动作 on-click，编写 js 脚本*）。
2. 动作类型选 **自定义脚本 / JS 脚本**，粘贴（核心：法规节点传 regId，机构节点传 issuerId，并把当前节点存到页面级变量供"新增/预览"按钮校验）：

```javascript
function main(params) {
    const self = this;
    // 把选中节点存到页面根，供新增/预览按钮前置校验用
    const root = self.$$roots()[0];
    root.currentTreeNode = params;   // 含 node_type / real_id / regulation_code / name

    const pageTableList = root.$$element("page_widget_list_<右侧列表标识>");
    if (!pageTableList || !pageTableList.dataEngine) return;
    const tableComp = pageTableList.dataEngine.state.getElement("table_<表格组件标识>");
    if (!tableComp) return;

    if (params.node_type == 2) {          // 法规节点 → 该法规下案由
        tableComp.params.regId = params.real_id;
        tableComp.params.issuerId = null;
    } else {                              // 机构节点 → 该机构下所有法规的案由
```

2. SQL 粘贴（**带 regId / issuerId 可选参数**，SQL 模板 `#if` 语法，未传参时默认全量）：

```sql
SELECT
    c.id, c.uid, c.code, c.name AS cause_name,
    r.name AS regulation_name,
    c.cause_type,
    CASE c.cause_type WHEN 1 THEN '罚则' WHEN 2 THEN '违则' END AS cause_type_name,
    c.status,
    CASE c.status WHEN 0 THEN '待审核' WHEN 1 THEN '已生效' WHEN 2 THEN '已驳回' END AS status_name,
    @DATE_FORMAT(c.create_time,'%Y-%m-%d %H:%i') AS create_time_fmt,
    c.create_human_name,
    c.regulation_id, c.regulation_code, c.region_id, c.region_code, c.description
FROM law_reg_cause c
LEFT JOIN law_reg_regulation r ON c.regulation_id = r.id AND r.delete_flag = 0
WHERE c.delete_flag = 0
  AND ( c.region_code IN ('${com.egova.lowcode.foundation.util.UserSessionUtils::getSessionVariable("<权限区域编码集会话变量ID>", true)}')
        OR c.region_code = '<中央区域code>' )
#if(regId != null && regId != '')
  AND c.regulation_id = '${regId}'
#end
#if(issuerId != null && issuerId != '')
  AND r.reg_issuer_id = ${issuerId}
#end
ORDER BY c.create_time DESC
```

### 6.2 搭审核弹窗页面

1. 新建一个普通 PC 页面 `案由审核弹窗`（记下页面 id 回填 6.1）。
2. 页面上放三个组件（标识改成好记的）：
   - **单选组件**，标识 `radio_result`，选项：`1-通过`、`2-驳回`，勾必填；
   - **多行文本**，标识 `textarea_opinion`，标题"审核意见"；
   - **按钮**，文本"确认"。
3. "确认"按钮绑定自定义脚本 = **UPDATE 案由状态 + INSERT 审核日志**（EXEC_FORMULA 两连；INSERT/UPDATE 公式的字段既可用列名也可用字段 id）：

```javascript
function main() {
    const self = this;
    const causeId = self.$route.query.causeId || self.params.causeId;      // 弹窗参数
    const beforeStatus = Number(self.params.beforeStatus || 0);
    const result = self.$$("radio_result").$$getValue();                    // 1通过 / 2驳回
    const opinion = self.$$("textarea_opinion").$$getValue() || '';
    if (!result) { self.$message.warning("请选择审核结果"); return; }
    const afterStatus = (result == 1) ? 1 : 2;   // 通过→1已生效；驳回→2已驳回

    const CAUSE_TBL = "<law_reg_cause实体id>";      // §0.1 抄的，如 t_xxxx
    const LOG_TBL   = "<law_reg_audit_log实体id>";

    // ① 更新案由状态
    const updateSql = "UPDATE('" + CAUSE_TBL + "',"
        + "['status'," + afterStatus + ",'update_time',NOW()],"
        + "QUERY_EQ('id','" + causeId + "'))";
    // ② 写审核日志（审核人/时间/意见/前后状态；只增不删）
    const insertSql = "INSERT('" + LOG_TBL + "',["
        + "'cause_id','" + causeId + "',"
        + "'audit_human_id'," + "DDCAT_CALL('<uid模型id>','','','result.uid')" + ","
        + "'audit_human_name',DDCAT_CALL('<姓名模型id>','','','result.name'),"
        + "'audit_username',USERNAME(),"
        + "'audit_result'," + result + ","
        + "'audit_opinion','" + opinion.replace(/'/g, "\\'") + "',"
        + "'audit_time',NOW(),"
        + "'before_status'," + beforeStatus + ","
        + "'after_status'," + afterStatus + "])";

    api.EXEC_FORMULA(updateSql).then(res1 => {
        if (res1.hasError) { self.$message.error("状态更新失败"); return; }
        return api.EXEC_FORMULA(insertSql).then(res2 => {
            if (res2.hasError) { self.$message.error("审核日志写入失败"); return; }
            self.$message.success(result == 1 ? "审核通过" : "已驳回");
            self.$$closeDialog && self.$$closeDialog();
        });
    }).catch(err => self.$message.error(err.message));
}
```

### 6.3 公式解释与备选

- `INSERT(表id, [列1,值1,列2,值2...])` 是文档标准公式（*INSERT (目标表id, [目标列1,目标值1,...])，目标表为实体表对应的id，字段取id或名称都可以*）；`UPDATE(表id, [列,值...], QUERY_EQ(...))` 同族；执行入口是 `api.EXEC_FORMULA("公式串")`。
- **before_status/after_status/审核人/时间/意见是评分点第 3 小点，一项都不能少**。
- 若环境不支持 `UPDATE(...)` 公式，备选：审核弹窗直接做成 **law_reg_cause 编辑表单**（只放审核结果/意见两个可见组件，status 用业务规则联动 `IF(EQ(审核结果,1),1,2)`），表单保存即更新状态；写日志放到表单"提交后执行公式/后置动作"里跑上面的 insertSql。
- 若 DDCAT_CALL 嵌在 INSERT 里不解析，就在脚本外层先 `api.EXEC_FORMULA("DDCAT_CALL(...)")` 取出 uid/姓名，再拼进字符串。

**✅ 本步验证**：找一条待审核案由 → 点审核 → 选"通过"填意见 → 确认 → 列表该行状态变"已生效"且审核按钮消失；再驳回一条变"已驳回"。到库里（或临时视图）查 law_reg_audit_log：新增记录的 audit_human_id 是 int 型 uid、before_status=0、after_status=1/2、意见和时间齐全。

## §8 打印预览（3分）

### 8.1 准备打印数据视图（主表 + 一对多子表）

打印模板的数据来源**必须是视图**（官方原文：*对于需要导出的子表的内容只能通过视图的方式作为打印模板的数据来源*）。

1. 数据管理 → 数据视图 → 新增 `v_print_regulation`（业务库，主表=法规）：

```sql
SELECT r.id, r.code AS regulation_code, r.name AS regulation_name,
       i.name AS issuer_name, r.region_code, r.description,
       @DATE_FORMAT(r.create_time,'%Y-%m-%d %H:%i') AS create_time_fmt,
       r.create_human_name
FROM law_reg_regulation r
LEFT JOIN law_reg_issuer i ON r.reg_issuer_id = i.id
WHERE r.delete_flag = 0
```

   【执行】→【保存】。
2. **给该视图加导航属性/关联视图**「案由明细」（视图编辑页的"导航属性/关联"配置区，以现场界面为准）：
   - 关联对象：`v_cause_list`（或单独建一个案由子视图）；
   - 关联关系：`本表.id = 子表.regulation_id`；
   - **关联类型必须选"一对多"**——官方原文：*子表的信息如果为多条的情况下，需要选择一对多，否则导出的时候只能显示第一条*。
   - 子视图里已把类型/状态翻译成文本（cause_type_name/status_name），打印直接用文本列（官方也是这么建议的：下拉/单选只存 code 时，通过关联视图处理文本字段值）。

### 8.2 设计打印模板

1. 入口：**应用设置 → 打印设计** → 点 **【新增模板】**。
2. 新增窗口逐项：
   - 数据集选择：`v_print_regulation`；
   - **模板类型选 word（或 excel）**——⚠️ office 预览只支持这两种，富文本模板只能走 pdfjs 预览，别选错；
   - 命名如 `法规案由打印模板` → 确定，进入模板设计器（word 在线编辑界面）。
3. **主表字段占位符**：版面上方排法规信息——把光标点到目标位置，然后**点击左侧字段列表中的字段，字段占位符将自动在文档中生成**（官方原文操作）。依次插入：法规编码 / 法规名称 / 颁发机构(issuer_name) / 创建人 / 创建时间。
4. **子表表格区**：版面下方插入一个**表格**，表头行写：案由编码｜案由名称｜案由类型｜案由状态｜创建人｜创建时间；数据行的每个单元格里，**从右侧子表字段列表（"案由明细"）里点选对应字段**插入占位符（官方原文：*对于添加子表的信息需要在右侧选择对应的字段信息，按照所需要的格式在对应子表中添加对应的填充字段即可*）。
5. ⚠️ **子表表格必须放在模板最后一行**——官方常见问题原文：子表不在最后行、下方有合并单元格时，会导致无法按子表数据数量扩行，导出报错。
6. 【保存】模板。
7. **抄模板 id**：*设计好后，在浏览器 URL 地址栏获取模板 id*（形如 `1bcea642-43d2-49ee-8587-ad0e83e04d33`），记为 `<模板id>`。

### 8.3 定义打印 API

1. 入口：**数据管理 → API 管理**。
2. 左侧 API 列表：先选/建一个分组 → 点分组后的 **…** → **【新增接口】** → 弹窗填：接口名称 `法规打印`、位置分组、**接口类型 POST** → 确定。
3. 选中该接口，右侧属性设置逐项填：
   - **接口地址**：可直接输入完整地址，**建议先配环境变量**（API 管理页顶部【环境变量】按钮 → 新增，值=内网 ip:端口）再在地址栏选环境变量 + 填相对路径：

     ```
     /unity/establish/printing_template/binding-data/document-url?printingTemplateId=<模板id>
     ```

     （有的版本前缀是 `/linglong-api/unity/printingTemplate/binding-data/document-url`，以环境为准；Query 还可带 `fileName=xxx` 指定生成文件名。）
   - **参数标签页 → Query 参数**：printingTemplateId 已写在地址里就不用重复；要参数化就【新增参数】填 `printingTemplateId`=`<模板id>` 并**勾选**（参数前的复选框勾上才生效）。
   - **参数标签页 → Body 参数**：右侧类型下拉选 **json**；内容传 SQL 过滤条件（过滤打印视图的主表），调试期先写死一条：

     ```json
     {"id":"1828675689310978048"}
     ```

     （运行期这个 Body 由 §8.4 脚本的 jsonParams 动态覆盖。）
   - **Headers 标签页**：点【新增】加一条：参数名 `use-web-Authorization`，参数值 `true`，**勾选生效**——作用是透传 token，**漏了必 401**。
4. 点 **【保存】**（官方明确：先保存才能生效）→ 点 **【发送】** 测试：响应里应返回渲染后文件的下载地址：
   - 过滤结果单条 → `http://IP:PORT/unity/establish/file/{文件id}/download?{token参数}`
   - 多条 → `http://IP:PORT/.../file/download-zip?id={文件id}...`
5. **抄 API id**：接口保存后其标识形如 `ds_api_xxxxxxxx`（接口配置页/URL 可见，以现场界面为准），记为 `<打印API的ds_api_id>`。
6. 内外网并存的环境，在 API **后置脚本**里替换下载地址域名（groovy）：

```groovy
def newJsonString = data.replaceAll("http://内网IP:端口","https://外网域名")
data = newJsonString
```

```javascript
    const self = this;
    const root = self.$$roots()[0];
    const node = root.currentTreeNode;
    if (!node || node.node_type != 2) {                    // 未选中法规节点
```

## §10 注意事项（常见坑汇总）

1. **跨数据源 JOIN**：sys_* 在用户中心库，law_* 在业务库，视图里 JOIN 不到——登录人区域/uid/姓名一律走公式或"数据模型+DDCAT_CALL"会话变量（§0.3）。
2. **USER_ID() ≠ sys_human.uid**：create_human_id / audit_human_id 要的是 int 型 uid，直接填 USER_ID()（varchar 主键）会存错甚至类型报错，必须走 `登录人uid` 会话变量。
3. **视图里调公式的转义**：`'${com.egova...runInSQL("公式")}'` 外层单引号+`${}`，公式内部双引号要 `\"` 转义；从网页复制公式先过一遍纯文本编辑器，别把 HTML 格式带进公式框。
4. **修改会话变量后**，引用它的列表过滤条件/视图要**重新选择/保存**一次才生效；不生效就删掉过滤条件重配。
5. **UNION 树 id 冲突**：机构 id 和法规 id 都是 bigint 会撞车，必须 CONCAT 前缀；UNION 各分支**列数、列序、类型必须一致**（数字列统一 CONCAT 成字符或都保持数字）。
6. **@DATE_FORMAT 的分钟是 `%i`** 不是 `%m`（%m 是月份）；国产库环境优先用 `@` 前缀自定义函数（@NOW()/@DATE_FORMAT/@CONCAT），且自定义函数名必须大写；自定义函数里嵌原生函数要用单引号包裹（或 @RAW('原生函数')）。
7. **文号规则**：规则要配"按日重置+4位补零"，否则跨天序号不归零、格式对不上 202606060001；用 GENERATE_SEQUENCE 时第5参是 applicationId，别漏。
8. **打印 API 忘加 Header `use-web-Authorization: true`** → 渲染接口 401/无权限；内外网环境还要在 API 后置脚本里 replaceAll 内网地址。
9. **打印子表只出一条** → 视图关联关系没选"一对多"；**导出报错扩不了行** → 子表表格没放模板最后一行（合并单元格挡住扩行）。
10. **预览路径版本差异**：`/linglong/design.html#/template/preview/{fileId}`（新）vs `/linglong/static/vue2/pc/third.html#/template/preview/{fileId}`（旧），word/excel 模板才能 office 预览；富文本模板只能走 pdfjs 预览。先手动验证再写进脚本。
11. **提示文案是采分点**："仅法规可新增案由！"、"请选择要打印的法规数据！"——标点（感叹号）都要一致。
12. **树 on-click 的 params 结构**先 console.log 确认（有的版本是 `params.node_type`，有的是 `params.node_type.value`），别盲写。
13. 新增案由后如果树上带计数，记得**同时刷新树面板**（`pageTreeEle.$$getRenderElement().$$refreshData()`）。
14. **视图先【执行】后【保存】**是官方标准动作；执行报错的 SQL 保存了也白搭，先在执行结果里把列名/数据对齐。
15. **API 参数勾选才生效**：Query/Body/Headers 每条参数前面有复选框，填了不勾=没配；改完随手点【保存】再【发送】测。
