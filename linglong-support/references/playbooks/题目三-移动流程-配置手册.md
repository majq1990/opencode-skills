## §1 新建流程表单

参考《移动流程表单搭建步骤》3.1、《PC工作台、地图交互、移动端流程相关配置》3.1。

### 1.1 操作步骤

1. 进入应用 → 左侧「**页面管理**」；
2. 点「**新建**」（或页面树上的 ＋ 号，以现场界面为准）→ 在弹出的页面类型选择里选择「**流程表单**」类型。
   - ⚠️ 这是本题第一个分叉路口：**必须选流程表单，不能选普通表单**。普通表单没有「配置流程」入口，后面 5 分的流程模板无处可配；
   - 若新建弹窗里类型很多（页面/表单/流程表单/移动页面…），认准带「流程」字样的表单类型（以现场界面为准）；
3. 页面名称输入：`违建问题上报表单`（名称自拟，全程保持一致即可）；
4. 点「确定/创建」→ 平台打开**表单设计器**（左侧控件栏 + 中间画布 + 右侧属性面板的三栏布局，以现场界面为准）。

### 1.2 关于文号（documentNo）字段

流程表单创建后会自动携带 documentNo（文号）等流程关联字段——这是流程引擎用来关联业务数据的内部字段（见《流程表单使用表单事件执行后公式》第 1 节）。

- **若表单画布上能看到文号字段**：选中它 → 右侧属性面板 → 打开「隐藏」开关（隐藏开关位置以现场界面为准），并确认它是自动生成、不需要人工填写；
- **若画布上根本不显示文号**：说明平台已把它作为纯内部字段处理，不用管；
- 原题原话：「若考试环境存在文号字段，文号字段应自动生成和隐藏，不作为人工编辑项」。

✅ **本步验证**：页面管理树里出现「违建问题上报表单」，双击/点击能进入表单设计器；页面类型显示为流程表单（或该页面有「配置流程/流程设计」入口——§3 要用）。

⚠️ **注意事项**：
- 建错成普通表单，趁早删掉重建，别硬救——字段照 §2 重敲十分钟够了；
- 文号是「隐藏」，案件号是「只读」，两者的处理方式不一样，别搞混（详见 §2.2 和 §9 坑 3）。

## §2 表单字段逐个配置（3 分中的 1 分 + 支撑后续全部）

在表单设计器中操作。通用手法：**从左侧控件栏找到目标控件 → 按住拖到中间画布 → 松手 → 点选该控件 → 在右侧属性面板逐项设置**（三栏布局以现场界面为准）。

7 个字段总表（做完逐行对照打勾）：

| # | 字段名称 | 控件类型 | 必填 | 关键配置 |
|---|----------|----------|------|----------|
| 1 | 案件号 | **流水号** | 否 | 自动生成；日期格式按**年月日**；**只读** |
| 2 | 信息来源 | 文本输入 | ✅是 | 打开「必填」开关 |
| 3 | 产权单位 | 文本输入 | ✅是 | 打开「必填」开关 |
| 4 | 联系人 | 文本输入 | ✅是 | 打开「必填」开关 |
| 5 | 使用单位 | 文本输入 | ✅是 | 打开「必填」开关 |
| 6 | 违建位置 | 文本输入 | ✅是 | 打开「必填」开关 |
| 7 | 创建时间 | 日期时间 | ✅是 | 默认值设为「当前时间」 |

### 2.1 字段 1：案件号（流水号控件）——本表单最讲究的一个字段

1. **拖控件**：左侧控件栏找「**流水号**」控件（可能归在“高级/系统”类控件分组下，找不到就用控件搜索框搜“流水号”，以现场界面为准）→ 拖入画布最上方；
   - ⚠️ 绝对不要用「文本输入」代替手填案件号——评分点原文是「案件号由系统自动生成且只读展示」，手填=0；
2. **改名称**：选中控件 → 右侧属性面板 → 「标题/字段名称」改为 `案件号`；
3. **配置编号规则**：属性面板里找「编号规则/流水号规则」配置项（通常是一个「设置规则」按钮或展开区，以现场界面为准），逐项设置：
   - **日期格式**：选 `yyyyMMdd`（即「年月日」——这是题目硬性要求「流水号格式按年月日生成」；下拉里若显示为「年月日」「yyyy-MM-dd」「yyyyMMdd」等多个选项，选不带分隔符或带分隔符的年月日均满足题意，认准包含**年+月+日**三段即可，别选成只有年月）；
   - **自增序号**：保留规则里的序号段；**序号位数**按默认即可（默认 4 位，效果如 `20260708-0001`；具体默认值以现场界面为准）；
   - **重置规则**：若界面提供「按日/按月/按年重置」选项，选**按日重置**最贴合「按年月日生成」的语义；没有该选项就不用管（以现场界面为准）；
4. **打开只读**：属性面板找到「只读」开关 → 打开（评分点原文「只读展示」）；
5. **不勾必填**：确认「必填」开关是**关闭**状态——流水号是提交时才生成的，勾了必填可能卡住提交（见 §9 坑 3）。

### 2.2 字段 2~6：五个文本输入（操作完全相同，逐个做完）

通用三步：拖「**文本输入**」（单行文本）控件 → 改标题 → 打开「**必填**」开关（打开后画布上字段标题旁出现红色 `*`，以此确认生效）。其余属性（占位提示、字数限制等）保持默认。逐个执行：

**字段 2：信息来源**
1. 左侧控件栏拖「文本输入」到画布，放在案件号下方；
2. 选中 → 右侧属性面板 → 标题改为 `信息来源`；
3. 打开「必填」开关 → 确认画布上出现红星。

**字段 3：产权单位**
1. 再拖一个「文本输入」，放在信息来源下方；
2. 标题改为 `产权单位`；
3. 打开「必填」开关。

**字段 4：联系人**
1. 再拖一个「文本输入」；
2. 标题改为 `联系人`；
3. 打开「必填」开关。

**字段 5：使用单位**
1. 再拖一个「文本输入」；
2. 标题改为 `使用单位`；
3. 打开「必填」开关。

**字段 6：违建位置**
1. 再拖一个「文本输入」；
2. 标题改为 `违建位置`；
3. 打开「必填」开关。

做完在画布上数一遍：**5 个文本输入、5 个红星**，名称与题目一字不差。

### 2.3 字段 7：创建时间（日期时间控件）

1. 左侧控件栏拖「**日期时间**」控件到画布（注意选**日期时间**而不是纯「日期」——题目控件类型写的是日期时间）；
2. 选中 → 属性面板 → 标题改为 `创建时间`；
3. 打开「**必填**」开关；
4. 属性面板找「**默认值**」→ 选「**当前时间**」（提交时自动填充，考试演示省一步手选）；
   - 若下拉里没有现成的「当前时间」选项，看是否支持公式默认值，填 `NOW()`；
   - 若两者都没有（以现场界面为准），就不设默认值——验证时手动选时间即可，字段本身必填就不丢分；
5. 显示格式选**日期＋时间**（如 `yyyy-MM-dd HH:mm:ss`，以现场界面为准）。

### 2.4 保存并自测

1. 点表单设计器右上角「**保存**」（部分平台还需「发布」，有发布按钮就一起点，以现场界面为准）；
2. **立即自测新增一条**：预览/运行该表单 → 只填 5 个必填文本 → 提交：
   - 案件号自动生成且**带今天的年月日**（如 `20260708xxxx`）→ 流水号规则 OK；
   - 案件号输入框呈灰色/不可编辑 → 只读 OK；
   - 留空任一文本字段提交会被拦截并标红 → 必填 OK；
   - 创建时间自动带出当前时间 → 默认值 OK。

✅ **本步验证**：7 个字段齐全、名称与题目一字不差；案件号自动生成＋年月日格式＋只读；5 个文本全部必填；创建时间必填＋默认当前时间；表单已保存。

⚠️ **注意事项**：
- 字段**名称必须照抄题目**：`信息来源` 不要写成 `问题来源`，`违建位置` 不要写成 `违建地址`——评分对表；
- 案件号规则里日期段必须含「日」，只选年月不满足「按年月日生成」；
- 这条自测数据是垃圾数据，§4 配完启动公式后再提交的才会进流程；如果平台支持删除记录，可顺手删掉（不删也不影响评分，只是列表里多一条无流程的数据）。

## §3 流程模板配置（5 分）

参考《PC工作台、地图交互、移动端流程相关配置》3.2、《移动流程表单搭建步骤》3.2。文档明确的配置清单是：**配置模板（流程设计画布）→ 配置每个节点关联的表单 → 配置每个节点可以操作的人员 → 配置参考节点 → 配置案件的认领方式 → 配置每个节点的操作菜单**。本章按这个顺序展开。

### 3.1 进入流程设计

1. 回到页面管理 → 找到「违建问题上报表单」→ 打开它的「**配置流程 / 流程设计**」入口（流程表单专属入口：可能在页面右键菜单、页面详情页按钮或表单设计器顶部，以现场界面为准）；
2. 进入后是**流程设计画布**：左侧/顶部有节点面板（开始、结束、业务节点等），中间是画布（以现场界面为准）。

### 3.2 画节点与连线

**目标结构：**

```
开始 ──► 处置 ──► 核查 ──► 核实 ──► 办结 ──► 结束
              ◄──退回──┘   ◄──退回──┘  ◄──退回──┘
（核查退回处置、核实退回核查、办结退回核实）
```

**拖节点：**

1. 画布上通常已有默认的「开始」节点（没有就从节点面板拖一个）；
2. 从节点面板拖 4 个**业务节点（人工/审批节点）**到画布，从左到右排开；
3. 逐个双击（或点选后在属性面板）把节点名称改为：`处置`、`核查`、`核实`、`办结`——**四个名字一字不差**，列表要展示「节点名称」，写错直接暴露在评分人眼前；
4. 拖一个「结束」节点放最右边。

**连正向线：**

5. 鼠标移到「开始」节点边缘出现连接锚点 → 按住拖到「处置」节点松手，生成连线（连线手法以现场界面为准）；
6. 依次连：处置→核查、核查→核实、核实→办结、办结→结束。共 5 根正向线。

**退回怎么处理（先看清再动手）：**

7. **优先方案**：退回用节点操作菜单里的「**回退**」动作实现（回退=回到上一节点），**不需要额外画反向连线**——这是灵珑移动端流程的标准做法（§3.6 配置）；
8. **备选方案**：仅当考试环境的流程设计器要求显式流向（点回退时提示无可用流向）时，才补画 核查→处置、核实→核查、办结→核实 三根反向线并把连线命名为「退回」（以现场界面为准）。先按方案 7 做，验证 §7 第 7 步时发现回退不了再回来补线。

画完先点一次「**保存**」。

### 3.3 每个节点的配置入口

点选（或双击）画布上的「处置」节点 → 弹出节点配置面板/抽屉，里面按 Tab 或分组分布着：关联表单、参与者（可操作人员）、认领方式、操作菜单、表单字段权限等配置项（Tab 名称与布局以现场界面为准）。**下面 3.4~3.7 的四件事，对处置/核查/核实/办结 4 个节点各做一遍。**

### 3.4 节点配置①：关联表单

1. 节点配置面板 → 找「**关联表单 / 节点表单**」配置项；
2. 下拉选择「**违建问题上报表单**」（即本流程表单自身）；
3. 4 个节点全部关联同一个表单。

### 3.5 节点配置②：参与者（节点可操作人员）

1. 节点配置面板 → 找「**参与者 / 可操作人员 / 受理人**」配置项；
2. 参与者类型选「**指定用户 / 具体人员**」（不是部门、不是岗位、不是动态参与者——本题不需要动态参与者公式）；
3. 点「添加/选择人员」→ 弹出组织机构人员选择器 → 用搜索框搜自己的账号名（如搜「处置员」）→ **勾选 XXX处置员01（XXX=自己姓名）** → 确定；
   - ⚠️ 考试租户里有很多考生的同名角色账号（张三处置员01、李四处置员01……），**必须选带自己姓名的那个**；
4. 四个节点对照表：

   | 节点 | 受理人账号（只选这一个人） |
   |------|--------------------------|
   | 处置 | XXX处置员01 |
   | 核查 | XXX核查员01 |
   | 核实 | XXX核实员01 |
   | 办结 | XXX管理员01 |

5. 每个节点配完，回看一眼面板上显示的人员名字再进下一个节点。

### 3.6 节点配置③：认领方式

1. 节点配置面板 → 找「**认领方式 / 收件方式**」配置项；
2. 本题每个节点只有 1 个受理人，不存在抢单，**保持默认（自动认领/直接分配）即可**（选项名以现场界面为准）；
3. 若默认是「手动认领」且改不掉：不算错，只是 §7 验证时每个节点办理前要先多点一次「认领/收件」（《移动流程表单搭建步骤》效果节的「点击收件」步骤），流程照样通。

### 3.7 节点配置④：操作菜单（本章最容易配错的地方）

《移动流程表单搭建步骤》原文：**内置流程审批按钮操作菜单，鼠标悬浮在操作项上时，点击「流程审批」新增此按钮**。移动端目前**只支持这 5 种菜单：办结、批转、退件、回退、认领**。

1. 节点配置面板 → 找「**操作菜单 / 按钮配置**」配置项；
2. 通过「新增按钮/流程审批」入口逐个添加动作按钮（悬浮出加号的交互以现场界面为准）；
3. 逐节点对照表配置：

   | 节点 | 操作菜单 | 说明 |
   |------|----------|------|
   | 处置 | **批转** | 批转流向→核查 |
   | 核查 | **批转**、**回退** | 批转→核实；回退→处置 |

4. ⚠️ 三条铁律：
   - 「退回上一节点」用「**回退**」，**绝对不要用「退件」**——文档原文：退件「相当于不处理，到办结栏」，会把案件直接甩进办结、破坏流程闭环；

### 3.8 节点配置⑤：表单字段权限（每节点 1 分的踩分句）

评分点原文（4 个节点每个都有）：**表单字段可见、可编辑，案件号除外**（办结节点写的是「表单字段可见」）。

## §4 启动流程公式（2 分，单点分值最高，务必最先打通）

要求：新增表单**提交成功后**自动创建流程实例并进入处置节点。

### 4.1 界面操作路径（参考《流程表单使用表单事件执行后公式》第 3 节，原文步骤）

1. 打开「违建问题上报表单」的表单设计器 → 点表单的「**高级**」；
2. 进入「**表单事件**」；
3. 点「**增加业务关联规则**」；
4. 在业务关联规则中选择「**执行后公式**」（即表单提交/保存成功后触发的公式）；
5. 在公式编辑框里写启动流程公式（4.2 节）→ 保存规则 → 保存表单。

（「高级」按钮的具体位置——设计器顶栏还是属性区——以现场界面为准，认准「高级 → 表单事件 → 业务关联规则 → 执行后公式」这条链。）

### 4.2 公式写法

标准公式（《PC工作台、地图交互、移动端流程相关配置》3.3.1 原文）：

```
FLOW_START(流程表单id, 文号)
```

含义：根据该流程表单的 ID，启动某文号对应某条数据的一个流程。

**本题的最简写法**（表单即流程表单本身）：

```
FLOW_START('<流程表单页面id>', 文号)
```

- 第 1 参 = **当前流程表单的页面 id**。获取方法：打开该表单的设计器，看浏览器地址栏 URL——形如 `.../page-build/page/1830568530480807936-2999-93be?...` 中 `page/` 后面那串就是页面 id（参考《移动端搭建实操》的 URL 结构）；或在页面管理里查看该页面的属性/复制页面 id（以现场界面为准）。**复制粘贴，不要手抄**；
- 第 2 参 = 当前记录的文号字段（documentNo）。在公式编辑器里通常可从字段列表点选插入「文号」变量（以现场界面为准）。

**备用完整写法**（仅当考试环境表单与业务实体分离、需要按业务主键反查时用；参考文档中的真实生产示例）：

```
FLOW_START('a77f469a-3151-47c9-bb50-2785c17b50e5',
  ENTITY_SELECT_ONE('t_4beacafcf80b4dee89519ea39f573b31','id',QUERY_EQ('identity_no',身份证号)))
```

参数说明（文档原文）：
- `a77f469a-...` 为**流程表单的页面 id**；
- `t_4beac...` 为实体表对应的标识 id；
- `id` 为实体表中的逻辑主键，用来与流程表单关联；
- `QUERY_EQ('identity_no',身份证号)` 相当于 SQL 的 `WHERE identity_no = 身份证号`。

本题照最简写法即可，替换成自己的页面 id。

> 顺带一提：文档 3.3 还有数据流转公式 `FLOW_BASE_ACTION_WITH_CONDITION(应用id,任务id,动作类型,动作意见,操作的节点和人员信息,条件)`（动作类型取 REDIRECT/RETURN/AGREE/FINISH 等）——本题**用不到**，批转/回退全走节点操作菜单，别画蛇添足。

### 4.3 自测（不通过绝不进 §5）

1. 用 **XXX处置员01** 登录（PC 端打开表单页即可，不必等移动页面）；
2. 新增一条数据：填 5 个必填文本 → 提交；
3. 去验证流程已启动（任一途径可证）：
   - 流程监控/流程实例管理里出现一条新实例，当前节点 = **处置**，受理人 = **XXX处置员01**（以现场界面为准）；
   - 或处置员01 的待办列表里出现这条案件。

**这条不通，后面 11 分的页面列表全是空的**。不通排查顺序：公式第 1 参是不是页面 id（不是应用 id、不是实体表 id）→ 规则是不是挂在「执行后公式」上 → 流程模板是否已发布 → 表单是否保存。

✅ **本步验证**：处置员01 提交一条新数据后，无需任何手工操作，流程实例自动创建且停在处置节点。

⚠️ **注意事项**：
- FLOW_START 配错位置（配成执行前/校验公式）不会在提交时报错，但流程不会启动——自测是唯一可靠的确认手段；
- 页面 id 那串很长，中间有 `-`，漏一段就是启动失败，务必复制。

## §5 移动端 5 tab 页面配置（11 分，大头）

### 5.1 建页面骨架（1 分）

1. 应用 → 页面管理 → 「新建」→ 选「**移动端页面**」类型（以现场界面为准）→ 命名 `违建问题办理` → 创建，进入**移动页面设计器**（画布是手机屏幕比例）；
2. 从左侧组件栏拖入「**标签页（Tab）**」组件到画布；
3. 选中标签页组件 → 右侧属性面板 → 找到 tab 项配置（一般是「标签项」列表，可增删、可改标题，以现场界面为准）：
   - 默认可能只有 2~3 个 tab，点「添加标签项」补到 **5 个**；
   - 逐个把标题改为：`处置`、`核查`、`核实`、`办结`、`查阅`——**顺序、名称照原题，别加多余 tab**；
4. 每个 tab 的面板容器内放一个**移动卡片列表**：
   - **首选**：直接复用 §3.9 里流程模板自动生成的移动卡片列表（文档原文「模板配置后会自动生成移动卡片列表，列表字段显示可根据需要进行拖拽显示」）——在组件/页面资源里找到它拖入 tab 容器，或在 tab 内拖入卡片列表组件后把数据源绑到流程待办数据（绑定入口以现场界面为准）；
   - 5 个 tab 各放一份（可复制组件后改过滤条件，比逐个重配快）。

### 5.2 各 tab 数据过滤

流程列表数据本质是「待办/已办/办结」视图（act_ru_task 关联 lcwf_process_record，字段有 taskId、processInstanceId、userId、createTime、**nodeName**、nodeId、recordId、documentNo 等——见《流程表单使用表单事件执行后公式》视图示例），按**当前节点名称**过滤：

| tab | 数据范围 | 过滤条件 |
|-----|----------|----------|
| 处置 | 处置节点待办 | 节点名称(nodeName) = `处置` |
| 核查 | 核查节点待办 | nodeName = `核查` |
| 核实 | 核实节点待办 | nodeName = `核实` |
| 办结 | 办结节点待办 | nodeName = `办结` |
| 查阅 | **已办结**数据 | 流程状态 = 已办结/已结束（办结数据视图，**不按节点过滤**） |

**操作**（以处置 tab 为例）：

1. 选中处置 tab 内的卡片列表组件 → 属性面板找「**数据 / 查询条件 / 过滤条件**」配置（以现场界面为准）；
2. 添加一条过滤：字段选「节点名称（nodeName）」→ 运算符「等于」→ 值填 `处置`；
3. 核查/核实/办结三个 tab 同法，值分别为 `核查`、`核实`、`办结`；
4. 查阅 tab：数据来源切换为**已办结数据**——若平台的流程卡片列表提供「待办/已办/办结」数据范围选项，直接选「办结」；若走自建视图，参照文档待办视图 SQL 把主表换成已办结实例（以现场界面为准）；
5. 各 tab 数据随流转自动进出（数据在哪个节点，就出现在哪个 tab；批转后从原 tab 移出）——这由过滤条件天然保证，**不需要额外配置**。

⚠️ 过滤值必须与流程模板节点名**一字不差**；查阅 tab **不是** `nodeName=查阅`（流程里根本没有查阅节点）。

### 5.3 列表卡片字段（处置/核查/核实/办结 四个 tab 一致）

每张卡片显示 4 个字段 + 1 个按钮：

| 显示项 | 绑定字段 |
|--------|----------|
| 案件号 | 案件号（流水号字段） |
| 节点名称 | nodeName（流程当前节点） |
| 处理人 | 当前节点处理人（userId/处理人名称字段） |
| 创建时间 | 数据创建时间 |
| 操作按钮 | 按钮文字改为「**办理**」 |

**操作——处置 tab（第一份，仔细做）：**

1. 选中处置 tab 内的卡片列表 → 进入卡片内容编辑（点卡片进入编辑态，或在大纲树中展开卡片节点，以现场界面为准）；
2. **拖拽调整显示字段**（文档原文能力「列表字段显示可根据需要进行拖拽显示」）：把 案件号、节点名称、处理人、创建时间 四个字段拖到卡片显示区；卡片模板自带的多余字段（如 documentNo、recordName 等）删掉；
3. 字段标签确认显示清楚（案件号：xxx / 节点名称：处置 / 处理人：XXX处置员01 / 创建时间：…）；
4. **办理按钮**：卡片上添加/保留一个操作按钮 → 选中它 → 属性面板把按钮**文字改为 `办理`**；
5. 按钮点击动作：属性面板 →「点击动作」→ 选「**打开页面**」→ 目标页面选 §6 要建的「移动办理页面」→ 配置**传参**：`recordId`（案件ID）＋ `taskId`（任务ID）——即待办详情 boxType=1 所需参数（传参配置方式同《移动端列表点击打开详情》：在卡片/按钮属性里配置打开页面及传参；参数值从列表当前行数据里选 recordId/taskId 字段，以现场界面为准）；
   - §6 还没建时可先留空，建完回来补选目标页面——建议顺序：先把 §6 页面建出空壳，再回来绑。

**操作——核查 tab（复制后改两处）：**

1. 大纲树选中处置 tab 的卡片列表 → 复制 → 粘贴到核查 tab 容器内（复制入口以现场界面为准；不支持复制就照处置 tab 步骤重配一遍）；
2. 改过滤条件：nodeName 等于 `核查`（§5.2）；
3. 检查卡片 4 字段＋「办理」按钮＋传参（recordId＋taskId）原样保留。

**操作——核实 tab：**

1. 同法复制一份到核实 tab 容器；
2. 改过滤条件：nodeName 等于 `核实`；
3. 检查字段/按钮/传参。

**操作——办结 tab：**

1. 同法复制一份到办结 tab 容器；
2. 改过滤条件：nodeName 等于 `办结`；
3. 检查字段/按钮/传参。

四个 tab 做完，把每个 tab 的过滤值再从头到尾核对一遍（复制流的经典事故就是四个 tab 全是 `处置`）。

### 5.4 查阅 tab（字段不同，专门做）

| 显示项 | 绑定字段 |
|--------|----------|
| 案件号 | 案件号 |
| 创建人 | 数据创建人 |
| 创建时间 | 创建时间 |
| 结束时间 | 流程结束时间 |

1. 卡片字段拖拽为上表 4 个字段——注意和前四个 tab **不一样**：没有节点名称/处理人，多了创建人/结束时间；
2. **不放任何办理按钮**（原题明确「查阅 tab 不应提供继续办理按钮」，放了倒扣印象分）——卡片上如果复制过来有「办理」按钮，删掉；
3. 打开详情用**卡片点击动作**（《移动端列表点击打开详情》原文操作）：**在移动卡片列表，大纲树选中卡片 → 点属性 → 配置「卡片点击动作」→ 配置打开页面及传参**；

### 5.5 悬浮新增按钮（仅处置 tab 显示）

## §9 注意事项与常见坑（12 条）

1. **公式没配 = 直接丢 2 分且全流程瘫痪**：FLOW_START 必须配在「表单高级 → 表单事件 → 业务关联规则 → 执行后公式」，且第 1 参是**流程表单页面 id**（不是应用 id、不是实体表 id）。搭页面前先自测提交能进处置节点（§4.3）。
2. **退回后再次批转**：核查退回处置后，处置员01 必须还能编辑并再次批转（评分点原文）。若退回后处置 tab 看不到数据，检查处置 tab 过滤条件是否只认「新增来源」——正确做法是按 `nodeName=处置` 过滤，与来源无关。
3. **案件号权限**：案件号是「只读展示」不是「隐藏」；文号（documentNo）才是隐藏。两者搞反扣分。案件号别勾必填（流水号提交时才生成，勾必填可能卡提交）。
4. **悬浮按钮位置**：必须放在处置 tab 容器内部；放页面全局层会 5 个 tab 都显示，直接违反「悬浮按钮仅在处置 tab 下展示」评分句。
5. **tab 过滤条件写错**：节点名称过滤值必须与流程模板里节点名一字不差（`处置` ≠ `处置节点`）。查阅 tab 是按**办结状态**过滤，不是 `nodeName=查阅`（流程里没有查阅节点）。复制卡片列表后逐个 tab 检查过滤值是否已改。
6. **操作菜单选错**：移动端只支持 办结/批转/退件/回退/认领 五种；「退回上一节点」用**回退**，别用**退件**（退件=不处理直接进办结栏）。「办结」只配给办结节点。
7. **先保存再批转**：办理时直接点批转可能丢表单修改，标准动作是「填写表单信息，先保存，再批转」（参考文档原文顺序），演示时也照这个顺序。
8. **受理人绑错账号**：节点参与者要指定到具体用户（XXX 带自己姓名的 01 账号），别在人员选择器里勾到同名的别人；每个节点配完顺手核对一遍面板上显示的名字。
9. **办理/查阅传参**：办理入口 boxType=1 传 recordId＋taskId；查阅入口 boxType=4 传 recordId＋**instanceId**。查阅传成 taskId 会打不开（办结后任务已不存在）。
10. **列表不刷新误判失败**：批转后列表没变先手动下拉刷新再判断，不要急着改配置；自动刷新脚本（refresh=1 ＋ onRefresh，§5.5 第 5 步）属加分体验，非评分点。
11. **建错表单类型**：必须是**流程表单**，普通表单无法配流程模板；发现建错尽早重建，字段配置照 §2 十分钟能重敲。同理，§6 要用「移动办理页面」专用类型，别拿普通移动页面凑。
12. **验证顺序**：退回演示完必须批转回来继续往下走，最终要有一条数据真正办结进查阅 tab，否则查阅 tab 的 2 分没有数据支撑。全程边验证边截图。
