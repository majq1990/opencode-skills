# 试题背景说明

现有设备巡检管理系统，涉及设备巡检任务、巡检标签等业务数据，相关数据分布在业务库的设备巡检任务表（`iot_inspection_task`）以及巡检任务标签明细表（`iot_inspection_task_tag`）中。

请基于上述数据表，在灵珑平台中完成设备巡检标签列表页面配置，实现：
1. 以列表形式展示设备巡检任务数据，列表主体数据来源于设备巡检任务表，支持按固定查询条件筛选数据；
2. 避免在主列表数据模型 SQL 中直接对巡检任务表和巡检任务标签明细表进行大表联查，要求通过 API 后置脚本根据主表  `task_id`  查询子表标签数据；
3. 支持将同一巡检任务下的多个标签名称、标签类型、标签分组、标签说明等信息拼接后展示在主表列表中；
4. 支持按计划开始时间、巡检任务编号、巡检任务状态进行普通列表过滤，其中计划开始时间为必填介于过滤；
5. 支持高级检索功能，可按标签名称、标签类型、标签说明、标签分组对巡检任务进行查询。最终效果包括：

[页面管理.mp4](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/1wvqrebwpN1YQnak/att/c77f7946-f8b9-4337-bfcd-91299ef02dad.mp4)

● 设备巡检任务列表能够正确展示主表中的巡检任务编号、设备名称、设备类型、点位名称、所属区域、巡检任务状态、计划开始时间等字段；

● 列表过滤条件固定为计划开始时间介于、巡检任务编号包含、巡检任务状态等于，且过滤条件能够正常生效；

● API 后置脚本能够通过巡检任务  `task_id`  批量查询巡检任务标签明细表，并将多个标签信息拼接回列表展示；

● 后置脚本查询子表时需过滤已删除标签数据，确保  `delete_flag = 0`  的标签才参与展示；

● 高级检索中，标签名称、标签类型、标签说明支持模糊查询，标签分组支持精准匹配；

● 页面最终能够在不直接大表联查的情况下，正常展示巡检任务及其扩展标签信息。

# 一、表设计

## 设备巡检任务表（iot_inspection_task）

说明：设备巡检任务表为本题主表，用于存储设备巡检任务的基础信息。页面列表以该表为主进行查询展示，避免在主列表 SQL 中直接与子表做大表联查。

| 字段名 | 数据类型 | 是否非空 | 默认值 | 字段注释 | 关联说明 |
|---------|------------|------------|---------|------------|------------|
| task_id | bigint | NOT NULL | AUTO_INCREMENT | 巡检任务标识（主键） | 被 `iot_inspection_task_tag.task_id` 关联 |
| task_code | varchar(60) | NOT NULL | — | 巡检任务编号 | 列表固定模糊查询字段 |
| device_code | varchar(80) | DEFAULT NULL | NULL | 设备编号 | 列表展示字段 |
| device_name | varchar(200) | DEFAULT NULL | NULL | 设备名称 | 列表展示字段 |
| device_type_name | varchar(100) | DEFAULT NULL | NULL | 设备类型名称 | 列表展示字段 |
| site_name | varchar(200) | DEFAULT NULL | NULL | 点位名称 | 列表展示字段 |
| area_name | varchar(100) | DEFAULT NULL | NULL | 所属区域 | 列表展示字段 |
| inspect_org_name | varchar(200) | DEFAULT NULL | NULL | 巡检单位名称 | 列表展示字段 |
| inspector_name | varchar(100) | DEFAULT NULL | NULL | 巡检人员姓名 | 列表展示字段 |
| task_status_name | varchar(40) | DEFAULT NULL | NULL | 巡检任务状态 | 列表固定精准查询字段 |
| risk_level_name | varchar(40) | DEFAULT NULL | NULL | 风险等级名称 | 列表展示字段 |
| plan_start_time | datetime | DEFAULT NULL | NULL | 计划开始时间 | 列表固定必填时间介于过滤字段 |
| plan_end_time | datetime | DEFAULT NULL | NULL | 计划结束时间 | 列表展示字段 |
| finish_time | datetime | DEFAULT NULL | NULL | 实际完成时间 | 列表展示字段 |
| task_desc | varchar(1000) | DEFAULT NULL | NULL | 巡检任务说明 | 列表展示字段 |
| inspect_result | varchar(1000) | DEFAULT NULL | NULL | 巡检结果 | 列表展示字段 |

## 巡检任务标签明细表（iot_inspection_task_tag）

说明：巡检任务标签明细表为本题子表，用于存储巡检任务关联的标签信息。一个巡检任务可以对应多条标签明细数据，列表需要通过主表 `task_id` 查询该子表，并将多条标签信息拼接回主表列表展示。

| 字段名 | 数据类型 | 是否非空 | 默认值 | 字段注释 | 关联说明 |
|---------|------------|------------|---------|------------|------------|
| tag_record_id | bigint | NOT NULL | AUTO_INCREMENT | 标签记录标识（主键） | — |
| task_id | bigint | NOT NULL | — | 巡检任务标识 | 关联 `iot_inspection_task.task_id` |
| tag_name | varchar(200) | NOT NULL | — | 标签名称 | 高级检索固定模糊查询字段 |
| tag_type_name | varchar(200) | DEFAULT NULL | NULL | 标签类型名称 | 高级检索固定模糊查询字段 |
| tag_group_name | varchar(200) | DEFAULT NULL | NULL | 标签分组名称 | 高级检索固定精准查询字段 |
| tag_desc | varchar(1000) | DEFAULT NULL | NULL | 标签说明 | 高级检索固定模糊查询字段 |
| relation_source | varchar(40) | DEFAULT NULL | NULL | 标签来源 | 列表展示或后置脚本拼接字段 |
| create_time | datetime | DEFAULT NULL | NULL | 创建时间 | — |
| delete_flag | int | NOT NULL | 0 | 删除标记：0-正常，1-删除 | 后置脚本查询时需过滤正常数据 |

# 二、关联关系

**巡检任务与巡检任务标签明细**
- `iot_inspection_task.task_id` ← `iot_inspection_task_tag.task_id`：巡检任务标签明细表通过巡检任务标识关联设备巡检任务表。
- 一条巡检任务可以对应多条标签明细数据，即一个任务可以有多个标签。
- 巡检任务标签明细表中 `delete_flag = 1` 的数据为已删除数据，后置脚本或高级检索查询时需过滤。

# 三、功能说明-设备巡检标签列表（16分）

### 3.1 页面布局

页面采用**列表 + 查询条件**布局：
- **上方**：普通查询条件区域，仅允许配置题目指定的固定过滤条件。
- **中间**：设备巡检标签列表，展示巡检任务基础信息和 API 后置脚本扩展出的标签字段。
- **高级检索**：提供标签名称、标签类型、标签说明、标签分组等标签维度的组合查询能力。

#### 3.2.2 固定查询条件配置（1分）

除高级检索字段外，普通列表查询条件必须固定为以下 3 个，不允许替换为其他字段：

| 查询条件 | 参数名 | 查询方式 | 对应字段 | 是否必填 | 分值要求 |

| 计划开始时间结束 | `plan_start_time_end` | 介于结束值 | `iot_inspection_task.plan_start_time` | 必填 | 时间条件的一部分 |
| 巡检任务编号 | `task_code` | 包含 / 模糊匹配 | `iot_inspection_task.task_code` | 非必填 | 包含查询字段 |
| 巡检任务状态 | `task_status_name` | 等于 / 精准匹配 | `iot_inspection_task.task_status_name` | 非必填 | 等于查询字段 |

> 说明：普通列表过滤条件只允许配置"计划开始时间介于、巡检任务编号包含、巡检任务状态等于"。例如设备名称、设备类型、所属区域、风险等级等字段只能展示，不作为本题普通列表过滤条件。

#### 3.2.3 时间条件配置（1分）

时间字段需配置为**必填项**，用于列表查询中的介于过滤。
- 固定按计划开始时间 `plan_start_time` 过滤。
- 灵珑数据模型时间介于查询参数必须命名为：`plan_start_time_start`、`plan_start_time_end`，这样才能直接使用这样才能被灵珑自动接收`plan_start_time`字段的介于条件。
- 需要在数据模型增加判断#if #else判空，不选时间则不会展示数据。
- `plan_start_time_start` 与 `plan_start_time_end` 均为必填。
- `task_code`、`task_status_name` 为非必填。

# 四、功能说明-高级检索（4分）

### 4.1 高级检索入口

在设备巡检标签列表页面提供高级检索入口，用户可按标签维度查询巡检任务数据。

### 4.2 高级检索字段

高级检索字段必须固定为以下 4 个，不允许替换为其他字段（时间字段必填不展示即可）：

| 字段名称 | 参数名 | 查询方式 | 来源 | 分值 |
|------------|---------|------------|------|------|
| 标签名称 | `tag_name` | 模糊查询 | `iot_inspection_task_tag.tag_name` | 1分 |
| 标签类型 | `tag_type_name` | 模糊查询 | `iot_inspection_task_tag.tag_type_name` | 1分 |
| 标签说明 | `tag_desc` | 模糊查询 | `iot_inspection_task_tag.tag_desc` | 1分 |
| 标签分组 | `tag_group_name` | 精准匹配 | `iot_inspection_task_tag.tag_group_name` | 1分 |
| 时间字段 | `plan_start_time` | 日期选择组件 | `iot_inspection_task.plan_start_time` | 必填，作为时间过滤条件，隐藏 |

### 4.3 查询逻辑
- 数据模型和api配置需要增加上诉四个查询条件，使用exists来配置过滤条件，不允许连表。
- 标签名称、标签类型、标签说明需使用模糊查询，支持按关键字匹配。
- 标签分组需使用精准匹配，仅返回与所选分组完全一致的数据。
- 高级检索需要基于 `iot_inspection_task_tag` 子表过滤，并过滤 `iot_inspection_task_tag.delete_flag = 0`。
- 当未输入高级检索条件时，列表按普通查询条件返回数据。

# 五、约束说明
1. 主表为 `iot_inspection_task`，子表为 `iot_inspection_task_tag`。
2. 列表主体数据必须来源于主表，并通过主表 `task_id` 查询子表，将标签数据拼接回主表列表展示。
3. 本题重点考察：避免主表和子表两个大表在主列表 SQL 中直接联查，改为通过 API 后置脚本查询子表并扩展字段。
4. 数据模型 SQL 必须能够正常执行并返回列表字段，不要求查询出全部字段，但必须满足展示和查询要求。
5. 普通列表过滤条件限制死为：`plan_start_time_start`、`plan_start_time_end`、`task_code`、`task_status_name`。
6. `plan_start_time_start` 与 `plan_start_time_end` 为必填过滤条件，参数命名需符合灵珑平台时间介于查询规范。
7. `task_code` 使用包含查询，`task_status_name` 使用等于查询，二者均为非必填。
8. API配置需保证授权、地址、参数和响应字段均正确。
9. 列表必须能够正常展示接口返回数据，并验证固定过滤条件正常生效。
10. API后置脚本需通过灵珑数据源名称全局变量获取数据库名称，不允许写死数据库名称。
11. API后置脚本需能够为巡检任务数据扩展标签字段，并在列表中正常展示。
12. 后置脚本及高级检索查询子表时，需过滤 `iot_inspection_task_tag.delete_flag = 0`。
13. 高级检索字段限制死为：`tag_name`、`tag_type_name`、`tag_desc`、`tag_group_name`。
14. 高级检索中，标签名称、标签类型、标签说明使用模糊查询，标签分组使用精准匹配。
