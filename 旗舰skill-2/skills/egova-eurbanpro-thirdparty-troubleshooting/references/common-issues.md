# 常见问题速查

## 404 / 地址不通
- 先做默认前置核查：
  1. 确认第三方调的是现场真实地址，不是文档示例地址。
  2. 路径中不要误带 `v22-api/`。
  3. 确认政务外网与源 IP 防火墙策略已开通。
- 最小动作：让第三方回传实际请求 URL，再对照真实接口路径逐段比对。

## 认证错误
- 先核标准链路：公钥 -> 加密 `client_secret` -> token -> 业务接口。
- 业务接口 token 可放：
  - Header：`X-EGOVA-Authorization: Bearer <token>`
  - Query：`egova_openapi_token=<token>`
- 若仍失败，再查是否还需要第三方自己的签名头或网关签名。

## 参数错误
- 高发原因：必填字段缺失、字段名拼错、大小写错误、类型错误。
- 常见笔误：把大写 `I` 写成小写 `l`。
- 若用户已给 `action + JSON`，转入定向诊断模板，不要继续泛化排障。

## 多媒体下载失败
- 先在我方服务器执行：
```bash
curl -I <多媒体URL>
```
- 若网络不通，先开网络策略；网络短期内打不通时，再考虑改为 base64 方式。
- 若 URL 可达，再回查第三方附件地址是否允许我方直接访问。

## base64 上传后文件不显示
- base64 内容应放在 `medias.content`，不要塞进 `mediaPath`。
- `mediaName` 使用英文文件名 + 扩展名。
- 检查入参是否带中文或其他不规范值。

## token 接口报错 / 代理用户认证失败
- 先查对接代理人字段是否有脏字符。
- 确认配置的是登录账号，不是人员名称。
- 确认 `client_id`、`client_secret`、服务名与现场配置一致。
- 配完后执行 `/unity/openapi/config/clear-sys-config`。

## 多媒体地址过长
- 常见原因：把 base64 内容误放进 `mediaPath`。
- 正确做法：URL 放 `mediaPath`，base64 放 `medias.content`。

## 未找到合适处理人 / 无法流转
- 优先检查 `district_id` 等现场流程依赖字段。
- 再检查代理人岗位权限。
- 再检查流程配置、参与者限制与采集配置。

## 登记栏受理员看不到第三方对接案件
- 先确认登记栏视图逻辑是否按“自己的岗位”过滤。
- 再确认对接代理人、受理岗位与案件当前阶段是否匹配。
