# 灵珑需求交付工作流（需求 → 完整实施方案报告）

> 用途：接到一个真实业务需求（不是考题）时，从需求采集到输出完整可实施的灵珑配置方案报告的标准流程。
> 触发形态：用户给「一段需求描述」/「Redmine 案件号或链接」/「设计文档链接（钉钉 alidocs 等）」，或三者组合。

---

## 总流程

```
① 需求采集（Redmine 案件 + 设计文档 + 口头补充）
        ↓
② 需求拆解（功能点清单 → 逐项映射灵珑能力）
        ↓
③ 历史避坑检索（可选：redmine-knowledge / 知识库）
        ↓
④ 方案生成（数据设计 → 页面设计 → 交互脚本 → 流程 → 权限）
        ↓
⑤ 报告输出（按模板成文，存日期目录，可推钉钉文档）
```

缺输入不猜：需求描述、设计文档、数据表结构三者缺关键项时，先列出「待确认清单」问用户，不要空想编造表结构。

---

## ① 需求采集

### 1.1 Redmine 案件读取

用 `redmine` MCP（runekaagaard/mcp-redmine）：

```
# 读案件正文 + 附件清单 + 处理过程（journals 含历次沟通，经常藏着真实需求）
mcp__redmine__redmine_request
  path: /issues/{案件号}.json
  params: {"include": "attachments,journals,relations,children"}

# 关联案件/父子案件同样读一遍（relations/children 里的 id）

# 下载附件（设计文档常以 docx/pdf/xlsx 附件挂在案件上）
mcp__redmine__redmine_download
  attachment_id: <附件id>
  save_path: <scratchpad 或 D:\opencode\file\yyyy-mm-dd\attachments\文件名>
```

- 用户给的是 Redmine URL 时，从 URL 提取案件号（`/issues/123456`）。
- 搜索案件：`/issues.json` + params `{"subject": "~关键词", "project_id": ..., "status_id": "*"}`；
  接口字段拿不准时先 `mcp__redmine__redmine_paths_info(["/issues.json"])` 查规格。
- journals 里的需求变更要按时间取**最新口径**，与正文冲突时在报告「需求理解」里显式标注。

### 1.2 设计文档读取

| 文档形态 | 读取方式 |
|---|---|
| 钉钉在线文档（alidocs 链接） | `mcp__dingtalk__get_document_content` 传 URL 或 nodeId（**勿用 dingtalk-wiki read_document，403**） |
| 钉钉文档内嵌附件 | `mcp__dingtalk__download_doc_attachment` |
| 钉钉表格（axls）/AI表格（able） | 先 `get_document_info` 看 extension，再走对应表格 MCP |
| Redmine 附件 docx | 下载后用 `anthropic-skills:docx` skill 解析（含表格/修订） |
| Redmine 附件 pdf | 下载后用 `pdf` 相关 skill 或 Read 直读 |
| 图片/原型截图 | Read 直接看图，拆分视觉区块 |

- 设计文档里的**数据字典/表结构**是方案的地基，逐表逐字段抄进报告，不省略。
- 有效果图时按「悟空大屏 skill」同款做法：先做视觉拆分（区块→组件），再逐块映射灵珑组件。

### 1.3 口径确认

采集完先输出一份**需求理解摘要**（10 行以内）+ **待确认清单**给用户核对，确认后再进方案。急件可跳过，但报告里要标「以下假设待确认」。

---

## ② 需求拆解

把需求切成功能点清单，每个功能点标注五要素：

| # | 功能点 | 类型 | 涉及数据 | 灵珑能力映射（guide 文档） | 复杂度 |
|---|---|---|---|---|---|
| 1 | 例：案件列表按区域过滤 | 列表 | mis_case + tc_region | `guide/列表查询基于Hook查询.txt` | 低 |
| 2 | 例：领导看板 3 指标 | 看板 | 统计 ddcat | `guide/领导看板主页数据对接说明文档.txt` | 中 |

类型枚举：列表 / 表单 / 详情 / 树 / 看板图表 / 地图 / 流程 / 打印 / 移动端 / 权限 / 对接API / 性能。
映射时先读 `guide/_索引.md` 定位文档，找不到再查 `知识库索引.md` 用 MCP 拉原文，仍没有 → 报告风险章节记「无既有方案，需现场验证」。

---

## ③ 历史避坑检索（可选但推荐）

- 有 `redmine-knowledge` agent 时：用 Agent 工具（subagent_type=redmine-knowledge）跑
  「precheck：<需求一句话>」拿历史高频踩坑模式 + 相似案件链接，写进报告「风险与历史教训」。
- 涉及第三方对接时必跑（对接类历史坑最多）。
- 无该 agent 时跳过，用 playbooks/guide 里的常见坑章节兜底。

---

## ④ 方案生成规则

按顺序产出，每层都要**完整可实施**（能直接照做，不是方向性描述）：

1. **数据设计**：业务实体注册清单（哪些表）、数据视图/ddcat 逐个给出**完整 SQL**
   （灵珑 SQL 模板语法：`#tag where()` / `#if` 判空 / `${var}`；入参表：名称/类型/必填/映射字段）。
   主子大表禁止直接联查 → API 后置脚本方案（参考 `playbooks/题目五`）。
2. **页面设计**：页面清单（PC/移动端）、每页布局区块图（文字版）、组件清单表
   （组件类型/数据来源/关键属性），复杂交互标注联动关系。
3. **交互与脚本**：每段 JS 完整给出（遵守 `scripting/` 核心约束：self=this、$$m 取隐藏组件、
   catch 必写、loading 管理；新环境用 DATA_EXECUTOR，旧环境 DATA_SOURCE_EXECUTE，报告里注明按环境实测）。
4. **公式与流程**：表单默认值公式（UUID()/NOW()/会话变量）、执行后公式（FLOW_START 等）、
   流程模板节点/参与者/操作菜单表。
5. **权限与变量**：会话变量/静态变量清单（用途/建法）、区域/角色权限隔离方案。
6. **打印/导出**：模板设计要点 + 打印 API 配置（Header `use-web-Authorization: true` 等）。
7. **验收清单**：按功能点逐条「操作 → 预期结果」，可直接当测试用例。

---

## ⑤ 报告输出

- **存放**：`D:\opencode\file\yyyy-mm-dd\灵珑实施方案-<需求名>.md`（附件下载到同目录 attachments/）。
- 用户要求推钉钉时：用 `mcp__dingtalk__create_document` / dws 写入指定知识库。
- **禁引未定稿标准**（全局硬规则）：报告中不得引用 GB/T 草案/送审稿等。

### 报告模板

```markdown
# <需求名> 灵珑实施方案
> 来源：Redmine #xxxx / 设计文档 <链接>；编制日期：yyyy-mm-dd；状态：待评审

## 1. 需求理解
1.1 背景与目标（3-5 句）
1.2 功能点清单（②的表格）
1.3 假设与待确认项

## 2. 数据设计
2.1 数据源与实体注册清单
2.2 表结构（从设计文档/案件抄录，逐表）
2.3 数据视图 / DDCAT（逐个：用途、完整 SQL、入参表、出参表、分页）
2.4 API 与后置脚本（如涉及）

## 3. 页面设计
3.1 页面清单与导航结构
3.2 逐页：布局区块 + 组件清单表 + 数据绑定
3.3 移动端页面（如涉及）

## 4. 交互与脚本
逐功能点：触发点 → 完整 JS/公式代码 → 绑定位置

## 5. 流程配置（如涉及）
流程图 + 节点配置表（受理人/操作菜单/字段权限）

## 6. 权限与全局变量
会话/静态变量清单 + 权限隔离方案

## 7. 打印与导出（如涉及）

## 8. 实施步骤与工作量
按依赖排序的操作步骤（引用 playbooks 同类步骤）+ 人天估算

## 9. 验收清单
| # | 操作 | 预期结果 |

## 10. 风险与历史教训
常见坑（guide/playbooks 提炼）+ redmine-knowledge 检索结果 + 无既有方案项

## 附录
引用文档清单（guide 文件名 / 知识库 nodeId / Redmine 案件号）
```

### 质量门（交报告前自查）

- [ ] 每个 SQL/脚本都完整可复制，没有"此处略"
- [ ] 表结构与设计文档一字不差，没有编造字段
- [ ] 每个功能点在报告里能找到对应实现章节
- [ ] 待确认项/假设显式列出
- [ ] 附录引用可追溯（文件名/nodeId/案件号）
```
