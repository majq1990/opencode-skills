# 悟空导出包结构 + 页面写契约（实证）

> 来源：在探索账号上对「【模版】空弹窗」做真实 `batch-export` 并解包分析（2026-05-29）。
> 这是「包补丁」落地路径的核心情报，也是「增量写」路径的关系契约来源。
> 本文件只含结构/字段名，**不含任何 token**，可随 skill 入库。

## 1. 只读导出通道（云端已验证）

整套导出无需服务器 SSH，纯接口即可，且对租户库零写入（只生成临时 zip）：

1. `POST /wukong-backend/unity/page/batch-export`，body `{"ids":["<pageId>", ...]}`
   - 返回 `{"hasError":false,"result":{"relativePath":"/files/tmp/page_<hash>.zip"}}`
   - 单个 id → `page_<hash>.zip`；多个 id → `pages_<hash>.zip`
2. `GET /wukong-backend<relativePath>` 带 `Authorization: Bearer <token>` → 下载 zip（`application/zip`）
3. 鉴权同读：仅需 `Authorization: Bearer <token>`，签名不强制。

> 项目级整包导出走 UI 导出按钮或备份机制（`file/tmp`、`backup/project/{date}/`），云端无 SSH 时优先用上面的页面级 `batch-export`。

## 2. zip 包目录结构（自包含）

```
zip 根/
├── pageJson/
│   └── {页面名}_{pageId}.json        # 页面主体配置（核心，见 §3）
├── cardListJson/
│   └── cardList.json                 # 该页用到的"组件定义"数组（见 §4.cardList）
├── card/
│   └── {Code}/{version}/
│       ├── {Code}.umd.js             # 组件前端 bundle（运行时按 packageUrl 加载）
│       ├── {Code}.umd.min.js
│       └── static/...                # 组件自带静态资源
└── images/
    └── {yyyyMMdd}/00/{pageId}/*.png  # 页面引用的静态图片，按日期+页面id归档
```

要点：
- 包**自带组件前端代码**（`card/`）和**静态素材**（`images/`），导入端可在缺组件时一并落地。
- 即使"空弹窗"也带 9 个基础组件 bundle + 1MB 体积，属正常。
- `pageJson` 文件名含中文页面名 + pageId，导入时以内部 id 为准。

## 3. pageJson 顶层 12 段（= 导入端重建的完整契约）

| 段 | 类型 | 含义 |
|----|------|------|
| `page` | object(43键) | 页面实体本身（见 §4.page） |
| `pageHook` | object/null | 页面级脚本钩子（preScript/afterScript/globalScriptJson；空弹窗为 null） |
| `pageCardList` | array | **组件实例**（放置/层级/父子/坐标，见 §4.pageCardList） |
| `cardList` | array | **组件定义**（code/版本/分类/出厂模板 id，见 §4.cardList） |
| `cardDataList` | array | **数据绑定**（request/extractor/refresh，见 §4.cardDataList） |
| `interactionList` | array | 交互链（事件→动作；空弹窗为空） |
| `pageLayerList` | array | GIS 图层（仅地图页非空） |
| `layerMenuList` | array | 图层菜单 |
| `layerMenuRelationList` | array | 图层菜单关系 |
| `labelList` | array | 标签 |
| `pageAiConfigList` | array | AI 解说配置（当前多为空） |
| `pageAiCustomInteractList` | array | AI 自定义交互 |

## 4. 核心子实体字段契约

### page（页面实体，43 键）
关键可改字段：`id`(uuid) / `name` / `project`(所属项目 id) / `type`(PROJECT…) / `kind`(PAGE|POPUP) /
`width` `height`(画布尺寸) / `previewMode`(ORIGINAL 真实数据 | STATIC 静态) / `templateStyleType`(如"专题模板") /
`styleConfigId`(皮肤外键) / `mapConfigId` `linesConfigId`(地图/辅助线外键) / `imageUrl`(封面) /
`style`(array,页面属性面板 10 项：code/screen/background/line/preview/cover/logo/theme/position/closeBtn) /
`lines`(辅助线 {v,h} 像素坐标) / `groupId`(目标分组) / `creator`/`createTime` 等审计字段。

### pageCardList[]（组件实例 = 放在画布上的一张卡）
`id`(实例 uuid) / `pageId` / `cardId`(指向 cardList 定义) / `name` / `dataId`(指向 cardDataList) /
`level`(Z轴,越大越前) / `styleConfigId`(**实例级**样式快照,非出厂模板) /
`x` `y` `width` `height`(绝对像素,原点左上,允许负) / `parentId`(分组容器) / `beGroup`(是否容器) /
`beHidden` `beLocked` / `style`(实例样式) / `interaction`。
> 分组容器：`beGroup=true` 的卡 `cardId/dataId` 为 null，子卡只在 `children[]` 里，子卡 x/y 是相对容器偏移。

### cardList[]（组件定义 = 用到的组件型号清单）
`id` / `code`(组件身份,如 Rangepick) / `name` / `width` `height` /
`packageUrl`(`/files/card/{Code}/{version}`,运行时加载点) / `version` /
`dataConfigId` `styleConfigId`(出厂模板外键) /
`categoryCode`/`categoryName`/`categoryParentCode`/`categoryParentName`(分类) /
`data` `dataMapping` `style` `interaction`(出厂默认)。

### cardDataList[]（数据绑定）
`id` / `name` / `type`(StaticData | …) / `proxy` /
`request`(15 键的请求描述：url/method/body/headers/sourceType 等) /
`cardData`(数据样本/字段) /
`extractor`(`function filter(data){...}` 清洗函数,运行时支持 ES6) / `extractorEnable` /
`paramFilter`/`paramFilterEnable`(入参转换) /
`refreshInterval`(默认 5000) / `timeoutTime`(默认 6000) / `refreshEnable` / `dataMapping`。

## 5. 落地路径 A：包补丁（主，推荐"一句话出整屏"）

1. 选一个高质量**专题模板**页 id（探索账号库，`templateStyleType=专题模板`）。
2. `batch-export` 导出 → 下载 zip → 解包。
3. **改 pageJson**：换 `page.id`/`name`、换 `pageCardList[].id` 与 `parentId` 引用（保持内部一致）、
   改 `cardDataList[].request`/`extractor` 绑新数据、按需调 `x/y/width/height` 布局、改 `page.groupId` 到目标分组。
   - `card/` 与 `images/` 通常原样保留（除非换组件/换图）。
4. 重新打 zip（命名 `page_xxx.zip`），`POST /wukong-backend/unity/page/batch-import`（multipart：`file` / `setStaticData` / `groupId`）。
   - 项目整包走 `unity/project/import`，包名 `project_xxx.zip`。
5. **写操作红线**：import 仅在隔离 `majianquan` 账号 + 用户显式确认后执行；探索账号永不写。

> 优势：保留模板的样式/动画/坐标/组件私有字段，比从零拼 page-detail 稳得多。

## 6. 落地路径 B：增量分层写（辅，推荐"在既有屏上改/补")

按 pageJson 的关系拆解逐层写：
`page`（建页）→ `pageCardList`（加组件实例，含坐标/层级/父子）→ `cardList`（注册用到的组件定义）→
`cardDataList`（数据绑定）→ `interactionList`（交互）→ `pageHook`（页面脚本）。
> 各写端点的真实 body 仍需在隔离账号手工操作 + 抓包校准（侦察期为只读，写字段名是按读结构反推）。
