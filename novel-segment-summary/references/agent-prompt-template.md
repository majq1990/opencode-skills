# 子 agent prompt 模板（逐块总结）

派发时把 `<...>` 占位符替换掉即可。**不要删掉任何一条硬指令**——每条都对应一个真实踩过的坑。

---

```text
你是小说内容总结助手。请阅读长篇小说《<书名>》（作者：<作者>；<一句话类型说明，例如：NBA 篮球系统流小说，主角杜康是洛杉矶湖人队主教练，人称"D教练"，拥有一个教练系统>）的指定行区间，并输出详细的中文总结。

【文件路径】<绝对路径，例如 D:/backup/user1/majq/Documents/book/某某小说.txt>
【阅读范围】第 <START> 行到第 <END> 行（含，1 起始行号）。本块大约覆盖<章节范围，例如 第 51 章至第 100 章>。

【阅读方法】
1. 用 Read 工具分段读取，每次 offset/limit 最多读 2000 行，连续读取直到完整覆盖 <START>-<END> 行，不得跳过任何部分。
2. 注意从第 <START> 行开始读（offset=<START>），不要从文件开头读。

【总结要求】输出结构化中文 markdown，包含：
- 【范围概览】一两句话说明本段覆盖章节和所处阶段
- 【故事流程】按情节顺序详细叙述主要事件（比赛/任务/交易/人物关系等），保留关键章节名和名场面
- 【主要冲突】本段核心矛盾（对手、内部矛盾、媒体舆论、系统任务挑战等）
- 【成就与收获】具体成果：战绩、记录、奖项、系统奖励、人物成长等，保留数字和名称
- 【关键人物】本段重要人物的动向和转变
- 【遗留伏笔】本段埋下的悬念

【注意事项】
- 文中可能混有与其他作品混淆的乱码段落（突然出现无关人物对话、一句话一段的杂乱文字），直接忽略，不要写进总结。
- 章节编号可能跳号（<按分块计划里的告警填写，例如：如第 113 章后直接跳到第 115 章、第 247 章后跳到第 268 章>），属正常现象，按实际内容总结。
- 文件末尾可能夹带作者新书宣传/外站导流内容，与本书无关，直接忽略。
- 总结长度 1000-2000 字，信息密度优先，保留专有名词（人名、地名、技能名、任务名、数字）。

【输出】写完后，将总结全文写入文件：<交付目录>/chunks/块<NN>.md，并在你的最终回复中原样返回总结全文。
```

---

## 模板要点说明（改动前先读）

| 指令 | 为什么必须有 |
| --- | --- |
| "每次最多读 2000 行，连续读到覆盖完整区间" | Read 工具默认单次上限 2000 行；不说清会漏读后半段 |
| "从第 START 行开始读，不要从文件开头读" | 不强调时 agent 常从第 1 行重读，浪费一半 token 还挤爆上下文 |
| "先写文件，再返回全文" | 抗限流：返回消息可能被截断，文件才是可靠载体 |
| "忽略乱码/无关段落" | 校对版全本常混入其他作品段落，不声明就会写进总结 |
| "章节跳号属正常" | 否则 agent 会以为漏读，反复回头找不存在的章节 |
| "保留数字和名称" | 长文总结的价值全在具体数字与专名，泛泛而谈等于没总结 |
| "1000-2000 字" | 给下限防止偷懒成 300 字，给上限防止把原文复述一遍 |

## 派发节奏

- 同一条消息里并发 8 个 Agent 调用（一批 8 块）。
- 派发后**不要轮询等待**，继续做别的（整理目录、归约已回批次的节点），完成会自动通知。
- 全部批次回来后，先跑一次磁盘清点（`ls chunks/`），再决定是否需要补跑。
