    // 部件ID与标签页面顺序对应
    const tabWidgetList = [
        "effbe7bd-21b3-42a7-8f42-b9316441a482",
        "55e42ef6-ffa0-492c-8924-853262fb7733",

使用内置字段替换不必要的组件隐藏以及强制渲染场景
组件隐藏并开启强制渲染代表组件还是渲染了只是不显示，使用内置字段来替换一方面可以去掉影响设计隐藏组件，另外内置字段组件相关其他组件更简单，效率更高。特殊隐藏组件很多时非常明显。
选择表单设置对内置字段进行管理
避免使用不必要的布局组件嵌套
在设计页面时尽量减少组件，很多人配置时使用了大量不必要的布局组件，会对性能有一定影响。
嵌套层级越深，渲染效率越差。
避免在列表或详情中展示原图
灵珑自己多媒体服务是提供缩略图功能，但在接入外部数据时，可能存在没有对应的缩略图服务。如果图片很大时，就会存在严重的性能问题。
补：灵珑自带多媒体已有缩略图功能，但外部数据来源的可能存在这种情况。

视图配置
基于视图变量性能优化
灵珑视图主要用于不固定条件的场景，如列表查询其条件是用户传入的，生成SQL规则默认：select * from （配置SQL）tmp where 条件。 在复杂大表查询场景，这种会引起索引失效、执行计划劣化问题。灵珑提供sql模块+视图变量方式来可以将部分条件植入到里面，从而提升查询效率。
场景示例
福建12345诉求详情会涉及到从  mis_rec 与 mis_rec_his 中查询案卷详情，同时需要取多张子表关联信息给前端展示。其中 mis_rec 与 mis_rec_his 涉及数据量较大，场景压测接口压测平均响应时间约6590ms。

知识扩展
会话变量会根据调用用户预先计算然后再参与sql查询，是一种预计算优化手段。
会话变量是基于当前用户信息来扩展会话的场景，它会按用户来缓存相关数据。
视图中可以使用工具类来调用会话变量，从而更灵活组织自己的SQL。
可以使用会话变量可以解决数据越权问题。
基于导航属性性能优化
列表或详情涉及到多张表数据查询时，可以通过导航属性来加载对应的数据。这样可以减少不必要的在联表查询，从而提升查询效率。
场景示例
临沂广告系统面向市民公众号服务中的备案记录一栏页面打开极慢，工程反馈需要半分钟。能否打开全凭运气，极大影响用户使用。
配置SQL
select 
ad.approval_id,
ad.documentNo,
ad.remark,
ad.check_result,
case check_result when 1 then '服务中' when 2 then '服务完成' when 3 then '退回' when 4 then '作废' else '待提交' end as checkResult,
ad.advert_status_id,
ad.advert_status_name,
ad.advert_name,
ad.create_time,
ad.set_location,
ad.evaluate_flag,
ad.safe_check_state,
ad.applicant_unit,
ad.setter_person,
wf.taskId,
wf.nodeName,
service.documentNo as serviceNo
 from advert_record ad
left join 
( SELECT
  _main.ID_ taskId,
_main.CREATE_TIME_ createTime,
_main.NAME_ nodeName,
record.documentNo documentNo
FROM
act_ru_task _main
INNER JOIN lcwf_process_record record ON _main.PROC_INST_ID_ = record.processInstanceId 
WHERE
_main.ASSIGNEE_ IS NULL 
ORDER BY
_main.CREATE_TIME_ DESC) wf 
on ad.documentNo = wf.documentNo
left join 
advert_service_evaluation service
on ad.documentNo = service.approval_no
where ad.advert_type_id = 2 and ad.valid_flag = 1 
group by ad.approval_id
order by ad.approval_id desc

基于视图计数的性能优化
在进行列表部件数据查询时会先生成对应的count语句用于计数，但是在性能压测时发现count语句的性能很差，这主要是原因灵珑默认生成的计数sql：select count(0) from (配置sql) where 条件。

Firefox 并发数限制
Firefox 是可以修改的，想要修改首先在地址栏输入 about:config，搜索 http.max 关键字，network.http.max-connections 为全局 HTTP 同时最大的连接数量，默认为 900；network.http.max-persistent-connections-per-server 为单个域名最大链接数量，默认为 6，双击此列可以进行修改。
