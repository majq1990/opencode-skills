# 灵珑配置手册生成工作流（场景 → 手册成果物）

> 用途：面对一道**具体考题**或一个**具体配置场景**，生成一份可直接照做的点击级配置手册**成果物**，输出到 `D:\opencode\file\yyyy-mm-dd\`。
> 核心理念：**skill 内置的是"生成能力"（配置文档 guide + 脚本规范 scripting + 本工作流的方法论），不是固定答案**。
> 考题每年 4/9 月更换、表结构字段会变——**手册是每次按输入现生成的独立成果物文件，不焊死进 skill**。

---

## 与 ⑤需求交付的关系

同一条逻辑——**给输入、按方法论生成独立成果物文件**，只是场景不同：

| | ③ 手册生成（本工作流） | ⑤ 需求交付 |
|---|---|---|
| 输入 | 一道考题 / 一个配置场景 | 真实需求 / Redmine 案件 / 设计文档 |
| 成果物 | 配置手册（点击级操作手册） | 实施方案报告（含工作量/验收/风险） |
| 输出 | `D:\opencode\file\yyyy-mm-dd\`（独立 md 文件） | 同左 |

考试备考走本工作流；真实项目走 ⑤。**两者都不把成果物写回 skill**。

---

## 总流程

```
① 场景识别（判断属于哪一类，可跨类）
      ↓
② 输入采集（题目原文/表结构/评分标准 或 场景描述/数据字典）
      ↓
③ 套用生成（骨架照抄换占位ID / SQL 按模式填本题表字段 / 组件清单对齐场景）
      ↓
④ 手册成型（点击级步骤 + 完整代码 + 评分/验收 checklist + 坑）
      ↓
⑤ 输出落盘（D:\opencode\file\yyyy-mm-dd\ 独立 md，不写回 skill）
```

读完输入后按"要做的东西"对号入座（一道综合题可能跨 2~3 类）。每类的**方法论要点 + 关键骨架**见下方 §附录；配置细节查 `guide/_索引.md` 对应文档，脚本规范查 `scripting/`。

| 场景特征 | 类别 | guide 主文档 |
|---|---|---|
| 统计看板/领导驾驶舱/多指标+图表+筛选联动/指标点击下钻列表 | **领导看板类** | 领导看板主页数据对接说明文档、基于页面的工作台配置、如何使用ddcat数据模型动态查询列表数据 |
| 综合监管工作台/组合筛选+概览指标卡+ECharts趋势图+明细列表导出跳转 | **PC工作台类** | 基于页面的工作台配置、查询条件联动图表配置、列表查询基于Hook查询 |
| 移动端多节点审批/处置流程+各节点tab+办理页 | **移动流程类** | 移动流程表单搭建步骤、移动端搭建实操、流程表单使用表单事件执行后公式 |
| 树+列表主从/区域权限隔离/表单公式自动填充/审核写日志/打印预览 | **视图公式打印类** | 复杂视图、公式、模板打印、公式使用场景示例、使用打印设计按照文档格式导出文档数据、树部件联动卡片和列表 |

## ② 输入采集

### 考题场景
- 题目原文（含表结构 DDL、字段说明、评分标准）——考试当场下发，或知识库「考题」文件夹（nodeId `ydxXB52LJq7l145giMPjgqQ3WqjMp697`）用 `mcp__dingtalk__get_document_content` 拉取
- **表结构是生成 SQL 的地基**：逐表逐字段抄下来，标记主键、关联键、多值字段（逗号分隔）、状态/类型枚举列、逻辑删除列
- 评分标准逐项列出——手册末尾 checklist 对齐它

### 真实场景（同 ⑤需求交付）
- Redmine 案件 `redmine_request` + 附件；钉钉设计文档 `get_document_content`
- 缺表结构先出「待确认清单」，不编造字段

## ③ 套用生成：两类资产区别对待

### A. 跟具体表无关的骨架 —— **原样照抄，只换占位 ID**

这些骨架本就通用（在 `scripting/` 和 §附录里），直接进成果物只替换 `{占位ID}`：
- 页面主脚本：`execDdcat` 适配层 / getFilterParams(clone+空值不传+0值处理) / refreshData(finally关loading+$message.loading句柄+catch) / setLoading / `$$m().props.dataSource.options` 赋值 / window 全局函数封装
- 列表 Hook：三级取参兜底(`$$getRouteView().currentParams`→`$route.params`→window缓存) / 空值合并 / 不动 param.paging / `DATA_EXECUTOR().executeDataModelForList`
- 指标 onClick 跳转：`$router.push` page-preview 带参
- ECharts 柱线混合 option、refreshAll 全页联动
- FLOW_START 启动流程公式、boxType 对照表
- groovy 后置脚本、会话变量三件套、打印 API + 预览按钮
- 脚本规范：`const self=this` / `$$confirm` / `.catch()` / `finally` 关 loading / 移动端 `$ztToast`

### B. 绑死场景的部分 —— **按 §附录模式模板 + 本场景表结构现填**

- **SQL**：用 §附录给的模式骨架（统计聚合/TOP-N多值拆分/明细下钻/exists检索/联合树UNION），`<表>``<字段>` 换成本题真实字段；判空 `#tag where()`/`#if`、时间参数 `_start/_end`、非必填、0值不当空——规则照搬
- **组件清单**：按该类页面组件范式对齐本场景指标数/维度
- **入参出参**：按本题字段命名，与 SQL `${}` 逐字符对齐
- **评分/验收**：对齐本题实际评分标准填分值

### 填充自检
- 每段 SQL/脚本完整可复制，无"此处略"；表名字段与输入一字不差不编造；占位 ID 用 `{XXX}` 统一标注并在开头给"资源 ID 登记表"


# 附录：五类方法论要点 + 关键骨架

> 以下是从 2026 版 5 道考题手册沉淀的可复用要点。骨架部分（JS/groovy/公式）跟具体表无关，生成时照抄换占位 ID。

## A1 领导看板类

**施工顺序**：统计ddcat → 先建下钻列表页 → 看板布局(标题/筛选/指标/图表四区) → 页面JS → 事件绑定 → 联调。

**SQL 模式**：
- 统计聚合（一次扫描避免重复全表）：`SELECT COUNT(1) AS total, IFNULL(SUM(CASE WHEN <标记列>=1 THEN 1 ELSE 0 END),0) AS hit, IFNULL(ROUND(SUM(...)*100.0/NULLIF(COUNT(1),0),2),0) AS rate FROM <表> #tag where() #if(...) ... #end #end`
- TOP-N 多值拆分：逗号分隔字段用 `SUBSTRING_INDEX` + 数字表 JOIN 拆分，内层先按条件过滤成小结果集再拆，`GROUP BY ... ORDER BY cnt DESC LIMIT 5`
- 明细下钻：列表 ddcat **开分页** + 额外下钻标记入参
- 字典下拉：`SELECT name AS label, name AS value`（value 用名称，不用可能对不上的 id）
- 通用规则：`#tag where()`/`#if` 判空、字符串加引号数值不加、入参全非必填、0 值不当空

**页面主脚本骨架**（照抄换 ID）：`execDdcat` 适配层 → `getFilterParams`（时间 `.clone()` 再 format、空值不传、0 用 `!==""` 判）→ `toQueryParams` → `refreshData`（两模型各 then/catch/finally，`$$m(id).props.dataSource.options` 赋值，页面级 `$message.loading` 句柄 + `Promise.all().finally(hide)`）→ `window.refreshData()` 首屏自动查。
**下钻 Hook 骨架**：三级取参兜底 + 空值合并 + 不动 param.paging + `DATA_EXECUTOR().executeDataModelForList`。
**指标 onClick**：含"率"return 不跳；某指标额外带下钻标记；`$router.push` page-preview 带 params。

**通用坑**：0值当空、ddcat(数组)vs api(JSON串)返回结构、loading忘关、options五要素(name/text/value/unit/checked)、保存挂window报错重试、字段别名致面板失效、分页两侧同步、Hook改param、时间补00:00:00/23:59:59、router.push保留栈。

## A2 PC工作台类

**施工顺序**：页面骨架 → **先拖隐藏图表组件加载ECharts库** → 查询区 → 概览卡 → 趋势图 → 列表 → 全页联动。

**要点**：
- 布局：容器+网格/flex，上查询/左下指标卡/右下图表/底部列表
- 查询区：下拉绑视图数据源(显示字段/值字段映射)、日期范围默认近N天、重置/查询按钮
- 概览兜底：JS 赋值 + 空数据 0/0.00（`Number()`+`isFinite()` 再 `toFixed`）
- **ECharts 柱线混合 option 骨架**（照抄）：legend[电子/异常]、xAxis category、yAxis 单位、tooltip、series[bar+line]、`setOption(option, true)` 全量替换防残影；DOM id = `<容器唯一标识>_csshandler_generate`；隐藏图表组件(容器隐藏+强制渲染)先加载 echarts 库；粒度天/周/月切换传参重查
- 列表 Hook + 内置导出按钮 + "更多>"跳转带参
- **refreshAll(params) 骨架**（照抄）：一次刷新概览+趋势+列表+回第一页；多选 `join(',')`；日期 `moment().clone()`

**通用坑**：echarts未定义(忘拖隐藏图表)、DOM id 漏 `_csshandler_generate` 后缀、参数名照题目原文(如 cicleType 别手滑改)、Hook改param、分页同步、多选传数组查空、日期格式化、didMounted时序(setTimeout)、setOption第二参true、空数据兜底。

## A3 移动流程类

**施工顺序**：账号确认 → 流程表单设计 → 流程模板 → 启动流程公式 → 移动端N个tab → 移动办理页 → 全流程验证。

**要点**：
- 表单：字段控件类型；流水号(编号年月日+序号,只读)；只读/必填/隐藏；文号隐藏
- 流程模板：N业务节点+开始结束；节点受理人指定具体账号；批转/回退路由；节点表单字段可见可编辑(编号除外)；操作菜单五种(办结/批转/退件/回退/认领，退回用**回退**不用退件)
- **启动流程公式**（照抄）：`FLOW_START(流程表单页面id, 文号)`；跨实体反查主键用 `FLOW_START('<页面id>', ENTITY_SELECT_ONE('<实体>','id',QUERY_EQ('<列>',<字段>)))`
- 移动端 N tab：标签页组件；每 tab 卡片列表按节点名/办结状态过滤；卡片字段+办理按钮；悬浮新增**仅首节点tab**显示
- **boxType 对照表**（照抄）：认领0/待办详情1/已办2/经办3/办结详情4/查询5；办理入口 boxType=1 传 recordId+taskId，查阅入口 boxType=4 传 recordId+instanceId
- 移动端脚本：消息用 `$ztToast`(非$message)、对话框 `$ztDialog`；提交返回刷新用 refresh=1 + `afterEach` + `card_container_xxx_csshandler_generate` `.__vue__.onRefresh()`

**通用坑**：公式配错位置(要在表单事件-执行后公式)、退回后要能再批转、编号是只读非隐藏、悬浮按钮放首节点tab容器内、tab过滤值与节点名一字不差、操作菜单退回选回退非退件、先保存再批转、受理人绑对账号、boxType传参、必须建流程表单类型。

## A4 复杂视图公式打印类

**施工顺序**：前置(实体注册/数据源/会话变量) → 联合树视图 → 树部件联动 → 列表视图 → 新增表单公式 → 提交刷新 → 审核+日志 → 审核记录 → 打印。

**要点**：
- **会话变量三件套**：数据模型+`DDCAT_CALL` 取登录人 uid/姓名/区域码；`REGION_CHILD_LIST(REGION_ID(),null,true,'code')` 权限区域集；内置 `USER_ID()`/`REGION_ID()`/`NOW()`；**跨数据源不能 JOIN**，登录人信息走公式；⚠️ `USER_ID()`(varchar主键) ≠ sys_human.uid(int)
- 联合树视图：多类节点 UNION + 前缀区分 id(`ORG_`/`REG_`) + node_type；区域权限 `region_code IN(REGION_CHILD_LIST) OR region_code='<中央code>'`
- 树 on-click 按 node_type 传 regId/issuerId 联动列表
- 列表视图：CASE 翻译状态/类型、状态筛选、操作列按状态显隐
- **新增表单公式**（照抄）：文号规则(年月日+4位序号)、`UUID()`、`NOW()`、会话变量取登录人/区域、默认状态0、字段禁用/隐藏
- 审核：状态 UPDATE + `INSERT('<日志表>',[...])` 写日志(含 before/after_status/审核人/时间/意见)
- 审核记录：带 causeId 参数视图，`@DATE_FORMAT(t,'%Y-%m-%d %H:%i')` 倒序
- **打印三件套**：打印数据视图+一对多导航属性；word/excel 模板(子表表格放最后一行)；打印 API(地址+Header `use-web-Authorization: true`+Body 条件)；预览按钮 `execApi` 骨架含未选校验，`design.html#/template/preview/{fileId}` 预览

**通用坑**：跨库JOIN、USER_ID非uid、视图内公式转义、会话变量改后重选、UNION id冲突要前缀且列对齐、`@DATE_FORMAT` 分钟是`%i`非`%m`、文号规则按日重置、打印 Header 漏致401、打印子表要选一对多、预览路径版本差异、提示文案采分一字不改、on-click params 结构先 console.log。

## A5 数据模型高级检索类

**施工顺序**：数据模型SQL → 全局变量 → API注册授权 → 后置脚本 → 列表hook → 查询面板 → 高级检索 → 验证。

**要点**：
- **数据模型 SQL**：主表查询+分页；占位扩展列 `'' AS tag_names`(给后置脚本回填)；时间必填介于(参数名 `<字段>_start`/`_end` + `#if...#else AND 1=2 #end` 不选时间返回空)；包含/等于普通条件；**exists 子查询高级检索**(禁连表，`AND EXISTS(SELECT 1 FROM <子表> WHERE <子表>.fk=<主表>.pk AND delete_flag=0 AND tag LIKE '%${x}%')`，分组精准用 `=`)
- **全局变量**：静态变量存数据源名 `bd_var:xxx`；后置脚本 `AppConstUtils.getValue("bd_var:xxx")` 取库名，不写死
- **API 配置**：注册 GET；环境变量拼地址(不写死 ip)；授权四选一；Query 参数与模型一致；后置转换解析
- **groovy 后置脚本骨架**（照抄，服务端）：反序列化 data → 收集主键集 → 全局变量取库名 → `sql.ofNamed(db).forList('...in(:ids)...delete_flag=0', ...)` → 按主键分组逗号拼接 → 回填扩展字段 → 序列化返回
- **列表 hook 骨架**（照抄）：`executeApiModelForList(apiId,"BUNCHES",param,{lostAbility:"01"})`(BUNCHES=灵珑API非WIDZOM)；旧版 `API_DATA_EXECUTE` 兼容；不动 param；分页 param.paging + 接口返回总数
- 骨架视图(字段名不别名、datetime 用 NOW 占位)；查询面板固定条件别多配；高级检索入口+字段绑定+隐藏必填时间

**通用坑**：介于参数命名 `_start/_end`、忘 `#else AND 1=2`、写死库名、exists 忘 delete_flag=0、图省事直接 JOIN 大表、hook apiId 没改/类型 BUNCHES 非 WIDZOM、忘占位扩展列、骨架视图别名、分页两侧同步、多配过滤条件、高级检索没带必填时间、状态配成包含应为等于、API 改完没保存就发送、groovy 命名参数别手拼 in。
