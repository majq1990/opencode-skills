# 企业物联告警数及平均告警数统计

## 1. 用户需求描述

统计企业物联告警数和平均告警数，查询参数为一个月的开始时间和结束时间，输出字段为：

- 企业名称
- 物联告警数
- 平均告警数

业务口径如下：

- 物联告警数 = 物联监测中设备监测数值不符合阈值产生的报警数
- 不包含离线报警，即 `value_type_id != '-1'`
- 平均告警数 = 告警总数 / 设备总数
- 企业名称不能为空
- 按平均告警数降序排序
- 仅返回前 9 条

说明：

- 未指定数据库方言，默认按 MySQL 方言编写
- 设备总数按技能约定，取 `iot_equip_info` 中 `valid_flag = 1` 的有效设备数

## 2. 参数说明

| 参数名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `startTime` | String | 是 | 查询开始时间，例如 `2026-03-01 00:00:00` |
| `endTime` | String | 是 | 查询结束时间，例如 `2026-04-01 00:00:00` |
| `equipTypeId` | String | 是 | 设备类型，例如 `41` |

时间过滤口径：

- `a.alarm_time >= '${startTime}'`
- `a.alarm_time < '${endTime}'`

## 3. 输出字段说明

| 字段名 | 说明 |
|---|---|
| `企业名称` | 企业名称，来源于 `iot_equip_info.manufacturer_name` |
| `物联告警数` | 时间范围内企业非离线报警记录总数 |
| `平均告警数` | `物联告警数 / 设备总数`，保留 2 位小数 |

## 4. DDCAT SQL 脚本
统计较复杂，需要在DDCAT中添加缓存，建议30分钟

```sql
#if (startTime != null && startTime != '' && endTime != null && endTime != '')
    SELECT
        d.manufacturer_name AS 企业名称,
        COALESCE(a.alarm_count, 0) AS 物联告警数,
        ROUND(COALESCE(a.alarm_count, 0) / NULLIF(d.device_count, 0), 2) AS 平均告警数
    FROM (
        SELECT
            manufacturer_name,
            COUNT(*) AS device_count
        FROM iot_equip_info
        #tag where()
            AND valid_flag = 1
            AND manufacturer_name IS NOT NULL
            AND TRIM(manufacturer_name) <> ''
            AND equip_type_id = '${equipTypeId}'
        #end
        GROUP BY manufacturer_name
    ) d
    LEFT JOIN (
        SELECT
            ei.manufacturer_name,
            COUNT(*) AS alarm_count
        FROM iot_equip_alarm a
        INNER JOIN iot_equip_info ei ON a.equip_id = ei.equip_id
        #tag where()
            AND ei.valid_flag = 1
            AND ei.manufacturer_name IS NOT NULL
            AND TRIM(ei.manufacturer_name) <> ''
            AND a.value_type_id != '-1'
            AND a.alarm_time >= '${startTime}'
            AND a.alarm_time < '${endTime}'
            AND ei.equip_type_id = '${equipTypeId}'
        #end
        GROUP BY ei.manufacturer_name
    ) a ON d.manufacturer_name = a.manufacturer_name
    ORDER BY 平均告警数 DESC, 物联告警数 DESC, 企业名称 ASC
    LIMIT 9
#else
    SELECT
        CAST(NULL AS VARCHAR(200)) AS 企业名称,
        CAST(NULL AS NUMERIC(18,0)) AS 物联告警数,
        CAST(NULL AS NUMERIC(18,2)) AS 平均告警数
    WHERE 1 = 2
#end
```

## 6. 计算逻辑说明

### 6.1 设备总数

设备总数来自 `iot_equip_info`，统计口径为：

- `valid_flag = 1`
- `manufacturer_name` 非空

按企业名称分组统计每个企业的有效设备数，作为平均告警数的分母。

### 6.2 物联告警数

物联告警数来自 `iot_equip_alarm`，并关联 `iot_equip_info` 获取企业名称，统计口径为：

- 仅统计有效设备：`ei.valid_flag = 1`
- 企业名称不能为空
- 排除离线报警：`a.value_type_id != '-1'`
- 报警时间在参数范围内：`a.alarm_time >= startTime` 且 `a.alarm_time < endTime`

### 6.3 平均告警数

平均告警数计算公式：

```text
平均告警数 = 物联告警数 / 设备总数
```

为避免除零错误，SQL 中使用：

```sql
ROUND(COALESCE(a.alarm_count, 0) / NULLIF(d.device_count, 0), 2)
```

### 6.4 排序和条数限制

- 首先按 `平均告警数` 降序
- 其次按 `物联告警数` 降序
- 最后按 `企业名称` 升序
- 返回前 `9` 条记录

## 7. 可执行 SQL

```sql
SELECT
    d.manufacturer_name AS 企业名称,
    COALESCE(a.alarm_count, 0) AS 物联告警数,
    ROUND(COALESCE(a.alarm_count, 0) / NULLIF(d.device_count, 0), 2) AS 平均告警数
FROM (
    SELECT
        manufacturer_name,
        COUNT(*) AS device_count
    FROM iot_equip_info
    WHERE valid_flag = 1
      AND manufacturer_name IS NOT NULL
      AND TRIM(manufacturer_name) <> ''
    GROUP BY manufacturer_name
) d
LEFT JOIN (
    SELECT
        ei.manufacturer_name,
        COUNT(*) AS alarm_count
    FROM iot_equip_alarm a
    INNER JOIN iot_equip_info ei ON a.equip_id = ei.equip_id
    WHERE ei.valid_flag = 1
      AND ei.manufacturer_name IS NOT NULL
      AND TRIM(ei.manufacturer_name) <> ''
      AND a.value_type_id != '-1'
      AND a.alarm_time >= '2026-03-01 00:00:00'
      AND a.alarm_time < '2026-04-01 00:00:00'
    GROUP BY ei.manufacturer_name
) a ON d.manufacturer_name = a.manufacturer_name
ORDER BY 平均告警数 DESC, 物联告警数 DESC, 企业名称 ASC
LIMIT 9;
```

## 8. 备注

- 当前写法按企业名称 `manufacturer_name` 分组；如果实际业务要求按企业 ID 唯一统计，可改为按 `manufacturer_id + manufacturer_name` 联合分组。
- 当前平均告警数的分母为企业有效设备总数，不受时间范围影响；如果后续需要改成“当月活跃设备数”或“当月有上报设备数”，需要补充明确口径后再调整 SQL。
