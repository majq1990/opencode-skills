# 星桥设备基础数据对接脚本实施计划

## Summary
- 产出两段脚本：`前置脚本`（仅做转换并改写 `request.body`）+ `后置脚本`（透传结果）。
- 输入格式固定为 `{"data":[...原始采集对象...]}`，输出改写为 `/api/admin/import` 要求的数组对象（严格按接口字段）。
- 本次不在前置脚本内主动 `HttpUtils.postJson` 推送，不使用 `api_stop`。

## Implementation Changes
- **前置脚本主流程**
  - 读取 `request.getBody().getString()`；空值直接 `return`。
  - 反序列化为 `Map`，取 `data` 列表逐条转换。
  - 坐标按 `bdmc2wgs84ll` 转换：`location_u097mk_longitude/latitude -> x/y`；任一为空则跳过该条。
  - 转换完成后 `request.setBody(JsonUtils.serialize(equipList))`。
- **字段映射（严格 admin/import）**
  - `equipCode <- text_log6v8`（仅此字段；为空跳过该条）。
  - `equipName <- equipName`，为空回退 `detailed_address`。
  - `equipTypeId <- 41`（室温设备类型常量）。
  - `address <- detailed_address`。
  - `manufacturerName <- heating_company_name`。
  - `projectId <- region_u9lwvg_city_name_code`（沿用现网约定）。
  - `cityCode/districtCode/streetCode <- region_u9lwvg_city_name_code / district_name_code / street_name_code`。
  - `cityName/districtName/streetName <- region_u9lwvg_city_name / district_name / street_name`。
  - `installTime <- installTime`（`yyyy-MM-dd` 转毫秒时间戳，失败则不赋值）。
  - `fields` 固定两项：`room_temperature`（数值，单位℃）与 `power_status`（文本）；字段名使用 `genAlarmFlag`、可带 `displayOrder`。
- **后置脚本**
  - 默认透传 `data`，不做二次加工（仅保留必要中文注释）。

## Test Plan
- 使用 `需求.md` 示例 body 验证可生成非空数组，且每项都满足 `/api/admin/import` 字段名。
- 验证 `equipCode` 为空记录被过滤；坐标为空记录被过滤。
- 验证 `installTime` 可正确转毫秒；异常日期不会导致整体失败。
- 验证前置脚本改写后的 body 为 JSON 数组字符串，后置脚本返回原始 `data`。

## Assumptions & Defaults
- 采集坐标是 BDMC，必须先转 WGS84。
- 不做严格校验与去重（按“不过度校验”执行）。
- 不使用 `BigDecimal`，关键步骤加中文注释。
- 当前模式不直推外部 URL；若后续切到“前置直推”，再补充并提醒替换目标 IP/端口与鉴权参数占位。
