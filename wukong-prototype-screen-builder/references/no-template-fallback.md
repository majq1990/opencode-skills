# 无模板时的组件化重建策略

## 判断条件

进入无模板 fallback 的条件：

1. 没有业务域、尺寸、布局都接近的整屏模板。
2. 真实模板为空壳、状态异常、组件缺失或缺少关键样式。
3. 设计图风格和现有模板差异过大。
4. 用户明确要求按原型图重建，而不是套老模板。

## 三档 fallback

| 档位 | 条件 | 处理方式 |
| --- | --- | --- |
| B1 组件模板可复用 | 没有整屏模板，但设计库有类似组件 | 用组件模板逐块拼屏 |
| B2 样式可复用 | 组件模板不匹配，但边框/标题/背景可复用 | 外壳复用，业务区重建 |
| B3 仅素材可复用 | 整屏和组件都不匹配 | 装饰切图 + 悟空占位组件 |

## 重建规则

1. 背景和复杂装饰可以切图。
2. 指标、图表、表格、地图、筛选器必须尽量用悟空组件。
3. 无法识别的图表先用静态图片占位，但要记录为待组件化区域。
4. 图层坐标按原型图比例映射到目标画布。
5. 先保证 R0 可编辑结构，再逐步接交互和真实数据。

## 输出要求

进入 fallback 时输出：

1. 为什么没有使用整屏模板。
2. 哪些区域可直接组件化。
3. 哪些区域需要切图。
4. 哪些区域先做占位。
5. 预计可达到 R0/R1/R2/R3 哪一档。

## 禁止

1. 禁止整图铺底后声明完成。
2. 禁止把图表截图当作最终动态组件。
3. 禁止在没有接口资料时编造真实数据源。
4. 禁止不说明可编辑性损失。
