# 起点读书每日任务自动化

无人值守跑完起点读书福利中心里所有**安全**的每日任务，把"看 15 秒广告换券"这种纯薅羊毛动作自动化。

## 触发条件

用户说以下任一：
- "/qidian-daily-tasks"
- "跑一遍起点每日任务" / "起点签到" / "起点日常"
- "领起点福利" / "起点广告任务" / "qidian 任务"
- 提到「起点读书」+ 「福利中心」/「广告任务」/「领奖励」

## 前置依赖（开跑前自检）

1. **mobile-mcp MCP server 已连上**：能调 `mcp__mobile-mcp__mobile_list_available_devices`
2. **adb 设备已连**：返回至少 1 个 `state: online` 的 Android 设备。无设备时停下来告诉用户："请用 USB 连接安卓手机并开启 USB 调试"
3. **起点读书已安装且登录**：`mobile_list_apps` 应包含 `com.qidian.QDReader`。未登录时 app 会停在登录页，识别到登录界面立即停下让用户手动登录
4. **屏幕未锁**：如果第一次 screenshot 是全黑，调一次 `adb shell input keyevent KEYCODE_WAKEUP` 唤屏；如果需要解锁密码，告诉用户手动解锁
5. **不要在通话中跑**：如果检测到 `dumpsys window | grep mFocusedApp` 包含 `incallui`，停下来告诉用户"当前正在通话，请挂断后重试"

## 核心安全清单

### ⛔ 绝对不做（硬编码黑名单，**永不触发**）

| 任务关键词 | 跳过原因 |
|---|---|
| **充值** / **支付** / **付款** / **当日游戏充值 1 次** | 🔴 **会扣真钱**。任何"完成"动作都意味着触发付款流程（哪怕 1 分钱），AI 永远不应自主代用户付款。这条是 hard rule，用户即使口头说"全跑一遍"也不要点。 |
| **添加小组件** / **桌面组件** | 会修改用户桌面布局，事后用户还要手动删，副作用持久 |
| **玩 X 分钟 H5** / **玩游戏 X 分钟** | 需要 10+ 分钟真互动，自动化无法保证奖励发放 |
| **每周阅读 X 分钟** / **去阅读** | 需要真实阅读时长，无法薅 |
| **分享** / **邀好友** | 涉及社交关系链，不应代用户分享 |
| **兑换**（兑换积分→实物/会员） | 消耗用户积分，需用户明确决策 |

### ✅ 允许自动跑

**类别 A：看广告类**——点了「去完成」弹广告小游戏，**点底部那条蓝色椭圆大按钮**（文案随广告主变：去看看 / 立即领取 / 查看详情 / 立即购买 / 立即抢购 / 了解更多 / 去逛逛 / 去微信 / 去 XX 玩…全都通用），sleep 20s 后切回起点，广告 SDK click-through attribution 就发奖励。识别特征：
- 弹窗里有底部蓝色或绿色椭圆大按钮，**永远点这条**
- 弹窗右下角标着「广告」
- 顶部小标签「点击后，看 15 秒可获得奖励」
- 切回起点后顶部变「恭喜已获得奖励」 = 成功
- 典型任务名：「激励任务」/「做任务领惊喜福利」/「做任务得 XX 装扮」/「完成 N 个广告任务得奖励」/ 515 popup「浏览广告得 X 点章节卡」

**⚠️ A 类内部细分（v1.2 新增）**：
- **激励任务（有限 stepper）**：5 阶进度条，每点一次去完成 = 看 1 次广告 + 领 1 阶奖励，5 阶全 ✓ 后按钮变「已领取」，今日不能再跑
- **做任务领惊喜福利（小时冷却）**：每 1 小时可跑一次，跑完显示「剩 HH:MM:SS」
- **完成 3 个广告任务得奖励（循环计数器）**：每跑 3 次广告自动 +10 点章节卡，看「再完成 N 次可得」状态。**会随激励任务/其他广告自动累加**，**不需要单独点**（虽然点了也行）
- **完成 1 个广告任务得奖励（独立任务）**：⚠️ **必须单独点这个按钮跑一次广告才发奖**，**不会**随其他广告自动累加。每次给「满 10 点-3 点订阅券」，可反复点（循环）
- **做任务得白泽宇航员装扮（每日 1 次）**：可能跟激励任务一起被自动领，也可能需要单独点

**类别 B：打开书架 N 本书类**——「每周新打开 3 本作品的更新提醒」之类，从书架挨个点书"打开"即可（用户授权过：3 本书任意挑，不挑剔哪本）。识别特征：
- 任务名含「新打开 N 本作品」或「打开 N 本书」
- 进度条显示「已打开 X/N 本」

## ⚠️⚠️ 坐标系铁律（2026-06-02 血泪，跑前必读，否则全程点空）

**mobile-mcp 的截图坐标 ≠ 点击坐标，两者差 1.336 倍。这是本 skill 最大的坑。**

- `mobile_take_screenshot` 返回的图被缩放到约 **898 宽**（高约 1998）。
- `mobile_click_on_screen_at_coordinates` 收的是**设备真实分辨率** `1200×2670` 坐标系。
- **换算：真实坐标 = 截图视觉坐标 × (1200/898) ≈ × 1.336**（x、y 同比例）。

**症状**：如果你直接拿截图上目测的像素（如「去完成」按钮看着在 `(760, 703)`）去点，会落在屏幕左中部的标题文字区，**点了完全没反应**——不弹广告、不跳转、页面纹丝不动。2026-06-02 因此误判成"模拟器拦广告""广告库存空"，浪费十几分钟，全是坐标错。

**正确做法（任选其一，推荐第 1）**：
1. **优先用本文档「实测数据」表里的真实坐标**（如激励任务「去完成」x=**1016**，不是 760）。表里所有坐标都是 1200 体系，可直接喂给 `mobile_click`。
2. 若必须用截图视觉定位（按钮位置随滚动变化），**读出的视觉坐标务必 ×1.336 再点**。例：视觉 (760, 703) → 真实 (1016, 939)。
3. 用 `mobile_list_elements_on_screen` 拿到的 native 元素坐标本来就是 1200 体系（如福利中心入口 `(330,1181)`），可直接用——这也是为什么导航能成、点广告按钮总失败的原因。

**自检**：点完「去完成」务必截图确认是否弹出广告全屏页（顶部「点击后，看 15 秒可获得奖励」+ 底部蓝色大按钮）。**没弹 = 99% 是坐标没换算，不是广告问题**，先怀疑坐标，别怀疑环境。

> 附带教训：mobile-mcp 会把真机 **Redmi K70 Pro（型号 `23127PN0CC`）误报成 `type: emulator`**。**不要据此判断是不是模拟器**，更不要因为"是模拟器"就断定广告跑不了。型号 23127PN0CC = 真机。

## 默认执行范围（2026-06-02 用户指定，除非另有说明）

用户日常只要跑这 **4 个**，按此顺序：
1. **激励任务**（5 阶 stepper）
2. **完成 1 个广告任务得奖励**（独立，必须单独点）
3. **完成 3 个广告任务得奖励**（计数器，跑前两个时自动累加，一般不用单独点）
4. **做任务领惊喜福利**（1 小时冷却）

**默认不跑**（用户明确排除，看到直接跳过，别问）：
- ❌ 做任务得白泽宇航员装扮
- ❌ 每周新打开 3 本作品的更新提醒（Step 5B 整段默认不执行，除非用户当次明确要求）

**节奏（用户指定，覆盖下文旧值）**：
- 广告全屏页点完蓝色大按钮后 **sleep 17 秒**（旧值 20s 作废）再切回起点。
- 上一个奖励领完（关 × + 知道了）后 **等 3 秒**再点下一个任务的「去完成」。

## 流程

### Step 1: 启动 + 导航到福利中心

```
mcp__mobile-mcp__mobile_list_available_devices
  → 取第一个 online 的 device id
mcp__mobile-mcp__mobile_launch_app(packageName=com.qidian.QDReader)
等 2 秒（首屏加载）
mcp__mobile-mcp__mobile_take_screenshot → 确认是起点首页
```

### Step 2: 点底部「我」tab

底部导航是 5 列等宽。「我」在最右。
- 屏幕宽 W，高 H，则「我」tab 中心 = (W * 0.9, H * 0.97)
- 1200×2670 设备：**(1080, 2586)**

```
mcp__mobile-mcp__mobile_click_on_screen_at_coordinates(x=1080, y=2586)
```

如果是其他分辨率，先用 `mobile_list_elements_on_screen` 找 `view_tab_title_title` text="我" 的元素拿 bounds。

### Step 3: 点「福利中心」入口

「我」页面是 RecyclerView，福利中心通常在第一行第一列。
- `mobile_list_elements_on_screen` 找 TextView text="福利中心"
- 然后点其父容器 `layoutItem` 中心
- 1200×2670 实测坐标：**(330, 1181)**

⚠️ 如果找不到「福利中心」TextView，可能是 app 改版了。停下来截图给用户看，请用户手动确认入口位置。

### Step 4: 扫描页面所有「去完成」

进入福利中心后，页面是 WebView + Native 混合，`mobile_list_elements_on_screen` 看不到内部元素。**必须用截图 + 视觉识别**。

扫描策略：
1. 先 `mobile_take_screenshot` 截当前屏
2. 视觉识别所有红色椭圆按钮，记录文字（去完成 / 已领取 / 去阅读 / 去看看 / 去分享 / 去订阅 / 领积分 / 兑换 / 剩 HH:MM:SS）
3. 视觉记录该按钮所在行的任务标题
4. `mobile_swipe_on_screen(direction=up, distance=1500)` 下一屏，重复
5. 直到看到「更多积分好礼 >」link 或者再滑没有新内容，确认到底

每一屏识别后，把所有按钮分类：

| 按钮文字 + 任务名 | 分类 | 处理 |
|---|---|---|
| 去完成 + 「充值」/「支付」/「付款」 | ⛔ 黑名单 | **绝不点**，加入 skip 列表 |
| 去完成 + 「添加小组件」/「玩 X 分钟」/「分享」/「邀好友」 | ⛔ 黑名单 | 跳过 |
| 去完成 + 「做任务」/「领惊喜福利」/「领装扮」/「激励任务」 | ✅ **A 类** | 列入待跑（按 Step 5A） |
| 去完成 + 「打开 N 本作品」/「打开 N 本书」 | ✅ **B 类** | 列入待跑（按 Step 5B） |
| 已领取 / 剩 HH:MM:SS / 已签 | ✓ 完成 | 跳过 |
| 去阅读 / 去订阅 / 去分享 / 去看看 / 兑换 / 领积分 | ⛔ 非自动 | 跳过 |
| 去完成 + 看不出是哪类 | 🟡 未知 | 截图给用户，问要不要点 |

把分类结果列表给用户确认一次（用 TodoWrite，把每个待跑任务列成一项，活动形式写明 A 类/B 类），然后再开跑。

### Step 5: 跑每一个「待跑」的去完成

⚠️ **回到页面顶部再开始**（避免坐标偏差）：`mobile_swipe_on_screen(direction=down, distance=5000)` × 2-3 次回顶。

按"先 A 后 B"的顺序处理（先把广告类一口气跑完，再做书架类，最后回福利页确认状态）。

#### Step 5A: 看广告类（ad-skip 模式）

对每个待跑的 A 类任务：

```
1. 滑屏直到该任务的「去完成」按钮在可视区
   - 截图确认按钮位置
2. 视觉读取按钮像素坐标（屏幕分辨率 1200×2670 时，按钮宽约 250px）
3. mobile_click_on_screen_at_coordinates(x=按钮中心 x, y=按钮中心 y)
4. 等 1-2 秒让广告弹窗出现
5. mobile_take_screenshot
6. 检查弹窗类型：
   - 见「立即领取」按钮 → 这是新版广告任务流程，继续 Step 7
   - 见绿色「去微信...玩...」按钮 → 旧版 ad-skip 类，跳到旧版流程（Legacy Step 7）
   - 没弹窗或弹窗形式不对 → 截图给用户，停下问

7. 【新版流程】点击「立即领取」按钮
   - 视觉识别「立即领取」按钮坐标并点击
   - 等 1-2 秒，截图确认
   - ⚠️ 关键验证：截图中必须能看到「15s」倒计时数字开始减少（如 15→14→13...）
     - 如果看不到倒计时开始减少 → 广告可能没真正触发，重试一次
     - 如果多次都没有倒计时 → 截图标记为「未确认」，跳过
   - 等待倒计时结束（约 15-20 秒）
   - 倒计时结束后，通常会自动弹出奖励或返回福利页
   - 截图确认奖励状态

   Legacy Step 7: 【旧版流程】视觉识别绿色「去微信...玩...」按钮坐标，点击
   - 1200×2670 典型坐标：(600, 1830)

8. Bash sleep 17  ← 用户指定 17 秒（旧值 20s 作废）让广告 SDK callback
9. mcp__mobile-mcp__mobile_launch_app(packageName=com.qidian.QDReader)
   - 切回起点
10. mobile_take_screenshot
11. 见「恭喜你已获得奖励」弹窗 + × 关闭按钮（右上角约 (1119, 302)）：
    - 点 ×
12. 弹窗变成奖励详情 + 「知道了」按钮（约 (600, 1742)）：
    - 点「知道了」
13. 截图确认回到福利中心页 + 该任务状态变为「剩 HH:MM:SS」或「已领取」
14. 把该任务 TodoWrite 标 completed
15. Bash sleep 3  ← 用户指定：领完上一个奖励等 3 秒再点下一个任务的「去完成」
```

> ⚠️ 步骤 2/3 的坐标：**别拿截图目测像素直接点**，先看顶部「坐标系铁律」——截图坐标要 ×1.336，或直接用「实测数据」表里的真实坐标（去完成 x=1016）。

**⚠️ 新版广告任务关键变化（2026-05-26 更新）**：
- 旧版：点「去完成」→ 弹窗 → 点绿色「去微信」按钮 → 切回 → 领奖励
- 新版：点「去完成」→ 弹窗 → 点「**立即领取**」→ **必须看到 15s 倒计时开始减少** → 等倒计时结束 → 奖励到账
- 判断方法：截图后看弹窗里是绿色椭圆「去微信...玩...」按钮还是「立即领取」按钮
- 如果倒计时没开始减少就切回，奖励**不会**生效

**奖励金额识别**：第 12 步「知道了」前的弹窗会显示具体奖励（如「恭喜获得 50-5 点订阅券」）。把每个任务的实际奖励记下来，最终汇总给用户。

#### Step 5B: 打开 N 本书类（书架点书模式）

当任务名形如「每周新打开 N 本作品的更新提醒」（进度「已打开 X/N 本」）时：

⚠️ **用户授权**：用户已明确说"从我的书架里面，找 N 本书打开即可"——任意挑 N 本，不挑剔哪本。**不要**进入书详情页改通知开关（用户没让做）；**只是单纯点开书进阅读页**。

```
1. 滑屏找到该任务行，截图记录现在「已打开 X/N」的 X 值
   - 比如：「已打开 0/3 本」→ 需要再打开 N-X = 3 本
2. 点该任务的「去完成」按钮
3. 等 1-2 秒，截图观察跳转结果：
   3a. 直接跳到书架页（底部 tab「书架」高亮）→ 已就位，进 Step 4
   3b. 弹解释弹窗 → 找「知道了/去看看/我知道了/确定」按钮点掉 → 等 app 自动跳书架；若不跳，手动点底部「书架」tab (1200×2670 时坐标 (120, 2586))
   3c. 跳到其他页（如新书推荐）→ 立即手动点底部「书架」tab 到书架
4. 在书架页，识别书目列表：
   - 用 mobile_list_elements_on_screen 找所有 `tvBookName` 元素（每本书有一个，含书名 text）
   - 取前 N - X 本（X 是已完成数）
   - 重要：跳过当前置顶的"在读"书（顶部那本最近读的不算"新打开"）
5. 对挑出来的 N - X 本书，依次：
   a. mobile_click_on_screen_at_coordinates(书名 tvBookName 元素中心)
   b. Bash sleep 2  ← 等阅读器加载，触发"打开"事件上报
   c. mobile_take_screenshot 确认进入阅读页（有正文）
   d. mcp__mobile-mcp__mobile_press_button(button=BACK) 回书架
   e. 再 sleep 1，确认回到书架（看到多本书列表）
   - 如果某本"打开"后弹了引导/广告/订阅弹窗：找 × 或「关闭/跳过/暂不」按钮点掉，再 BACK
6. 全部 N - X 本打开完后，回福利中心：
   - 点底部「我」tab (1080, 2586)
   - 点「福利中心」layoutItem (330, 1181)
   - 滑到该任务行截图
7. 检查任务状态：
   - 若变成「已领取」或带「领取/领奖励」按钮 → 点「领取」收奖励
   - 若 X 仍未到 N（如显示「已打开 1/3 本」而预期 3/3）→ 起点服务端可能还没同步，再等 5-10 秒重新进福利页看一次
   - 若多次确认 X 仍未涨 → 任务标记为「未确认领取」，截图给用户人工核实
8. 若有「领取」类按钮，点击后处理「恭喜获得 XXX」弹窗（同 5A 第 11-12 步）
```

**注意**：
- 该任务通常是**每周**冷却，不是每天。已领取过这一周就别再跑了，靠 Step 4 的扫描结果判断（看到「已领取」就跳过）
- 若书架空（用户没加任何书），无法完成，把任务标记为「无书可开」

### Step 6: 汇总报告

跑完所有待跑任务后，给用户一个表：

```

| 任务名 | 奖励 | 状态 |
```

## 异常处理

| 现象 | 处理 |
|---|---|
| 启动后停在登录页 | 停下告诉用户："起点账号未登录，请手动登录后重跑" |
| 点「去完成」后 30 秒还没弹窗 | 多 screenshot 一次，可能是 app 卡了，最多重试 1 次 |
| 弹窗跳到天猫直播/京东超市等深链 WebView | 按 BACK 退出，奖励**照常发放**（嵌入式 WebView 而非外部 app）— 不要标记跳过 |
| 弹窗真的跳出到外部 app（如淘宝/京东 app） | 立即按 BACK 退出，把这个任务标记为「跳过-需人工」 |
| 「我」tab 找不到 / 福利中心入口找不到 | app 改版，截图给用户，让用户描述新路径，把这条经验回写本 skill |
| **点福利中心 (330, 1181) 却跳到「邀好友阅读」页** | 顶部有消息通知条/红点导致页面下移。`BACK` 退出 → 用 `mobile_list_elements_on_screen` 找 `TextView text="福利中心"` 拿真坐标 |
| **进福利中心自动弹 popup**（如「邀好友阅读得 12000 点」全屏） | 这是活动 popup 自动占据屏幕，按 BACK 一次即可退回福利中心 |
| **每天首次进福利中心弹 515 书粉节 popup**（「浏览广告得 6 点章节卡」） | 跑它！点「去浏览」(600, 1603) → 跑一次广告就拿 6 点章节卡（每日 1 次额外薅） |
| 切回起点后弹窗不见了 | SDK 可能没 callback，截图证据 + 标记为「未确认领取」 |
| 跑到一半设备掉线 | `mobile_list_available_devices` 重新探测；若空则 `adb kill-server && adb start-server && adb devices`，若仍空让用户检查 USB 连接 |
| **手机息屏导致截图全黑/点击无响应** | `adb shell input keyevent KEYCODE_WAKEUP` 唤屏。**长流程时尽量保持屏幕亮起** |
| **通话中触发** | 检测到 incallui（来电/通话）立即停下来告诉用户挂断后重跑 |
| 同一个广告主连刷 4-5 次 | 正常，广告 SDK 短时内会重复推同广告主（京东 La Mer 等）。每次都是不同的广告位计数，奖励照发 |

## 调用频率建议

- **「激励任务」** 每日 5 次广告（5 阶 stepper），一波跑完即可，跑完显示「已领取」当日不再
- **「做任务领惊喜福利」** 1 小时冷却 → 一天可跑多次
- **「完成 1 个广告任务得奖励」** 单次 → ⚠️ **必须单独点这个按钮**才发奖（满 10 点-3 点订阅券）；可反复点（循环）
- **「完成 3 个广告任务得奖励」** 计数 → 跑激励任务时自动累加 +1，凑够 3 次自动到账 +10 点章节卡
- **「做任务得白泽宇航员装扮」** 每日 1 次（可能跟激励任务一起被自动领，看到「已领取」直接跳过）
- **「515 popup 浏览广告得 6 点章节卡」** 每日 1 次，进福利中心自动弹
- **「每周新打开 3 本作品的更新提醒」** 每周 1 次 → 一周 1 次足够（领过本周不需再跑）
- 推荐：每天定时跑一次（手动 `/qidian-daily-tasks` 或挂 `/schedule` 每天 9:00 自动跑）
- 实测（2026-05-29）：**广告 SDK 短时连刷 8-10 次无问题**，不像 v1.0 警告的那样会封整天。建议一次性把所有 A 类跑完。

## 全跑一天的「最优路径」（v1.2 实测）

按以下顺序一次跑完，约 8 分钟，每日总收益约 +20 点收益 + 多张订阅券 + 30+ 点章节卡：

1. 启动起点 → 点底部「我」(1080, 2586) → 点福利中心 (330, 1181)
2. **515 popup 自动弹**（首次进当天）→ 点「去浏览」(600, 1603) → 15s 广告 → 6 点章节卡 ✅
3. 跑激励任务 5 阶（点 5 次「去完成」，每次 15s 广告 + 关 × + 知道了）→ stepper 全 ✓ 显示「已领取」
4. 中途自动触发：完成 3 个广告自动 +10 点章节卡 ×N 轮（无需手动）/ 完成 1 个广告**不会自动**
5. **单独点「完成 1 个广告任务得奖励」**（容易漏！）→ 1 次广告 → 满 10 点-3 点订阅券 ✅
6. **单独点「做任务领惊喜福利」** → 1 次广告 → 10-3 / 50-5 订阅券 ✅（之后 1 小时冷却）
7. 检查白泽宇航员装扮：若「去完成」则单独点跑一次，若已变「已领取」就跳过
8. 汇总报告：本周收益 / 优惠卡券 / 章节卡 / 积分增量

## 不在本 skill 范围内（明确边界）

- ❌ 真签到/连续签到的连续天数维护（起点是自动的，不需 skill）
- ❌ 兑换积分→礼品/会员（需用户明确决策每次兑哪个）
- ❌ 抽奖（必中夺宝之类）— 消耗点币，要用户决策
- ❌ 阅读真书/订阅真书（需要真实阅读时长，无法自动化）
- ❌ 跨设备同步（本 skill 只操作本机连的那台 adb 设备）
