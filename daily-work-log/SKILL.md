# daily-work-log：当日工作面板填报

## 面板

- 地址：`http://100.103.28.84:8765/input?key=AhXDXgGlwjFarWup`
- `day=YYMMDD`（当天）。**每天 18:20 面板自动把当日内容整理成日报推钉钉——18:20 前写好。**

## 读写接口

- 读：`GET /input?key=...`（返回 HTML；`freeform` = 「其它工作」textarea；另有待办勾选区 `done_*` / 进展 `prog_*` 字段）
- 写：`POST /submit-input`，form-urlencoded 三字段：`key` / `day` / `freeform`

## 硬规则（踩过坑的）

1. **编码必须 UTF-8**：Windows 下 curl 会按本地 GBK 发送中文 → 面板全文乱码。用 python `urllib.parse.urlencode(...)`（自动 utf-8）或预先编码好的 `--data-binary @file`。
2. **超时 ≠ 失败，但可能只写入一部分**：`/submit-input` 处理慢（常见 40 秒以上）。实测 60 秒超时会只保存第一行/把格式重排。建议 `timeout=180`；提交后必须 `GET /input` 回读验证（中文正常 + 所有条目都在）。若内容不完整，用"完整目标内容"重新提交，**不要追加**。
3. **记录格式（用户拍板 2026-10-22，最新）**：每条记录 = `序号、分组名，内容`
   - 序号写在最前，按当天"大工作项"顺序递增「1、2、…」；**一个大工作项只占一条、只有一个序号**；同一次会话/同一件事的子任务、过程、多个发现全部合并进这一条，**禁止拆成多条编号记录**；
   - 序号后用「、」接工作分组（已知分组：`AI提效-售前工作台`、`内部平台-明道云维护`、`AI提效-文档生成`、`AI提效-安全漏洞响应`、`鹰潭大城管测试`；其他分组以用户当日说明为准），分组后用中文逗号「，」接内容；
   - 每条 30-50 字，必要时可到 100 字：只写核心成果（可带提交号），不写过程、不逐条罗列细节；以完整表达该大工作项为准。
   - **反例（2026-10-22 实际踩过）**：把"明道云维护"这一件事拆成 1、2、3、4、5、6 六条编号记录——错误，应合并为一条、只占一个序号。
4. **记录粒度：一个会话只写 1 条（用户 2026-10-23 确认，与规则 3 互补）**：
   - 把该会话当天所有成果**聚合成一条**记录，不要按工作项拆成多条（拆条会让日报变成流水账）；
   - 聚合写法：`<序号>、<分组>，<主成果 + 关键配套（发布/上线/回写等）>`，括号里可带规模数字；
   - 同一天开了多个会话 → 每个会话各 1 条，序号接在当天已有记录后续编。
5. **写前先读，且写入是整块覆盖**（2026-10-23 踩坑）：
   - 面板 `freeform` 是**整块覆盖写**，不是追加——必须「读 → 拼旧+新 → 整块提交 → 回读校验」；
   - **读到空不等于真空**：可能有别的会话正在同时写，首次读到空时要在提交前再读一次确认，否则会把对方内容盖掉或自己白写；
   - 续写不覆盖用户已手工修改的内容；待办勾选区（`done_*`/`prog_*`）属用户个人待办，未经用户明确指示不勾选、不改动。
6. 写后回读确认内容与编码（回读要同时校验「自己的新记录在」和「原有内容还在」）。

## 提交模板（规避编码坑）

```python
import urllib.parse, urllib.request
text = "1、AI提效-售前工作台，……"
body = urllib.parse.urlencode({
    "key": "AhXDXgGlwjFarWup", "day": "YYMMDD", "freeform": text,
}).encode("utf-8")
urllib.request.urlopen(urllib.request.Request(
    "http://100.103.28.84:8765/submit-input", data=body,
    headers={"Content-Type": "application/x-www-form-urlencoded"}), timeout=180)
# 超时后先回读 /input；内容不完整就用完整目标内容重提，不要追加
```
