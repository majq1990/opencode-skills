为数字政通工程技术中心的项目经理本职工作服务。先识别用户要哪个子命令，再执行对应流程。
脚本与模板路径相对本 skill 目录：`scripts/`、`templates/`。

## ⛔ 全局硬规则（产出任何正式文档前必须执行）

1. **禁引未定稿标准**：删除 `GB/T XXXXX`、`报批稿`、`征求意见稿`、`送审稿`、`草案`、
   `V1.x 意见反馈稿`、在编标准等。引用标准须有正式发布号且未废止；拿不准改写成业务描述。
   **永不引用用户在编标准。** 发现即删并告知原因。
2. **周报分类**：三段式＝项目支持 / 工具与技术提升 / 其他；安全→技术提升；明道·通途→其他。
3. **工期算法**：用 china-festival-mcp 判工作日，法定假日顺延。
4. **钉钉输出**：UTF-8，关键词含进 title+text。
5. **政务数据安全**：客户 IP/人员/金额等敏感数据不外发、本地处理。

## 子命令：标书检查 ✅

**这是确定性规则引擎，不靠模型手感，查全率优先。** 用它给硬规则 1 兜底。

执行步骤：
1. 拿到文档路径（.docx/.md/.txt）。若用户粘贴文本，先 Write 到临时文件或用 `-` 走 stdin。
2. 运行规则引擎：
   ```bash
   python "C:/Users/majq1/.claude/skills/项目经理助手/scripts/compliance_check.py" "<文档路径>"
   ```
   - 加 `--json` 得到结构化结果便于二次处理。
   - 退出码：2=有高危（合规事故，必须处理）、1=仅中危、0=干净。
3. 脚本检测：A 未定稿状态词 / B 占位或缺年份标准号 / C 国密标准号配对 / D 法规现行有效性。
4. **在规则引擎之上做一次语义复审**（规则抓不到的）：通读全文，找"引用了用户自己在编标准"
   "标准号看似正式但实际未发布"这类需要理解的情况，补进问题清单。
5. 输出合并问题清单（位置 | 命中 | 类型 | 严重度 | 建议），高危项逐条给改写建议。
   **高危一处都不能放过——漏一处就是合规事故。**

## 子命令：周报生成 ✅

执行步骤：
1. 收集本周进展要点：用户口述，或（经授权）调 redmine MCP 拉我名下本周 issue 变更、
   调钉钉日志 MCP 拉本周日报。
2. 读取模板 `templates/weekly_report_template.md`。
3. 按三段式归类，**严格执行硬规则 2**：
   - 安全扫描/漏洞响应/渗透/加固 → 第二段「工具与技术提升」（不是第一段）
   - 明道、通途相关 → 第三段「其他」
   - 对外项目交付/客户支持/现场 → 第一段「项目支持」
4. 每段 3~5 条，动词开头，量化结果（数量/工期/影响范围）。
5. 输出 Markdown。可选：经确认后用钉钉日志 MCP 提交到周报模板。
